# 原生平台验收

此驱动在独立验收分支运行，候选另行 checkout 到固定 SHA 并构建；不能把驱动提交的 SHA 写成候选 SHA。候选源码必须干净，依赖仅用于验收，不进入三个发布包。

`node probe.mjs <候选目录> <报告目录>` 使用 node-pty 的原生 PTY/ConPTY，驱动实际 CLI 导出的 main 与真实 daemon，只有外部模型由确定性本地 HTTP 服务代替。覆盖 UTF-8 分片输出、分片键入、括号粘贴、允许/拒绝审批、Ctrl+C 取消、空闲恢复、断开重连和终端 raw 模式清理。每项断言根据模型收到的输入、实际文件副作用、终端输出与进程终态判断；不能由空日志或未执行场景通过。

Windows 在 runner 的用户私有目录中启动 daemon，再创建临时普通用户，对真实凭证/元数据和 named pipe 做访问尝试。先证明该用户能执行探针、读取公开控制文件，再验证私有文件与 pipe 的访问拒绝；不人为收紧被测目录权限。临时用户和公开探针目录在 finally 清理，报告不包含 token、密钥或用户密码。

报告通过仍需按 `docs/release-evidence.md` 审核，不能把单个平台通过填成三平台覆盖。任何失败必须保留，不能以修改报告、跳过用例或放宽断言换取发布。
