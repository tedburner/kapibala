# Spec Delta

## Purpose

为会话输入提供 `@` 文件引用：在沙箱工作区内补全文件路径，以轻量文本语义进入消息——路径由模型用既有文件读取工具自行获取，不注入内容、不新增授权路径。

## ADDED Requirements

### Requirement: 沙箱内文件补全

输入框中 `@` 触发文件路径补全：候选列表 MUST 仅来自当前工作区沙箱边界内的文件（不含沙箱外路径），MUST 支持路径模糊匹配与键盘导航；列表枚举 MUST 有界（深度与数量预算），并排除通用忽略目录（依赖与缓存目录如 node_modules、.git）。跨工作区切换后补全 MUST 反映当前工作区，不残留上一工作区路径。

#### Scenario: 边界内枚举

- **WHEN** 在受信任工作区键入 `@src/`
- **THEN** 补全候选仅含该工作区 `src/` 下的文件，不出现沙箱边界外路径

#### Scenario: 忽略目录排除

- **WHEN** 工作区含 node_modules 与 .git 目录
- **THEN** 键入 `@` 后的候选列表不包含这些目录下的文件

### Requirement: 轻量文本语义

选中文件后 MUST 以 `@<相对路径>` 文本形式插入消息并正常发送；该消息与普通文本消息的处理路径完全一致（同一次模型请求、同样的历史落盘），MUST NOT 注入文件内容、MUST NOT 触发自动读取或附加。引用路径仅为文本提示，模型是否读取、以何种工具读取，走既有文件读取授权与沙箱规则。

#### Scenario: 引用消息不产生额外注入

- **WHEN** 发送「请评审 @src/index.ts 的实现」
- **THEN** 消息原文包含 `@src/index.ts`，落盘内容与用户输入一致，无附加内容块、无自动工具调用

#### Scenario: 引用不豁免读取授权

- **WHEN** 消息含 `@` 引用且模型随后读取该文件
- **THEN** 读取走既有 read 工具授权与沙箱校验，与管理面/引用功能启用与否无关

### Requirement: 路径有效性反馈

补全选中或手输的 `@` 路径若在工作区内不存在，MUST 在发送前给出可见提示（不阻断发送——模型可能以相近路径自行解析）；`@` 后无路径分隔内容时 MUST 展示工作区顶层候选而非报错。

#### Scenario: 不存在路径提示

- **WHEN** 输入 `@src/不存在的文件.ts` 并准备发送
- **THEN** 输入框展示路径不存在提示，用户仍可选择发送

### Requirement: 枚举不泄漏内容

文件补全的枚举结果 MUST 只含路径与基本元数据，MUST NOT 包含文件内容、MUST NOT 返回沙箱外文件系统信息；枚举服务的访问范围与桌面会话的沙箱边界一致，未打开会话或工作区未信任时 MUST 不提供枚举。

#### Scenario: 未信任工作区不枚举

- **WHEN** 当前项目空间未受信任时键入 `@`
- **THEN** 不出现文件补全候选（或展示明确的能力不可用提示），不发起枚举请求
