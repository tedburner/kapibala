# Design: v0.0.8 终端客户端与跨端展示

## Context

动机和范围见 [proposal](proposal.md)，产品与架构基线见 [技术方案](../../../docs/superpowers/specs/2026-10-17-v0-0-8-terminal-experience-design.md)。这是涉及宿主、Core 公共观察接口、终端依赖、构建及恢复行为的跨模块变更，因此保留本设计作为实施决策记录，行为以六个 capability spec 为准。

当前接点已核实：`index.ts` 创建启动期 readline 并在 factory 中接入 MCP；`repl.ts` 执行命令/Skill/Prompt 并等待控制器清理；`ui/events.ts` 混合展示状态与 ANSI；命令处理器存在终端旁路输出；`AgentRuntime.listTasks` 已返回复制快照，内部有状态通知集合；类型检查和打包当前没有 TSX/纯展示子路径。

## Goals / Non-Goals

**Goals**：以 CLI 包内增量替代交互 REPL 的展示与输入实现；共享展示投影、统一终端所有权和命令裁决，保持 Headless Core、完整工具历史、清理解锁、文本 detailed 及配置/信任语义。

**Non-Goals**：本版不改变 Provider 协议、会话 Schema、压缩规则、审批权限、结果投递调度、工作区隔离或计费；不新增工作区/发布包，不实现桌面端或客户端 wire 协议，不进行 Git 提交与发布。

## Decisions

### 1. 同包分层和独立入口

`kpbl` 的 CLI 入口承载 TUI 与文本两种展示策略，`--ui text` 在交互式 TTY 中也可显式使用。未来 GUI 共享语义展示规则，各端布局与输入交互自行适配，不以界面完全相同为验收要求。Core 事件/历史先由 Host 投影，再进入 ViewModel；Core 不直接依赖展示模型。

- `view-model/` 定义纯展示输入、文档块、运行/交互状态、折叠选择、候选匹配和选择器；不引用 Core 类型或宿主运行时。
- `host/` 负责 canonical 白名单投影、事件代次、Session/控制器绑定、目录来源、命令执行、输出、审批和任务观察。
- `tui/` 负责 Ink 组件、编辑器、终端模式守卫、焦点、行布局、缓存和视窗；只能通过注入端口调用宿主动作。
- 独立导出 `@kiturone/kapibala-cli/view-model` ESM 与声明，保留当前 CLI 根入口和 bin。独立构建不能带 shebang 或 Node 依赖，类型检查去掉 Node 全局类型；浏览器产物导入验证不触发终端初始化。

相较新建包，该方式满足用户不新增包的约束，并避免新 npm 发布身份与版本拓扑；相较把 TUI 写进 Core，保持核心零运行时依赖与无界面副作用。

### 2. 依赖准入先于产品接入

初始候选为 Ink 6.8.0、React 19.2.4，保持 Node >=20。准入在临时、隔离的受控模型/终端场景验证安装、备用屏、IME、分片键、粘贴、滚动、缩放和退出；外部模型或真实用户设置不是测试依赖。版本和完整传递依赖树通过后才锁定，失败需记录具体缺口并修订选型，不能删除验收场景以继续。

适配显式关闭 Ink 的自动 Ctrl+C 退出和 console 劫持，设置单一 maxFps；先复用其解析/同步输出，再在唯一输入或写屏链内补必要能力。采用支持 Node 20 的构建/测试工具运行兼容检查，不能以当前 pnpm/Node 24 环境代替最低版本验收。

### 3. 共享执行协调，不复制 Agent 循环

抽取现有 REPL 的交互执行协调职责为宿主端口驱动实现；文本和完整视图接入同一控制器、dispatcher、Skill/Prompt 运行入口与取消句柄。`CliInputCoordinator` 保留文本/启动阶段适配角色，TUI 实现相同宿主输入契约，不依赖该具体类的 readline。

`--ui` 在设置迁移/信任副作用前校验。判断单次问答与交互可用性后选择输出策略，help/version 不导入渲染器。向导/MCP 初始授权可使用启动输入，但移交前关闭旧实例并等待解绑；后续 factory/重连从当前输入端口获取审批能力，不能捕获已关闭的启动读取器。auto 的初始化回退只在未受理任务且已恢复资源后进行。

### 4. 展示身份与提交对齐

Host 创建本地 operationId/viewEpoch，并随 conversationId、branchId、事件序号送入投影。消息以 canonical ID 标识，流内临时块以 operation/turn/块序号标识；tool ID 与思考 blockId 都按 operation 隔离。完成事件与暂存内容对齐一次；保留临时身份别名以维护用户覆盖，不按正文 hash 去重。

初始化、恢复和切分支从原始 `getHistory` 白名单构建；不投影私有签名/加密状态。操作结束重新校对 canonical 历史；未持久化片段只在当前临时视图保留为中断提示。批处理仅影响通知/绘制；边界事件之前先按序处理所有增量。`run_finish` 进入 settling；只有控制器迭代和 finally 完成后发本地 settled，避免提前允许切换/新任务。

### 5. 统一输出和参数级命令可用性

命令上下文增加宿主输出能力，文本默认适配保留既有测试/消费者行为，TUI 注入通知/列表显示。逐项迁移命令、dispatcher、运行期诊断与 MCP 输出，不全局修改 console。共享命令解析/校验/可用性结果由 dispatcher 提供，面板和最终执行使用同一实现与互斥条件，防止 UI 另写命令名单。

候选来源由 Host 适配，排序与窗口选择在纯展示层；候选稳定 ID 区分命令、当前获胜 Skill 发现身份和 Prompt 服务身份。未填参数先编辑，参数改变重算；执行前再次解析元数据与权限代次。只读分支/归档列表在无独占问答时可用，cancelling/settling 和变更命令互斥均计入门禁。

Skill 无现成 catalog-id，Host 按 name/scope/规范化 discoveryRoot/discoveryPath 的无歧义字段编码生成不透明身份；路径身份沿用现有信任规则，Windows 物理路径使用 native realpath。路径不原样进入共享候选。contentDigest 与目录代次作为单独的新鲜度检查，来源替换/撤销使旧选择失效，内容刷新不无条件丢弃同来源选择。Prompt 的 server/name 同样无歧义编码，连接/目录代次由 Host 执行前复核。

### 6. 输入、安全与模式守卫

单一输入协调器管理编辑草稿、弹层、审批/秘密和消息焦点；秘密缓冲只在宿主输入对象，不在共享快照。粘贴作为完整编辑输入，不能自动执行快捷键/批准。支持终端协议的按键走单一解析链，必要缓冲有超时/字节边界并在关闭时释放。

任务取消保持终端和运行锁。正常关闭先停止受理、取消并等待 Session/Runtime、停止绘制和卸载，再恢复拥有的模式。模式守卫预先记录 raw 状态及实际启用的备用屏/光标/键盘/粘贴状态，同步兜底幂等且不抛新异常；致命错误保留 Node 默认非零退出，不恢复继续执行，不承诺不可捕获终止下的异步清理。

### 7. 行窗口与布局缓存

布局索引、文本换行/Markdown 终端行、滚动锚点、revision/宽度缓存留在 TUI。可见范围按实际行计算，上下默认一屏 overscan；压力时减少 overscan，不减少屏内正文。大消息使用行片段，活跃节点动态计数，不设 30 个硬上限。完成块不随每个 delta 重解析，当前流块增量失效；布局回收只删除可重建内容，避免深拷贝整个历史。

初始额外过程/布局预算分别 1 MiB/8 MiB。状态发布合并和 Ink 写屏限帧职责分离，不叠加独立周期写屏。同步输出按能力判断使用且只配对一层；不支持时差量渲染。参考性能场景、内容完整性和输入延迟按 viewport spec 留证，不能仅证明 React 挂载较少就宣称性能验收完成。

### 8. 后台观察与状态栏

Core 仅增加通用任务变化订阅，快照继续复制，监听异常隔离且关闭释放。Host 按父会话/rootTaskId/来源分支投影，执行终态与 Outbox/Inbox 收集事实分离；任务详情只读，不隐式 collect 或请求模型。状态段由宿主提供，Git 异步缓存，usage 不知则未知，run 累计不能替代上下文占用。

## Risks / Trade-offs

- [终端兼容和 IME 行为不同] → 阶段 A 的平台/协议证据先行，自动模式可在安全初始化边界退化文本，显式失败不冒充成功。
- [新适配仍遗留直接输出或旧输入引用] → 检查全部调用点、架构门禁及真实进程测试；避免只靠组件单测。
- [布局缓存淘汰或缩放导致跳动] → 稳定块/块内锚点，宽度相关失效，长历史及大块独立压力验收。
- [旧测试写用户审计目录受沙箱限制] → 测试使用隔离用户/日志目录，不关闭审计以求通过。
- [macOS/Node 20 不在本机默认环境] → 增加可复现平台任务/脚本并分别记录实测、自动化证据和未完成项，不以 Windows 的成功代替它们。

## Migration Plan

按 A 依赖准入 → B 纯投影 → C 宿主交互 → D 完整功能 → E 交付验收推进，详见 tasks。实施时先写有意义的行为回归再接入；阶段任务仅在相应行为/证据完整后勾选。

现有设置与历史无需迁移；默认交互体验改变由 `--ui text` 提供保守回退，单次和非 TTY 继续文本。发布版本推进、提交、推送和真实外部凭据不包含在本次实现授权内。最终同步使用、迁移和验证文档；已审阅技术方案保留设计基线，当前事实和进度指向本 change。
