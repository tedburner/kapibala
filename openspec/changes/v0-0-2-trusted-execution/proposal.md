# Proposal

## Why

v0.0.1 的工具能力声明尚不参与授权，CLI 日志仅在 `--debug` 时零散输出，项目指令也未加载。v0.0.2 需要让每次工具操作可裁决、可追溯，并让项目约定在明确的权限边界内生效，然后才能开放命令执行。

## What Changes

- 新增默认启用的结构化日志系统：正常运行持久化关键生命周期、模型、工具、权限和错误事件；命令审计记录脱敏预览与可核对的执行指纹，启动时将未完成操作标为结果未知；`--debug` 增加开发诊断，两个级别均进行脱敏。
- 新增四态 `SessionMode`、执行前权限策略与宿主注入的人工审批通道；命令审批绑定实际解释器、工作目录和执行参数，拒绝不可靠的命令前缀规则；模型可见工具按模式及整项拒绝规则过滤。所有工具调用记录授权来源和执行结果。**BREAKING**：此前可直接执行的自定义工具将受能力声明与执行前授权约束。
- 新增稳定工具错误码与重试策略，审批拒绝、超时和中断均形成合法工具结果。
- 新增用户级和项目目录链的多层 `AGENTS.md` 加载、轮次边界刷新与来源诊断；指令文本不能扩大工具权限。
- 在权限和日志验收通过后，新增开箱即用的跨平台 `run_command` 工具：有可用执行环境时默认注册并在允许执行的模式下向模型提供，无需用户先传启用参数；用户或宿主可显式关闭。Windows 自动模式只用 `PATH` 与运行时探针选择 Bash（运行时分类 native Bash 与 WSL），依次向 WSL 与 PowerShell 兜底，不写死安装路径；PATH 上没有 Bash 时须由用户显式提供解释器全路径。命令使用当前操作系统用户权限，不受文件工具的 `PathSandbox` 隔离；执行中展示进度，超时或中止须回收子进程树并确认状态，大输出可从受控文件查看。
- 明确 `FullAccess` 为“对已注册且已声明能力的工具默认免逐次审批”：显式 `deny`、显式 `ask` 和宿主硬限制仍生效；显式关闭的 `run_command` 不会因切换模式而重新注册。CLI 的 `FullAccess` 只能由用户在本次会话主动选择，并持续显示当前模式；项目文件不能开启。同步修正基线文档中与命令隔离语义不符的描述，保留原章节编号与交叉引用。

## Capabilities

### New Capabilities

- `structured-logging`: 持久化运行日志、开发诊断和必须留痕的审批审计。
- `tool-permissions`: 模式、能力规则、人工审批、会话缓存与执行前最终裁决。
- `structured-tool-errors`: 工具错误分类、安全回填和工具历史闭合。
- `project-instructions`: 多层 `AGENTS.md` 发现、快照刷新和来源诊断。
- `shell-execution`: 跨平台命令工具的默认注册、显式关闭、环境选择、审批、输出边界与进程回收。

### Modified Capabilities

无；当前 `openspec/specs/` 尚无主规格。

## Impact

- Core：新增日志、权限与指令模块；调整 `AgentSession`、`ToolExecutor`、Hook/事件与工具结果契约；保持运行时零第三方依赖和 Headless 边界。
- CLI：新增日志文件宿主适配、审批交互、模式配置与诊断入口；保留正常输出简洁性。
- 配置与兼容：读取旧配置时采用新默认值，不将内置模型清单写回用户配置；已有历史消息保持可读取。
- 验证：权限矩阵、命令规则冲突与组合命令、审批目标变化、每次工具操作日志、脱敏与崩溃审计恢复、历史闭合、指令刷新、Windows PowerShell 与 POSIX Bash 的真实命令执行及进程回收纳入发布门禁；Windows 有 Git Bash 时另验证自动与显式选择，仅有 WSL launcher 时验证 `wsl` 兜底。
