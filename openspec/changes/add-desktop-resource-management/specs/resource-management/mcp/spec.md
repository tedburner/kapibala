# Spec Delta

## Purpose

为 MCP 服务器资源提供配置管理面：让用户在设置界面完成全局服务器的查看、增删改、启停与诊断确认，项目级声明保持只读可见。管理面只投影既有配置契约，不改变会话装配与授权语义。

## ADDED Requirements

### Requirement: 全局服务器清单可见

设置面板的 MCP 子面板 MUST 展示全局 `~/.kapibala/mcp.json` 中全部服务器的：名称、传输类型（stdio 命令 / HTTP 端点）、目标摘要与启用状态。配置文件不存在时 MUST 展示空态而非报错。

#### Scenario: 空配置零开销展示

- **WHEN** 全局与项目级均无任何已配置服务器
- **THEN** 面板展示空态提示，不发起任何网络探测或后台进程，不产生配置文件写入

#### Scenario: 已配置清单展示

- **WHEN** 全局配置声明了 stdio 与 HTTP 两类服务器，其一 `enabled: false`
- **THEN** 清单逐项展示类型、目标摘要与启用状态，禁用项有明确视觉区分

### Requirement: 全局服务器的受控 CRUD

用户 MUST 能在面板中新增、编辑、删除全局配置中的服务器。写回 MUST 复用既有配置校验：命令与 URL 按传输类型校验必填，命名冲突拒绝覆盖；校验失败 MUST 拒绝整个写回并展示原因，禁止部分写入。单个文件 MUST 以短事务方式写回（与全局配置事务同一锁语义），并发写不互相覆盖。

#### Scenario: 新增服务器校验失败拒绝

- **WHEN** 新增 stdio 服务器未提供命令，或名称与既有服务器重复
- **THEN** 提交被拒绝并展示具体原因，`mcp.json` 内容不变

#### Scenario: 删除立即生效

- **WHEN** 删除一个已启用服务器
- **THEN** 全局配置移除该项；后续新建会话不再挂载该服务器，运行中会话不受影响

### Requirement: 逐服务器启停为配置级开关

用户 MUST 能对单个服务器切换启用/禁用，写回该服务器配置的 `enabled` 字段（含纯禁用覆盖语义：禁用不要求保留传输字段）。启停 MUST 只影响后续会话装配；已挂载服务器在运行会话中的行为不因开关改变。

#### Scenario: 禁用后新会话不挂载

- **WHEN** 将某服务器置为禁用并新建会话
- **THEN** 该会话的 MCP 挂载不含该服务器，面板状态与配置一致

### Requirement: 项目级声明只读且信任防线可见

面板 MUST 只读展示当前工作区项目级 `.kapibala/mcp.json` 的声明；项目未被信任时 MUST 明确展示「已排除」状态与原因，不得提供编辑入口。项目信任状态变化后重新打开面板 MUST 反映最新排除结果。

#### Scenario: 未信任项目零注入且可见

- **WHEN** 当前项目未受信任且其 `mcp.json` 声明了服务器
- **THEN** 面板展示这些声明为「已排除（项目未信任）」，会话装配不注入它们；面板无编辑入口

### Requirement: 诊断不静默

配置解析失败、格式错误、信任排除等诊断 MUST 在面板原样可见（严重级别 + 原因），禁止静默丢弃；诊断内容 MUST 遵循既有脱敏规则，不展示密钥或完整环境变量值。

#### Scenario: 配置损坏可见诊断

- **WHEN** 全局 `mcp.json` 无法解析
- **THEN** 面板展示解析失败诊断与会话侧一致的错误摘要，同时保留受影响项的只读展示

### Requirement: 启动授权语义不变

管理面的任何操作 MUST NOT 改变既有 MCP 启动审批行为：stdio 服务启动仍须经用户显式批准，`--no-mcp`（宿主级禁用）仍整体关闭且面板不得提供绕过入口。

#### Scenario: 管理面不豁免审批

- **WHEN** 用户在面板中新增并启用一个 stdio 服务器，随后新建会话
- **THEN** 该服务器的启动审批流程与手动编辑 `mcp.json` 的场景完全一致
