# Spec Delta

## Purpose

为技能资源提供可见性与开关管理面：让用户在设置界面查看已装技能、扫描诊断与信任标注，控制全局启用与逐技能禁用。管理面只投影既有发现/信任/授权规则，不新增授权路径。

## ADDED Requirements

### Requirement: 技能清单可见

设置面板的 Skills 子面板 MUST 展示经既有发现规则（有界扫描 + 信任门禁）得到的技能清单：名称、来源范围（用户全局 / 项目 / 内置路径）、可用状态与描述摘要。清单 MUST 与技能运行时看到的内容同源——面板展示的可用集合与新建会话注册的工具目录一致。

#### Scenario: 清单与运行时同源

- **WHEN** 全局技能目录含两个有效技能、项目目录含一个有效技能（项目受信任）
- **THEN** 面板展示三个技能并标注各自来源；新建会话的技能目录包含同样三个条目

#### Scenario: 未信任项目技能标注

- **WHEN** 项目未受信任且其技能目录含技能
- **THEN** 面板展示该技能并标注不可用/未信任状态，新建会话不加载其正文

### Requirement: 全局启用开关走配置事务

用户 MUST 能开关全局技能功能（既有 `settings.skills.enabled`）。开关 MUST 经全局配置短事务写回（并发写不互相覆盖）；关闭后新建会话 MUST 不注册任何技能工具、不扫描目录；开启后恢复。运行中会话不受开关影响，空闲期切换对下一个会话生效。

#### Scenario: 关闭后新会话无技能工具

- **WHEN** 全局开关置为关闭并新建会话
- **THEN** 该会话不注册 `load_skill` / `list_skills` 等技能工具，面板开关状态与配置一致

### Requirement: 逐技能禁用走配置事务

用户 MUST 能按名称禁用单个技能（既有 `settings.skills.disabled` 列表）。禁用 MUST 经全局配置短事务写回；被禁用技能 MUST 从后续会话的技能目录排除且不注册其工具，面板 MUST 展示禁用状态。禁用列表中的未知名称 MUST 保留（目录刷新后即时生效），不得被清理。

#### Scenario: 禁用后目录排除

- **WHEN** 禁用技能 A 并新建会话
- **THEN** 技能目录不含 A，模型无法通过 `list_skills` 发现 A；面板展示 A 为已禁用

#### Scenario: 禁用项先于目录存在

- **WHEN** 禁用一个当前目录中不存在的名称，随后该技能被放入目录
- **THEN** 新建会话仍将其排除，禁用项未被清理

### Requirement: 扫描诊断可见

技能扫描产生的诊断（frontmatter 无效、正文超限、路径越界、信任缺失等）MUST 在面板原样可见并遵循既有脱敏规则；诊断只描述事实，不提供绕过信任或边界的入口。

#### Scenario: 无效技能可见诊断

- **WHEN** 技能目录存在 frontmatter 缺失名称的文件
- **THEN** 面板展示该文件的诊断条目，有效技能清单不受影响

### Requirement: 授权路径不变

管理面的任何操作 MUST NOT 改变技能加载授权：显式加载仍走同一读取策略、精确缓存与宿主审批裁决；资源读取审计与物理边界校验保持不变。面板 MUST NOT 提供跳过审批或扩大 boundary 的入口。

#### Scenario: 面板启用不豁免审批

- **WHEN** 用户在面板开启全局技能并在对话中显式加载某技能
- **THEN** 审批裁决与审计流程与开关前完全一致
