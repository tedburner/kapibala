# Kapibala v0.0.10（未发布）：稳定整合版

**状态：实现与本地门禁已完成，尚未发布。** 本版不新增客户端类型或运行时子系统，只把 v0.0.9 交付的 Core 公共 API、本地 wire 协议 1.0 与本地客户端契约收口为可依赖的稳定面：显式工作区身份与宿主级写租约、类型化的错误与取消语义、按方法与参数具体化的客户端结果、父子协调器传递、快照分块与恢复单位，以及旧新产物、三平台与长时资源的门禁工具。

本版有 9 处公开差异，发布前必须逐条解释，见下表；完整盘点见 [SDK 兼容性说明](../sdk-compatibility.md)，动作项见 [迁移说明](../migration/v0.0.10.md)，真实证据与未补齐门禁见 [验收记录](../verification/v0.0.10.md)。

| 变化 | 影响 | 迁移方式 |
|---|---|---|
| `SessionConfig` 至少提供一个根字段，`interface` 改为联合 `type` | 缺少两字段的调用、接口继承/合并用法需要调整；`rootDir`-only 保持有效 | 优先 `workspaceRoot`；兼容 `rootDir`；扩展配置改用交集或 `SessionOptions` |
| 删除 `sharedWorkspaceLeaseCoordinator` 导出 | 导入旧单例的 SDK 代码需要调整 | 显式创建 `WorkspaceLeaseCoordinator` 并注入需要共享的会话 |
| 缺省协调器改为会话独占 | 独立 SDK 会话不再暗含全局串行关系 | 同一业务宿主持有并注入共享实例 |
| `LocalClient.call()` 结果具体化 | 依赖宽泛结果做不安全索引的调用需收窄类型 | 使用方法结果类型；cursor 快照按分块结果处理 |
| 显式 cursor 从误重组分支改为原始续块返回 | 运行时返回形状/失败路径变化，不只是类型收窄 | 读取正文用无 cursor 调用；手动分页处理 chunk/cursor |
| attach 中途取消、重组或缓冲回放失败明确拒绝并关闭整个连接 | 同一连接的其他控制会话也会断线收口；不再允许异步 `close` 后仍返回快照 | 新建连接后按需重新 attach，不重发写任务；独立控制需求使用独立连接 |
| `SpawnContext` 必须携带协调器，runner 接收第三个运行上下文；CLI runner 工厂协调器必填 | 自定义 `prepareSpawn`/runner 装配及 CLI 工厂调用需更新 | 注入父 Session 实际实例，消费 runner 上下文，不序列化该实例 |
| `LocalTransport` 增加必填 `setLimits(limits: TransportLimits): void` | 自定义传输实现需支持握手后收紧帧与发送队列预算 | 导入公开 `TransportLimits`，修改实现；缺少能力时连接失败，不静默使用默认值 |
| 清理异常改用类型化 code | 部分原先退化为 `INTERNAL_ERROR` 的清理失败会细化到既有 `SESSION_CLEANUP_FAILED` | 调用方按既有业务码处理可重试关闭，不将取消请求失败理解为任务已停止 |

## 本版交付

- **公共面冻结**：Core / MCP / CLI 三个库根入口与 CLI 的 `protocol` / `client` / `view-model` 子路径导出清单与声明基线固定，差异登记在 `scripts/fixtures/public-api/`，`pnpm check-public-api` 进入 lint 链；`pnpm check-protocol-contract` 冻结 wire 1.0。
- **会话与工作区身份**：`workspaceRoot` / `rootDir` 至少一个绝对路径，冲突与相对路径明确失败，Core 不读 `process.cwd()`；Windows 路径身份统一 `fs.realpathSync.native` 语义。
- **写租约所有权**：会话缺省独占，宿主显式共享；协调器只在内存传递，子代理经 `SpawnContext` 与 runner 第三参数继承父实例，缺失时零副作用拒绝。
- **协议与客户端契约**：方法级结果类型、快照首块 + 原始续块两种形状、恢复单位为整个连接、协商预算同时驱动传输帧、发送队列、分块与审批上限。
- **错误与取消语义**：Core 与 wire 的稳定分类对齐（含 `SESSION_CLEANUP_FAILED`、`WORKSPACE_ROOT_REQUIRED`），取消请求与终态分离，清理失败保留存储锁并可重试。
- **回归与门禁工具**：`pnpm verify:compat`（v0.0.9 tarball × 候选构建，4 组合 × 2 传输）、`pnpm verify:platform`（当前 OS 真实进程 + 三包隔离安装）、`pnpm verify:soak`（PR 10 / nightly 100 / release 1000 且 ≥30 分钟），以及三协议 × 三宿主的无密钥组合回归与历史/配置兼容语料。
- **示例**：`examples/` 覆盖最小会话、共享租约、受控取消与本地客户端四类装配，全部进入类型检查。

## 本版明确未交付

- 不新增 GUI、Web/移动客户端、远程传输（TCP / HTTP / WebSocket）、系统服务安装、自动更新或崩溃后的自动任务续跑；不做 barrel 重构，不新增 npm 包。
- 不提供跨连接事件重放；不同进程的 conversation 之间不具备跨进程工作区互斥。
- 不承诺性能阈值：release 档增长预算需要人工冻结基线后才判定，本版不发明数字。

## 发布阻断条件

以下任一项未闭合前，不推送版本标签、不执行 npm 发布（详见 [验收记录](../verification/v0.0.10.md) 第 3 节）。准备性提交和分支/main 推送由用户手动完成，用于取得 CI 与基线采集证据；不能把这些源码推送当作版本发布。

先提交经审核的性能基线和发布文档，再在干净 main 上用 `pnpm release 0.0.10` 创建最终升版提交及本地标签；同一最终 SHA 的 CI、人工专项及正式 soak 全部通过后才推送该标签。完整顺序见[发布前执行顺序](../verification/v0.0.10.md#5-发布前执行顺序)。

1. 干净提交上的 `pnpm verify` / `verify:compat` / `verify:platform` 记录（当前本机证据均为 dirty 工作区产物）。
2. Node 20 最低运行版本的真实 CI 证据。
3. Windows ACL、ConPTY 与进程树取消（Git Bash、PowerShell 两种 shell）证据。
4. POSIX 交互式 PTY 的粘贴 / 审批 / 恢复证据。
5. 同一 SHA 的 release 档 soak 报告与人工冻结的增长阈值基线。
6. 公开差异已逐条解释、迁移与发布文档经用户审核。

不能通过删测试、放大预算或自动改变支持范围来解除阻断。

## 安装与升级

需要 Node.js 20 或更高版本。发布完成后按版本安装（当前尚未发布，请使用本地 `pnpm dev` 构建）：

```sh
npx @kiturone/kapibala-cli@0.0.10
npm install -g @kiturone/kapibala-cli@0.0.10
npm install @kiturone/kapibala@0.0.10 @kiturone/kapibala-mcp@0.0.10
```

升级前请阅读 [v0.0.10 迁移说明](../migration/v0.0.10.md)。发布标签触发 Actions 完成全量验证、三包发布、公共 registry 安装 smoke 与 GitHub Release。
