# Kapibala v0.1.5：开放外部代理工作台（通用 ACP 生态与原生 CLI 直连）

本版按[技术方案 015](../design/015-v0.1.5-acp-external-harness.md)在宿主层交付开放的「外部代理（External Harness）」独立会话域与桌面全图形化管理工作台：顶层以统一的 `ExternalHarnessDriver` 状态机编排会话、审批与只读归档，底层同时提供零外部 SDK 依赖的 **`acp-stdio` 通用驱动**与 **`claude-cli` / `codex-app-server` / `pi-rpc` 三个原生 CLI 直连驱动**；`@kiturone/kapibala`（Core）保持零改动，本地宿主协议保持整数 `PROTOCOL_VERSION = 2` 并增量扩展 `'external-session'` 能力。

## 🤝 四套零 SDK 传输驱动：开箱直连主流编码 CLI

- **`claude-cli` 原生直连驱动**：直连本机已安装的 `claude` / `claude.exe` 双向 `--input-format stream-json --output-format stream-json --permission-prompt-tool stdio` 管道，无需额外安装任何桥接包或捆绑重型 SDK；支持流式思考与正文增量、`TodoWrite` 任务进度同步、`control_request(can_use_tool)` 交互式人工审批、`interrupt` 取消及 `--resume` 会话恢复，并默认禁用 `AskUserQuestion,EnterPlanMode,ExitPlanMode` 防止无 TTY 子进程挂死。
- **`codex-app-server` 原生直连驱动**：直连本机 `codex app-server -c thread_unload_delay_secs=0`，原生适配无 `jsonrpc` 字段的 `jsonrpc_lite` 帧格式；完整支持 `thread/start`、`thread/resume`、`turn/start`、`turn/interrupt`、`turn/plan/updated` 以及命令执行与文件修改双向审批（含 `acceptForSession`）。
- **`pi-rpc` 原生直连驱动**：直连本机 **Pi Coding Agent**（`pi --mode rpc`）双向 JSON 行流管道，默认挂载宿主受管的只读审批守卫扩展（`--extension`），通过 `extension_ui_request(select)` 将 `bash`、`powershell`、`write`、`edit` 等写执行工具调用接入桌面与 CLI 统一人工审批卡，并支持 `--session-id` 会话恢复与 `abort` 取消。
- **`acp-stdio` 通用开放生态驱动**：基于标准 JSON-RPC 2.0 over NDJSON stdio 与轻量 `AcpHarnessFlavor` 容错层，原生支持 **Antigravity（`agy acp`）**（自动协商 `oauth-personal` 认证）、**OpenCode（`opencode acp`）**（兼容 `session/load` 预绑路由与先行重放通知）、**DeepSeek Harness（`dsh --profile acp`）**（兼容 `sessionCapabilities.resume`）、Gemini CLI、Qwen Code、官方 ACP Registry 模板（Copilot CLI、Cursor Agent、Cline、Kimi Code、Goose、Mistral Vibe、Auggie）及任意本地自定义 **`Local ACP Command`**。

## 🖥️ 桌面端全图形化设置与外部会话工作台

- **设置弹窗左栏新增「外部代理」一等标签页**：
  - **内置外部代理卡片**：直观展示传输类型、就绪版本或未登录/未安装状态徽章，提供启停开关、一键「检测连接」、终端登录/安装命令一键复制，以及可折叠的图形化「配置覆盖」面板（路径覆盖、逐行字面参数、`envFrom` 环境变量名白名单与一键恢复默认）；
  - **自定义与社区 ACP 代理**：支持一键从官方 ACP 目录模板填充表单，或手动新建/编辑/删除 `Local ACP Command`；保存前即可直接点击「测试握手」验证协议连通性、版本与恢复能力，全程无需手改 JSON。
- **工作区侧栏与外部会话视图**：
  - 在新对话输入框按代理浏览或直接搜索，选择已启用的外部代理及其默认模型，或直接选择可用的 Kapibala 模型。发送首条消息即创建会话，已有外部会话在所属项目下显示代理名和运行状态。
  - 外部会话主视图复用本地 Streamdown Markdown、思考折叠块、工具卡片与详情抽屉及 `TaskPanel` 任务进度 pill；顶部常驻展示代理标识、只读模型/模式标签、外部权限边界说明及同工作区并发运行冲突提醒；
  - 底部内联渲染外部审批卡片（原样保留外部代理提供的全部选项与剩余倒计时）；后台外部任务完成、失败或待审批时，窗口失焦发系统通知、前台弹轻量提醒卡片。

## 💻 CLI `/external` 对等命令组与 Wire v2 扩展

- 新增 `/external` 命令组（读写同一份 `~/.kapibala/external/` 配置与登记簿）：覆盖 `list`、`harnesses`、`harness test|add|enable|disable|remove|reset`、`start`、`show`、`prompt`、`approve`、`cancel`、`close`、`delete`，内置引号感知非 Shell 参数分词以兼容带空格的 Windows 可执行路径。
- 本地宿主协议保持 `PROTOCOL_VERSION = 2` 不变，`SERVER_CAPABILITIES` 新增 `'external-session'`，增补 16 个 `external/*` 方法与 `external/event` 通知，并更新冻结契约快照 `scripts/fixtures/protocol/v2/contract.json`。

## 🛡️ 进程安全、Windows 解包与只读快照归档

- **Windows 无 Shell 安全启动**：全程 `shell: false, windowsHide: true`，拒绝相对路径命令；内置桌面 GUI 受限 `PATH` 常见安装目录只读兜底；按 `[".exe", ".cmd"]` 优先级探测并以 `fs.realpathSync.native` 静态解包标准 npm/pnpm `.cmd` 三形态垫片（原生 `.exe`、`.js` 脚本与 `#!...node` 无后缀脚本）。
- **两段式进程树回收与限帧**：NDJSON 通道单帧硬上限 8 MiB（配队列高低水位流控），启动期非 JSON 横幅容错且超 100 行 / 64 KiB 自动熔断；关闭会话时先调 `stdin.end()` 留出优雅收尾窗口，超时自动升级 POSIX 进程组信号或 Windows `taskkill /T /F` 强杀整树。
- **有界只读归档与 `configDigest` 连续性门禁**：每轮结算原子写入脱敏只读快照（上限 160 条消息 / 680 KiB，确保单帧稳定低于桌面与本地 Wire 1 MiB 预算），子进程 30 分钟空闲回收或客户端重启后历史输出立即可查；仅在 `resumable === true` 且启动配置摘要未变时才开放原地续聊，否则自动切换为只读历史归档态。

## ⬆️ 升级与边界说明

本版为**非破坏性升级**（Core 零改动，本地协议保持版本 `2`）：

```bash
npx @kiturone/kapibala-cli@0.1.5
npm install -g @kiturone/kapibala-cli@0.1.5
npm install @kiturone/kapibala@0.1.5
```

- 外部代理遵循各自 CLI 的权限与登录态，Kapibala 本地的 `Auto` / `FullAccess` 绝不自动放行外部审批；ACP 客户端 `fs/*`、`terminal/*`、`elicitation/*` 默认关闭。
- 同工作区多 Agent 并行所需的 Git Worktree 物理隔离与文件级检查点回滚不在本版范围，按路线图排入 v0.1.6；详细说明见 [v0.1.5 迁移说明](../migration/v0.1.5.md) 与 [SDK 兼容性盘点](../sdk-compatibility.md)。
