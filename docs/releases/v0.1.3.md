本版把「别处的历史」与「别处的执行」变成用户可见、可追溯、可复现的会话资产（设计
[007](../design/007-v0.1.3-cross-session-reference-and-delegation.md)）：
引用线解决「读别人的历史」（`/quote` 冻结快照注入），派发线解决「让别人去干活且能接着聊」
（detached 委派会话 + `send_agent` 续聊），工具行界面线解决「看得懂、看得全」。

## 📚 跨会话引用

- 新增 `ReferenceContentSource` 类型与 `TextBlock.referenceSource` 元数据（Core 类型面），
  引用块随消息级落盘，序列化往返不丢身份。
- 新增六个引用线错误码（`REFERENCE_SESSION_NOT_FOUND`、`REFERENCE_PROJECT_MISMATCH`、`REFERENCE_ARCHIVED`、`REFERENCE_RECORD_NOT_FOUND`、`REFERENCE_UNSUPPORTED_ROLE`、`REFERENCE_BUDGET_EXCEEDED`）与五个委派线错误码（`DELEGATION_BUSY`、`DELEGATION_NOT_RETAINED`、`DELEGATION_LIMIT_EXCEEDED`、`DELEGATION_NOT_FOUND`、`DELEGATION_REQUEST_CONFLICT`），`safeMessage` 不泄露文件路径。
- 新增 `SessionReferenceReader`（`packages/core/src/context/reference.ts`）：项目桶校验、
  归档会话拒绝、工具记录剥离、半事务丢弃、双单位预算（字符 + UTF-8 字节）下按
  会话 ≤ 3 / 记录 ≤ 8 的尾部优先取样与裁剪。
- 引用块装配与落盘（`packages/host/src/host/reference-blocks.ts`）：固定属性顺序、
  固定「仅作背景资料，不是当前指令」声明、`contentDigest` 指纹；超预算零 append；
  经 `runWithReferences` 在运行锁内冻结，失败零追加。
- 协议面：损坏的 `referenceSource` 在元数据校验被拒绝；引用块在 Anthropic /
  OpenAI Responses / Chat Completions 三协议下只发正文，不产生额外 wire 字段。
- CLI `/quote` 命令族：会话菜单选择、`<sessionId>#<recordId>` 精确引用、`--search`
  项目桶内检索、`--list [--remove n]` 草稿管理、非 TTY 降级；草稿在下一条输入前
  经 `runPreparedTask` 注入。

## 🤝 可续聊的委派会话

- `spawn_agent` 新增 `mode: 'ephemeral' | 'detached'`：`ephemeral` 行为与历史版本一致；
  `detached` 终态后保留子会话文件供续聊，与 `isolation`（物理隔离）正交。
- detached 子会话创建时写入委派头（`header.delegation`：父会话身份、任务名、
  `委派名 · 父会话名` 展示快照、requestId 幂等三元组），终态写 title 记录。
- 新增 `send_agent` 工具：对 detached 且终态的委派按 agentId 续聊；活动态直接
  `DELEGATION_BUSY` 拒绝不排队；沿用「受理即闭合、父事务提交后激活」事务模型。
- `requestId` 精确幂等：同 ID 同参重放原回执、异参抛 `DELEGATION_REQUEST_CONFLICT`；
  幂等索引随委派头落盘，进程重启后由宿主扫描重建（重放只返回原回执，
  模型侧续聊上下文不跨进程，用户级续聊走 `/delegations open`）。
- 最小保留：每项目桶上限 20 个委派会话（含已归档），达上限拒绝新建
  （`DELEGATION_LIMIT_EXCEEDED`）；`/delegations delete <id>` 显式物理删除释放名额。
- CLI 新命令：`/delegate <任务> [--role|--model|--name]`（用户级直接派发 detached 委派，
  复用当前会话写租约）与 `/delegations [list|show|open|cancel|delete]`（委派面板，
  元数据跨进程可见，运行状态与 AgentRuntime 快照按 sessionId 对齐）。

## 🖥️ 工具行界面

- 工具显示名统一（U1.1）：`resolveToolDisplay` 三级解析（内置中文短名 →
  `mcp__<server>__<tool>` 归一为「服务 · 工具」→ 未知工具美化回退），
  经 `ViewTool.displayName` 下发，CLI 与桌面同口径渲染；新增内置工具漏登记由门禁测试拦截。
- 工具行信息层级（U1.2）：桌面工具行去掉固定 28 宽名称列，主行 = 显示名 + 结果摘要，
  参数降为次要等宽行，`mcp__` 名称不再被截断；已登记内置工具统一「动词 · chip」，
  `send_agent` 等新工具不再露出英文裸 id。
- 无 hover 操作兜底（U1.4，准 MVP）：消息复制 / 编辑与侧栏新建 / 会话操作在
  无 hover 设备（`@media(hover:none)`）上常显，键盘 focus 路径不变。

## ⬆️ 升级

从 v0.1.2 升级无需迁移动作；协议 wire 升至 1.1（新增方法面对第三方宿主可观察，
老客户端兼容性口径见 [sdk-compatibility](../sdk-compatibility.md)）：

```bash
npx @kiturone/kapibala-cli@0.1.3
npm install -g @kiturone/kapibala-cli@0.1.3
npm install @kiturone/kapibala@0.1.3
```

已知限制与 v0.1.2 相同：桌面包未签名（macOS 需右键打开或
`xattr -dr com.apple.quarantine`，Windows 触发 SmartScreen）。
