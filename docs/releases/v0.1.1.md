# Kapibala v0.1.1：桌面四平台自动打包与 Windows 冷启动修复

本版交付 CI 干净环境的桌面包链路修复与 Windows 首次启动兼容性修复，随 Release 附带四平台未签名测试安装包。

## 🖥️ 桌面

- Host 连接就绪等待从 5 秒放宽到 30 秒：主进程要 spawn agent-host 子进程并完成工作区初始化才能回传握手，Windows 全新安装的首次启动还要过 Defender 实时扫描（远超 5 秒），过紧的兜底把健康但慢的启动误判为死连接——CI 安装副本验收与真实用户首启同源。
- 连接建立前收到 host 不可用事件会立即终止等待并如实上报错误，不再拖到兜底超时，「初始化失败」与「冷启动过慢」从此可区分。

## 📦 打包链路（CI 首次跑通四平台）

- legacy deploy 原用 `--offline`，但依赖树重放仍需 registry 元数据，CI 元数据缓存不全导致四平台解析全部失败；改为 `--prefer-offline --frozen-lockfile`：缓存优先、缺失联网补齐、解析钉死在共享 lockfile。
- 工作区成员名单从 `packages/` 实际清单推导，不再手工维护；host 层拆包后 CI 打包不再误判 `WORKSPACE_VERSION_MISMATCH`（本机 pnpm 会自动改写清单，该缺陷只在干净环境暴露）。
- `release.yml` 新增 `desktop_only` 手动入口：发布后桌面包个别平台失败可跳过 verify/publish 补跑，`packages/` diff 守卫锁定产品代码与 tag 一致（两套桌面 e2e 规格不进安装包，允许随 UI 修正）。
- 安装副本 smoke 对齐审批队列自动弹出的新交互（标题栏常驻「审批 N」入口已移除）。

## ⬆️ 升级

从 v0.1.0 升级无需迁移动作，直接安装即可：

```bash
npx @kiturone/kapibala-cli@0.1.1
npm install -g @kiturone/kapibala-cli@0.1.1
npm install @kiturone/kapibala@0.1.1
```

已知限制与 v0.1.0 相同：桌面包未签名（macOS 需右键打开或 `xattr -dr com.apple.quarantine`，Windows 触发 SmartScreen）。
