# Kapibala v0.0.4：原生协议与场景模型路由

已于 2026-10-07 发布至 npm 与 [GitHub Release](https://github.com/tedburner/kapibala/releases/tag/v0.0.4)，远端验收见 [验收记录](../verification/v0.0.4.md)。

本版让 Anthropic Messages、OpenAI Responses 和现有 Chat Completions 通过同一 AgentSession、工具执行器、权限与 canonical 历史运行。Profile 明确选择协议，自建网关保持用户配置；错误不会自动降级协议。

- 新增原生 Anthropic：系统/工具投影、多个工具回合、可见思考块事件、签名与脱敏状态保真、缓存 usage 与同 run 前缀保护。
- 新增无状态 Responses：store:false、手动 Item 回传、有序消息阶段、源 Item ID 与 call_id 区分、原始函数参数、加密 reasoning、明确拒绝及严格完成边界。
- 加固 Chat：完整 finish_reason/DONE、整批 JSON 对象参数验证及显式兼容能力；有证据的网关可配置 DONE 例外，普通 EOF 仍失败。
- 显式 planning/execution/fast 任务角色：整个 run 固定绑定；CLI 角色绑定、route 和 --role 共用规则，实际模型、预算、上下文、usage 和错误一致。角色不改变权限或自动执行计划。
- 可覆盖输出预算：原生 OpenAI 推理建议 32768、Claude 5 建议 16384，兼容缺省保留 4096；总量包含推理。摘要目的独立上限 4096。
- 统一最终内容与历史：finalContent 按服务端顺序落盘，增量用于展示，工具只执行一次；所有协议继续保存 canonical tool 结果。私有状态来源验证、跨模型隔离与摘要排除遵循相同规则。
- 内置目录版本升级：Claude/OpenAI 改用原生协议，保留已存密钥、角色引用、自建网关和用户预算覆盖；安全写回不物化未启用模型。

普通用户继续使用当前 default 模型；内置默认仍为 deepseek-flash，不增加默认分类调用。summary 缺映射继续回退 default，摘要费用独立记账。取消、消费者提前退出和进程恢复继续要求工具事务闭合，未知执行结果不重放。

SDK 宿主需检查新增 ContentBlock/思考事件的穷尽处理；更换协议、模型或端点时必须提供匹配 Provider。旧版不能承诺直接读取升级后的全部设置/历史，升级前应保留备份，回退不能删除新版原始记录。接入和命令示例见 [迁移说明](../migration/v0.0.4.md) 与 [场景路由](../models/scenario-routing.md)。

本地类型检查、全量测试、lint、构建、跨协议 Session、Windows 与 WSL/Linux 真实进程验收已执行，结果见 [验收记录](../verification/v0.0.4.md)。真实 Anthropic/OpenAI API 冒烟未执行：本轮没有已批准的调用费用预算。模拟数据不能证明账号权限、真实模型质量、外部 API 稳定性或实际费用。

需要 Node.js 20 或更高版本。按版本安装：

```bash
npx @kiturone/kapibala-cli@0.0.4
npm install -g @kiturone/kapibala-cli@0.0.4
npm install @kiturone/kapibala@0.0.4
```
