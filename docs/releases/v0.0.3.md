# Kapibala v0.0.3：历史会话与上下文管理

本版交付独立会话文件、显式恢复续答、完整轮次保护、保守两级压缩和 Core 六大领域重构。工作区实现与本地验收不等于 GitHub/npm 已发布。

- 普通启动默认新建；`/history` 浏览，`/resume [id]` 续答，`--continue`/`--resume <id>` 启动恢复，`/new` 与 CLI `/clear` 保留旧文件。
- 版本化 JSONL、稳定 UUIDv7、可重建列表缓存、单写者锁和幂等旧历史导入。恢复不重放工具、不继承审批缓存、不改变 cwd。
- 内置成功读取/搜索结果先剪裁，仍超阈值再摘要；原文保留，各级先提交后激活，恢复验证来源和文件事实。
- 当前任务、最近成功交互和失败尾部完整保护，超限停止。任务内部压缩留到后续版本。
- `/context` 显示预算与比例条，`/compact` 手动摘要；统一命令目录、参数、状态门和输入协调器，新增 `/permissions`、兼容别名与默认模型写入修复。
- 压缩失败熔断、独立摘要 usage、恢复一致性及消费者提前退出的中止/清理边界。公开 SDK 导出保持兼容，运行时继续零依赖、Headless。
- 已闭合的旧失败/中断轮次可参与二级摘要，未知副作用保真；一级剪裁仍只处理成功完成旧轮次。修复 Windows 原生命令执行环境的 PATHEXT 缺失。
- 单次问答终端 Ctrl+C 会中止并等待清理；文件操作记录实际执行目录，跨子目录恢复后的摘要不会误认文件路径。
- DeepSeek 工具调用后的请求完整回传思考历史；主任务与摘要统一展示脱敏模型错误、服务端原因、HTTP 状态与错误码，底栏汇总失败阶段及重试建议。失败不自动重放工具。
- 请求未返回 usage 时，上下文占用显示当前请求的预算估算，并明确标注“估算”；未知实际消耗不伪装为零或计费数据。模型菜单去掉主观中文描述，开发门禁中的预期错误由测试捕获验证。

三组真实工具任务的小规模对比验收已完成，约束、待办、未知写入核实和滚动摘要重启均有实际证据；摘要有额外费用与耗时，不保证短任务节省总量。详见 [真实模型验收](../verification/v0.0.3-live-quality.md)。

升级前请阅读 [v0.0.3 迁移说明](../migration/v0.0.3.md)。原始历史仍随单会话增长；首版不提供跨项目全文检索、历史分叉或归档。验证证据、真实模型限制及当前交付状态见 [验收记录](../verification/v0.0.3.md)。

需要 Node.js 20 或更高版本。发布完成后可按版本安装：

```bash
npx @kiturone/kapibala-cli@0.0.3
npm install -g @kiturone/kapibala-cli@0.0.3
npm install @kiturone/kapibala@0.0.3
```

真实 DeepSeek 测试曾出现流式连接重置（`ECONNRESET`），同一会话重试后也有完整成功记录。本版提供准确失败反馈与恢复边界，不保证外部模型服务或网络持续可用。
