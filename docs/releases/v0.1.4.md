# Kapibala v0.1.4：会话级监视、资源管理、右侧信息面板、任务面板与权限重做

本版按[版本设计 014](../design/014-v0.1.4-version-design.md)把七组能力一次收口：把「等外部条件」
交给宿主监视并驱动续跑（[008](../design/008-v0.1.4-session-watch.md)）、把技能与 MCP 从只读发现
扩展为可诊断、可导入、可逐服务器批准的受管资源（[009](../design/009-v0.1.4-skills-management-and-import.md)、
[011](../design/011-v0.1.4-mcp-management-and-release-updates.md)）、把「这一轮改了什么」投影为只读
会话看板与图片产物预览（[010](../design/010-v0.1.4-session-evidence-dashboard.md)、
[012](../design/012-v0.1.4-artifact-preview.md)）、把任务清单与输入区状态补进桌面与 CLI
（[013](../design/013-v0.1.4-task-panel-and-composer-status.md)），并重做命令分级与硬禁区
（[016](../design/016-v0.1.4-permission-model-rework.md) P0）；本地协议同步升为整数
`PROTOCOL_VERSION = 2` + 能力集合，桌面正文与思考块升级到 `streamdown` 生态。

## 👀 会话级监视

- 新增全局控制记录 `watch_state`（三处类型同步、两处元数据重建，重启可恢复），载荷只存
  `lastSeenAt` / `lastNotifiedAt` 水位，不存投递布尔值；恢复时按水位补投一条简报，不重放历史。
- 两类触发源：工作区文件变化（忽略 `.git` / `node_modules` / `dist`）与 localhost 端口就绪；
  设计初稿的 `process_exit` 因 shell 工具尚未向模型暴露进程句柄而**整体摘除**，遗留 kind 登记报
  `WATCH_KIND_UNSUPPORTED`，历史中的遗留记录按残缺数据跳过并输出诊断。
- 触发后以 `role: 'user'` 背景消息落盘并在会话空闲时自动续跑一轮：忙碌期事件按 2s 窗口合并、
  60s 冷却、单会话每分钟最多续跑 1 次的硬上限；通知去重依赖 `watchSource.eventId`，
  重复投递不会产生第二条历史消息。
- 只有持有会话写租约的宿主布置触发源；CLI 与桌面同时打开同一会话时，另一侧只读状态不重复投递。
- 模型侧新增 `watch_start` / `watch_cancel`，CLI 新增 `/watches [cancel <id>]`，wire 新增
  `watch/list` / `watch/cancel`；桌面提供会话徽标、系统级通知与斜杠命令，独立可视化面板顺延后续版本。

## 🧰 技能管理与导入

- 新增 `/skills inspect [--json]` 诊断与 `/skill import`（CLI），桌面新增
  `resources.inspectSkills` / `resources.importSkills`；外部 Harness 目录**只在打开导入界面或执行命令时
  扫描一次**，不进入运行期发现链，也不参与预算、同名优先级或自动同步。
- 导入是显式 mutation：预览 → 隔离写入 → 原子替换 → 写 `.imported-from.json` 溯源；不执行来源代码、
  不建工作树；越界符号链接跳过；同名默认跳过，覆盖需显式选择且旧副本移到技能根之外；
  单来源上限 200 个候选 / 64 MiB，超出返回 `partial: true`。
- frontmatter 导入时归一：`context` / `agent` / `model` / `effort` / `hooks` / `shell` 与未知字段被剥离并写诊断，
  `allowed-tools` 含参数模式时整条丢弃；这是刻意的安全收敛，来源技能行为可能与原 Harness 不同。
- `getSkills()` 返回值附加 `enabled` / `roots` / `lifecycle`（纯新增），生命周期事件只记录发现事实与原因码、
  不携带正文，上限 200 条；`resources.importSkills` 的项目作用域仅在已信任项目上可用。

## 🔌 MCP 管理与分发更新

- 新增 `/mcp add|remove|edit`，把既有 `mutateGlobalMcpConfig` 泛化为 `mutateMcpConfig`：全局与项目级共用
  同一事务（独占锁、损坏中止、全量校验、原子写）；`--project` 只在已信任项目上可写，未信任直接
  `MCP_PROJECT_UNTRUSTED` 拒绝，不提供交互绕过。
- MCP 执行改为**逐服务器批准**（`/mcp approve|revoke`，记录 `~/.kapibala/mcp-approvals.json`）：
  批准绑定「作用域 + 服务名 + 完整配置摘要」，命令 / 参数 / 环境键值 / URL / headers 任一变化即失效并回到待批；
  未批准的 server 不启动、不后台拉起、不进入工具集；记录只存摘要与时间戳，不保存敏感配置值。
  **升级提示**：旧版本没有批准记录，升级后每个 server 首次启动会重新请求一次批准。
- 新增 `/mcp import` 与桌面 `resources.inspectMcpImport` / `importMcp`：一次性扫描并导入 Claude Desktop /
  Claude Code / Cursor 的 MCP 声明，预览结果是脱敏投影（不含 env / headers 正文），同名默认跳过。
- 桌面设置页 MCP 区块由「全局可写、项目只读」扩展为完整管理面（保存 / 删除 / 启停 / 批准 / 撤销），
  写入仍与 CLI 同一事务、同一把锁；`resources.readMcp` 诊断条目新增 `severity`。
- 新增桌面更新检查与下载（主进程 `app.checkUpdate` / `app.downloadUpdate` / `app.cancelUpdateDownload`）：
  只由用户点击触发、只读查询 GitHub Releases；下载地址只取主进程保存的上一次结果且必须是
  `https://github.com/`；先取 `SHA256SUMS` 并确认目标条目，再流式下载到系统下载目录，摘要缺失、
  条目缺失或哈希不一致一律拒绝落地并删除临时文件（不提供跳过校验）；进度节流后推送，同一时刻只允许一个下载。

## 🖼️ 产物预览

- `write_file` 成功写入图片产物（png / jpg / jpeg / gif / webp / bmp / svg）时投影到既有右侧 dock 自动预览，
  自动弹以 `(workspaceKey, toolCallId)` 为消费键只触发一次，历史重放、切回或用户关闭后不复弹；
  工具行保留常驻 chip，顶栏提供「打开产物预览」手动重开入口，无产物不渲染。
- 路径按固定允许根校验（会话工作区 + OS 临时目录），整根排除 `~/.kapibala` 凭据区；
  `realpathSync.native` 后先判边界再判存在，拒绝码区分 `path_not_allowed` / `file_not_found`。
- SVG 经 `<img>` data URL 渲染，脚本不执行、外链不加载；读取失败退化为文件名提示，不发起必然失败的请求。

## 📋 任务面板与输入区状态

- 新增会话任务清单工具 `todo_write`：四态 `pending / in_progress / completed / cancelled`，
  `in_progress` 允许 0..N（首个为主任务，其余 `+N`），读路径取分支历史中最后一次成功调用，
  不落新记录类型、不占写租约，并补一条压缩保护规则。
- 桌面新增输入框上方任务进度 pill 与任务浮层、底栏状态条（空间 / Git 分支 / 上下文）；
  CLI 新增 `/todos` 同口径展示。

## 🔐 权限模型重做（P0）

- 三档预设 `Approval` / `Auto` / `FullAccess` 不变，内部改为「沙箱边界 × 询问策略」两轴组合；
  命令分级从程序白名单改为风险类别（`read` / `workspace-write` / `vcs-write` / `network` / `destructive` /
  `escape` / `unknown`），冲突取最严，非交互场景下 `ask` 按 `deny` 处理。
- 新增可解析写法的硬禁区（直接拒绝、不产生审批）：`.git/hooks`、`.git/config`、`.env*`（豁免
  `.env.example` / `.sample` / `.template`）、`.envrc`、`.kapibala/**`、`.github/workflows/**`、`.npmrc`、
  `.netrc`、`.git-credentials`；shell 重定向、`tee`、`cp` / `mv`、`sed -i`、`find -delete` 命中禁区直接 deny，
  解析不了的写法统一归为 `unknown` 询问。
- 自写脚本自动放行附加清洁度校验：仅当脚本与 HEAD 一致且未修改时才在 Auto 模式放行，
  脏 / 未跟踪脚本需询问；会话批准指纹绑定脚本目标摘要，目标被改动即失效重审。
- 路径身份统一走 `fs.realpathSync.native`，并补齐 PowerShell 反斜杠与盘符路径的分类，消除 POSIX 主机越界与禁区漏判。
- 三级审批记忆（`session` / `project` / `global`）、`maxClass` 与设置页规则视图为 P1，顺延 v0.1.7。

## 🖥️ 桌面与界面增强

- 正文与思考块升级到 `streamdown` 生态：全语言按需高亮、代码块折行开关与 HTML/SVG 预览、
  Mermaid 严格模式与滚入视口懒加载、KaTeX 公式，并加单 `$` / 单 `~` 误判守卫。
- 工具行增强组收口：主行显示名 + 结果摘要、参数降为次要等宽行，保留缩进并允许横向滚动，
  失败原因内联首行（完整结果仍在详情抽屉）；耗时与最后活动展示；连续同类调用合并为
  「已读取 3 个文件」「运行 20 次，1 次失败」等分组摘要。
- 助手回答新增重试与逐条 token 消耗：Core 回退上一轮并持久化 usage，Host 以 `history_replaced`
  整体重建视图；重试只对最后一轮且在宿主空闲时出现。
- 输入框支持 ↑/↓ 召回聊天历史：桌面按会话保留未提交草稿，CLI 关闭 readline 隐式历史避免与自有历史冲突。
- 产物预览支持 SVG 并在顶栏提供重开入口；兼容 SSE 尾部空 choice；dev 实例锁按心跳自愈。

## 📦 协议与 SDK（破坏性变更）

本地 wire 从 `{ major: 1, minor: 0 }` 区间协商改为**整数代际 + 能力集合**：

- `PROTOCOL_VERSION` 为整数 `2`，`initialize` 提交 `protocolVersion` 与 `capabilities`
  （本版新增能力 `watch` / `evidence`）；服务端严格相等校验，失败返回 `PROTOCOL_MISMATCH`，
  旧 `{major,minor}` 报价在参数校验阶段即 `INVALID_PARAMS` 失败，官方不承诺旧客户端降级连接。
- ViewModel 纯新增 `ViewArtifact`、`ViewTodoState` / `ViewTodoItem` / `ViewTodoStatus`、`ViewEvidence`
  与可选 `ViewTool.artifacts`、`PresentationState.todos`、`ViewMessage.usage`；旧渲染忽略即保持原行为。
- Core 新增可选 `ShellScope.scriptTrust` 与 `computeScriptTargetDigest`、技能生命周期类型与
  `SkillRegistry.lifecycle` / `roots`，以及 `getMessageUsages()` / `rewindLastTurn()` / `restoreBranch()` 等；
  逐条影响与迁移动作见[v0.1.4 迁移说明](../migration/v0.1.4.md)与 [SDK 兼容性盘点](../sdk-compatibility.md)。

## ⬆️ 升级

本版为**破坏性协议升级**，CLI 与桌面端需同时升级到 0.1.4 及以后版本：

```bash
npx @kiturone/kapibala-cli@0.1.4
npm install -g @kiturone/kapibala-cli@0.1.4
npm install @kiturone/kapibala@0.1.4
```

升级后 MCP server 首次启动会重新请求一次批准（旧版本没有批准记录）；三级审批记忆与规则页
（016 P1）、`process_exit` 进程退出监视、桌面独立监视面板不在本版承诺范围。

桌面包仍为未签名测试包：macOS 需右键打开或 `xattr -dr com.apple.quarantine`，Windows 会触发 SmartScreen；
应用内更新检查只做完整性校验（`SHA256SUMS`），不证明来源。
