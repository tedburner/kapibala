# Kapibala v0.0.6：受控 MCP 生态接入与安全架构加固

本版实现 Model Context Protocol (MCP) 规范的受控生态接入，以独立公共包 `@kiturone/kapibala-mcp` 交付，保持 Headless Core 运行时零外部依赖。本地与集成验收见 [验收记录](../verification/v0.0.6.md)，迁移指南见 [迁移说明](../migration/v0.0.6.md)。

## 交付要点与新增能力

- **独立包架构与 Headless 防线**：新增 `@kiturone/kapibala-mcp`，Core 源码绝不反向依赖 MCP 包，外部 MCP SDK 依赖严格隔离在扩展包内；Core 运行时依赖依然为 0。
- **配置发现与多层覆盖**：支持全局 `~/.kapibala/mcp.json` 与项目级 `<projectRoot>/.kapibala/mcp.json`；项目级配置受项目信任隔离控制，未信任项目自动排除并告警；提供 `--no-mcp` 宿主禁用硬防线。
- **可靠进程与传输管理**：
  - **Stdio 传输**：支持受控子进程生命周期管理、优雅关闭与跨平台进程树（Windows taskkill / POSIX SIGTERM+SIGKILL）强制回收，避免孤儿进程；
  - **Streamable HTTP 传输**：统一处理 SSE/HTTP 双向流，内置 RFC 1918 私网网段与保留地址硬拦截，Socket Remote IP 二次复核防御 DNS Rebinding。
- **启动授权与工具分离**：服务启动授权与工具调用授权完全分离；非 TTY 环境下拒绝未经审批的 Stdio 服务启动，严格阻止恶意静默拉起子进程。
- **安全工具发现与命名隔离**：
  - 工具统一映射为 `mcp__<server>__<tool>` 命名空间；
  - 参数模式严格归一化校验与预算审计；
  - 终端展示格式化为 `[MCP: server] tool`，自动脱敏 key/token/secret/password/credential 等敏感参数。
- **工具事务闭合与结果转换**：
  - 严格保持历史闭合不变量：assistant 的 `tool_use` 必须紧随对应的 `tool_result`，提前取消或超时正规闭合为取消状态；
  - 消息级落盘包含可选 `mcpSource` v1 元数据，发往外部模型 wire 时自动剔除内部来源。
- **Prompt 模板受控执行**：
  - 支持 `/prompts [query]` 纯内存元数据搜索（不预取远端正文）；
  - `/prompt <server>/<name> [arguments-json]` 参数校验与受控获取，以单条 user 消息安全接入统一任务执行流。
- **CLI 管理命令与交互**：
  - `/mcp` 查看全部服务状态与能力统计；
  - `/mcp tools <server>` 查看服务导出的工具与只读安全标记；
  - `/mcp reconnect <server>` 沿用已解析配置安全重连；
  - `/mcp enable <server>` / `/mcp disable <server>` 会话内动态切换服务，纯内存生效，忙碌期间安全拦截。

## 安装与使用

需要 Node.js 20 或更高版本。

```bash
# 全局安装 CLI
npm install -g @kiturone/kapibala-cli

# 安装 Core SDK 与 MCP 扩展包
npm install @kiturone/kapibala @kiturone/kapibala-mcp
```
