# Kapibala v0.1.0：桌面客户端

给已有的 Agent Harness 套上一层窗口：同一个 Core、同一套工具与审批、同一份会话历史，换成了可并排查看的多会话侧栏、图形化设置页和原生生命周期入口。终端与 SDK 的用法不变。

## 🖥️ 桌面形态

- 单个 `utilityProcess` 承载 Agent Host，复用 Core 与 MCP；渲染层只经受控 IPC 通信，没有 Node 能力，也拿不到任意 IPC 通道。
- 默认空间开箱可用；挂载项目要过一次显式信任确认，未确认前不读项目指令、不写项目配置。
- 工作区身份、会话句柄与审批裁决都由 Host 决定，渲染层提交的路径与身份不参与裁决。
- 系统深浅色跟随，单色主题；并排详情、覆盖式详情与三档宽度断点各有独立焦点策略。
- 关窗不退出：macOS 走 Dock，Windows / Linux 提供托盘；窗口隐藏或失焦时任务结束用系统通知提示，托盘内直接退出。

## 💬 会话

- 多会话并行：句柄池有上限，关闭保留历史，清理成功才释放占用。
- 上下文菜单现在支持**重命名 / 置顶 / 归档 / 删除**：置顶会话排在列表前部；归档从侧栏移出，在设置页「会话归档」里按空间分组恢复或删除。
- 删除是物理删除（正文 `.jsonl` + 元数据 sidecar 一起移除），会二次确认；会话正在运行时直接拒绝，只有空闲句柄会先自动关闭再删。
- 改名与置顶走同一条控制记录通道（`title` / `pin_state`），落在会话正文里，sidecar 重建不会丢状态。

## ⚙️ 模型设置

- 一屏可读的厂商 → 模型列表，内置 8 家厂商 / 20 个模型，可自建端点。
- 密钥按厂商族共用一份：同一厂商只需配一次，借用来源会在界面上显式写出来，不会静默串用。
- 端点变更后旧密钥不会自动发往新地址。

## 📦 安装

npm 三包照旧：

```sh
npm i -g @kiturone/kapibala-cli
```

桌面版本版**未签名、未公证**，不提供自动更新，随 Release 附带的只有维护者本机打出的 macOS arm64 测试包（产物名带 `Test`，appId `dev.kapibala.desktop.test`）：

- macOS 首次打开：右键 →「打开」，或 `xattr -dr com.apple.quarantine /Applications/Kapibala.app`。
- Windows 若拿到测试包会触发 SmartScreen：「更多信息」→「仍要运行」。

`packages/desktop` 保持 private，不进 npm 发布集合；桌面端版本随工作区同步。

## ⚠️ 已知限制

这一版按**未签名个人自用版**口径发布，以下项目**没有**完成，文档与后续说明都不会把它们写成已完成：

- 代码签名、公证、票据装订，以及 Windows / Linux / macOS x64 安装包。
- 六类人工验收专项（Node 20 实机、Windows 跨用户 ACL 与 ConPTY、POSIX PTY、跨解释器进程树、MCP 全链路、release 长跑）的人工审核 —— 本轮只保留自动化门禁结果。
- 自动更新、窗口多开、Worktree 物理隔离、编排画布。

自动化门禁没有放宽：`verify` 工作流的 ubuntu / macos / windows 矩阵、Node 20 安装、compat、release 长跑、`verify:desktop` 的 mac/win e2e 与三包 registry 安装 smoke 都在同一次发布里跑。

## 🔁 兼容与迁移

- wire 协议仍是 1.0，CLI 与 SDK 的历史格式、事件语义不变。
- Core 公共 API 有增量：`SessionManager` 新增 `pinSession` / `renameSession` / `deleteSession`，`SessionMetadata` 新增 `pinned`，`SessionRecordType` 新增 `pin_state`；宿主侧 `ManagedHostSession` 同步新增 `rename` / `setPinned`。旧调用方不需要改动。
- 迁移动作见[迁移说明](../migration/v0.1.0.md)，公开差异见 [SDK 兼容说明](../sdk-compatibility.md)。

## 🔭 下一步

v0.1.1 做两件事：跨会话消息引用（把别的会话历史作为带溯源头的冻结快照引入当前会话），以及多任务派发（委派会话升级为可见、可续聊的一等会话）。规划见[版本路线图](../RELEASES.md)。
