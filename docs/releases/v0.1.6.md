# Kapibala v0.1.6：Git Worktree 并行隔离、Shadow Git 检查点、UI 2.0 墨工坊工作台与断流自愈

感谢使用 Kapibala 并持续反馈工程场景需求。本版将 Kapibala 从单目录串行会话工具全面升级为支持多 Agent 同仓并行隔离、轮次级文件可逆回滚、并排五标签工程检视与流式断连自愈的多代理编码工作台。

## 同仓多代理并行不抢锁、零污染文件检查点回滚、UI 2.0 墨工坊五标签工作台与流中断自动恢复 ✨

- 🌿 **Git Worktree 并行物理隔离与两阶段无损合并。** 新建本地对话、`/delegate --worktree`、`spawn_agent(isolation: 'worktree')` 与外部代理会话均可一键切出受管独立工作树（`~/.kapibala/worktrees/<4hex>/<repo>`），彻底解除单写者锁对同仓库并行改码的阻塞；内置两阶段冲突隔离合并（冲突留在工作树内交由 Agent 解决，主工作区零污染快进落盘）与 Windows NTFS Junction 安全清理。
- ⏪ **零 `.git` 污染的 Shadow Git 轮次检查点与整轮真实 Diff。** 在 `~/.kapibala/checkpoints/` 维护侧挂快照库（支持 Git 仓库 `alternates` 秒级零拷贝初始化与非 Git 普通目录兜底），打通本地 `run_command` 与黑盒外部代理会话的整轮真实磁盘 Unified / Split Diff，支持在重新生成回答、切换分支或工作台审阅时按归因路径外科还原磁盘文件（保留用户原有未跟踪文件，事后手动改动自动弹出冲突确认）。
- 🎨 **UI 2.0「墨工坊 Ink Atelier」全量重构与可拖拽五标签右侧工作台。** 彻底卸载第三方预设组件库 `@cloudflare/kumo`，基于原生 `<dialog>`、`popover="auto"` 与暖墨纸张语义设计系统重写桌面全部视图；新增并排可调宽五标签工作台（`变更`、`预览`、`文件`、`终端`、`详情与证据`），内置惰性加载 `node-pty` + `200K` 回放缓冲的会话级保活终端与本机回环开发端口沙箱预览。
- 🤝 **子代理审批向父会话冒泡、委派层级树与桌面 `@` 双模跨会话引用。** 修复子代理规则继承与后台运行期审批断层，子代理触发 `ask` 时携最内层身份向父会话内联审批叠卡冒泡并暂停运行超时计时；侧栏原生呈现父子委派树与跨空间运行收件箱；输入框 `@` 支持同面板切换检索工作区文件与同空间历史会话/消息快照胶囊（压缩后仍保留引用溯源索引），新增跨分支结构化摘要 `/branch --summary`（兼容 `--with-summary`）。
- 🔄 **模型请求有限指数退避重试与流中瞬时断连无痕恢复。** Core 模型循环新增 `Retry-After` 响应头解析、`90s` SSE 分块空闲看门狗、配额/余额耗尽快速剥离及最多 2 次带抖动指数退避重试；流式输出中途断网时自动下发 `stream_reset` 清空未提交半截残文并重发当前模型步，已完成工具调用 100% 保留不重复执行。

## 详细变更

### 🌿 Git Worktree 并行隔离与合并审阅

*解耦项目归属根（`projectRoot`）与会话实际执行根（`executionRoot`），打通本地、子代理与外部代理共用的受管工作树全生命周期。*

* 新增宿主级 `WorktreeService` 与跨子系统 `ExecutionRootCoordinator`：统一使用 `<home>/.kapibala/worktrees/<4hex>/<repo>` 短路径桶本地零网络切出分支（自动规避 `refs/heads/kpbl` D/F 引用冲突、剥离继承 `GIT_*` 环境变量、拷贝 `.worktreeinclude` 受控常规文件）
* 新增 4 步 `.git` 双向 `fs.realpathSync.native` 回链校验（`verifyManagedWorktreeLink`），安全继承已信任主仓库权限并阻断伪造 `.git` 指针越权；Core `PathSandbox` 同步将任意层级 `.git` 精确路径本身纳入写硬禁区
* 新增冲突隔离式本地合并（`previewMerge` → `applyMerge`）：校验 `previewToken` 未漂移后先在受管工作树内合并主分支，存在冲突时主工作区保持干净并可一键填入助手解冲突提示词；无冲突时主工作区执行原子 `git merge --ff-only`
* 新增三路脏状态检查与 Windows NTFS Junction 安全清理（`removeWorktree`）：删除前核查未提交变更、敏感被忽略文件与未合并提交，Windows 下先行解除目录联接再清理工作树，并在设置页「会话归档」提供孤儿工作树一键清扫
* CLI 新增 `-w, --worktree [branch]` 启动参数、`/delegate --worktree`、`/external start --worktree` 与 `/worktrees` 命令组；Wire v2 新增 `'worktree'` 能力与 7 个 `worktree/*` 方法

### ⏪ Shadow Git 工作区检查点与真实磁盘 Diff

*在不触碰用户项目 `.git` 历史与暂存区的前提下，为本地工具、Shell 命令与外部代理补齐轮次级真实文件快照与定向可逆回滚。*

* 新增 `CheckpointService`（`~/.kapibala/checkpoints/<projectKey>/<executionRootHash>/`）：Git 仓库自动通过 `objects/info/alternates` 共享对象库并复制主仓索引预热，普通非 Git 目录自动建裸仓兜底；强制屏蔽 `core.hooksPath`、拦截盘符根与 `$HOME` 高危目录，并实施单文件 `10 MiB` / 单目录 `200` 文件 / 单次 `64 MiB` 三层未跟踪文件预算及 `500 MiB` 分桶自动修剪
* 轮次前置采样设置 `5s` 超时预算与连续 2 次超时会话级自动熔断，后置采样记录完整变更路径集与增删行数并实时推送 `diffSummary`
* 新增外科归因路径回滚与三路哈希冲突预检：回滚仅触碰目标轮次区间内 Agent 实际增删改的路径，自动保留 `pre-restore` 备份引用；若用户在轮次结束后手动修改了归因文件则默认返回 `conflict` 交由用户确认是否强制覆盖
* 打通本地 `run.regenerate({ restoreFiles: true })`（「还原文件并重试」）、CLI `/checkpoints` 与 `/branch --restore-files`、外部代理会话「仅还原归因磁盘文件」及 Wire v2 `'checkpoint'` 能力

### 🎨 UI 2.0「墨工坊」桌面重构与五标签工程工作台

*全面退役 `@cloudflare/kumo`，落地零外部预设组件库的原生语义原语、四域 Zustand 状态架构、五标签并排工作台与 CLI 同构终端主题。*

* 新增 `packages/desktop/src/renderer/ui/` 原生组件原语库与 `styles/{tokens,base,prose,shiki,index}.css` 双主题语义令牌（暖白纸张与暖黑石墨基调，全面禁用 `transition-all` 与硬编码色值，渲染层全目录单文件严格控制在 `≤ 450` 行并由 `pnpm check-desktop` 门禁守护）
* 重构顶层应用壳 `AppShell`（响应式 `wide` / `medium` / `minimal` 三档视口与 `Ctrl+K` / `Ctrl+B` / `Ctrl+J` / `Ctrl+,` / `Ctrl+1..5` 全局快捷键）、左栏 `NavigationRail`（运行收件箱 + 项目空间父子会话树）、居中 `LaunchpadView`、统一 `SessionStage`、内联非阻断 `ApprovalDeck`（支持焦点外 `Y / S / N` 单键审批且零原始 UUID/宿主路径泄漏）、`LiveStatusStrip` 与 `OmniComposer`
* 新增右侧可拖拽分栏 `WorkbenchStage` 五标签工作台：
  * **变更（`DiffTab`）**：支持会话累计、按轮次检查点、相对工作树基线三档范围与 Unified / Split 双视图切换，集成冲突确认还原与工作树合并面板
  * **预览（`PreviewTab`）**：统一承载断网沙箱 HTML/SVG 渲染、安全允许根图片产物预览与本机回环开发服务（`localhost` / `127.0.0.1` / `[::1]`）实时预览，严格拦截私网 RFC1918 与云元数据地址
  * **文件（`FilesTab`）**：支持工作区/受管工作树文件模糊检索、只读代码行号检视与一键插入 `@文件` 引用
  * **终端（`TerminalTab`）**：`agent-host` 惰性加载 `node-pty`（含 macOS `spawn-helper` 权限自愈、Windows ConPTY 降级兜底、Linux 打包按需原生重编与未就绪时的面板级优雅降级、`200K` 分段回放缓冲与 `16ms` IPC 合批），跨标签切换 DOM `hidden` 保活不丢滚动缓冲
  * **详情与证据（`InspectorTab`）**：检视工具调用入参输出、审批底层环境载荷及四维会话证据看板
* 将模态设置弹窗升级为壳内主舞台 `SettingsStage` 八大二级分组（常规、模型与服务商、默认模型与路由、外部代理、权限审批、资源管理、会话归档、诊断），单层 `<ModalDialog>` 承载新增/编辑子表单
* CLI 同步升级 `packages/cli/src/ui/theme.ts` 与紧凑欢迎头，统一 `NO_COLOR` / `FORCE_COLOR` 降级与语义符号表

### 🤝 子代理审批冒泡、委派收口与跨会话引用

*闭合多级子代理权限继承与人工审批冒泡链路，打通桌面委派树与 `@` 历史会话快照引用。*

* 新增 `SubagentApprovalBroker` 与 `SubagentApprovalOrigin`：嵌套子代理（`root → A → B`）触发人工审批时保留最内层子代理身份冒泡至父会话控制面；等待人工审批期间自动暂停子代理运行超时计时器；支持父轮次已结束后的后台 `detached` 子代理审批投递，并修复子代理 `PermissionPolicy` 规则继承遗漏
* 桌面输入框 `@` 升级为「文件 / 会话与消息」双模 `ReferencePopover`，选中历史会话或消息记录即挂载可移除快照胶囊，发送时冻结注入 `<session-reference>` 且用户消息气泡干净展示结构化 `@标题` 溯源徽章
* 上下文压缩器在摘要旧消息前自动提取 `<session-reference>` 生成紧凑溯源存根（`R2.1`），防止长会话压缩后丢失历史引用出处
* 新增 `AgentSession.createBranchWithSummary`、桌面页头「分叉并附带背景摘要」与 CLI `/branch --summary`（兼容 `--with-summary`，`R2.2`）

### 🔄 模型请求自动重试与 SSE 断流恢复

*精准区分临时故障与配额耗尽，支持流式半截输出无痕重置重试，不重复执行已完成工具。*

* 重构三套模型适配器（Anthropic Messages、OpenAI Responses、OpenAI Compatible）统一走共享 `openModelResponse` 与 `parseSSE` `90s` 分块空闲看门狗，流中途意外 EOF 统一标记为可重试传输中断
* 在通用 `429` 限流判定前优先识别 `402`、`insufficient_quota`、余额不足及厂商配额错误码并直接标为不可重试，在桌面输入框底部给出「切换模型」直达引导；解析 `x-should-retry`、`retry-after-ms` 与 `retry-after`（超 `60s` 立即报错不盲等，命中窗口附加 `0..+20%` 防惊群正向抖动）
* `AgentLoop` 在单步模型调用失败且满足重试条件时发出 `stream_reset` 与 `retry_scheduled` 事件，`PresentationStore` 原子丢弃当前未落盘模型步的流式草稿块并展示退避倒计时（支持随时点击「停止」中断退避），前序已落盘工具调用结果完整保留

## 升级与安装说明

本版为**非破坏性升级**：`@kiturone/kapibala`（Core，保持 **0 运行时依赖**）与 `@kiturone/kapibala-mcp` 公共导出零移除符号，本地宿主协议保持整数版本 `2`（新增能力 `'references'`、`'retry'`、`'checkpoint'`、`'worktree'`，旧客户端仍可正常握手并连续接收事件）。升级细节与安全边界见 [v0.1.6 迁移说明](../migration/v0.1.6.md) 与 [SDK 兼容性盘点](../sdk-compatibility.md)。

- **命令行与 SDK（需 Node.js 20+）**：

```bash
npx @kiturone/kapibala-cli@0.1.6
npm install -g @kiturone/kapibala-cli@0.1.6
npm install @kiturone/kapibala@0.1.6
```

- **桌面客户端**：在 Release Assets 下载对应平台的安装包。当前桌面构建仍为未签名个人自用测试包（不宣称已完成代码签名、公证或四平台人工实机安装验收），macOS 首次打开需右键打开或执行 `xattr -dr com.apple.quarantine`，Windows 首次运行会提示 SmartScreen；Linux 打包若缺少对应架构的 `node-pty` 预编译二进制，会自动尝试通过本机 `node-gyp` / `electron-builder`（需 Python 3、`make` 与 C++ 编译工具链）针对目标 Electron ABI 重编，若运行环境缺少 `pty.node` 则仅将工作台「终端」标签降级为不可用提示，不影响核心会话、文件与 Diff 功能；下载后请核对 `SHA256SUMS.txt`（详见 [桌面发布说明](../desktop-release.md)）。
