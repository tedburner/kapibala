# Kapibala v0.1.2：修复 Windows 安装副本连接挂死与发布附件命名

本版修复 Windows 安装副本（含 CI 打包 smoke）控制端口永不投递、应用挂死的问题，并调整 Release 附件命名；v0.1.1 未产出的 Windows 安装包在本版补齐。

## 🖥️ 桌面

- 修复 Windows 安装副本冷启动挂死的根因：CI Windows runner 的临时目录是 8.3 短名（如 `RUNNER~1`），路径里的 `~` 被 Node `pathToFileURL()` 百分号编码成 `%7E`，而 Chromium 回读的帧 URL 保留字面 `~`。主进程的 `kpbl:ready`、bootstrap-theme、剪贴板权限与资源白名单都做 URL 字面比较，两侧永不相等，守卫静默拒绝，控制端口永不投递，renderer 干等到超时。这是确定性失败，与启动快慢无关——早前归因于 Defender 实时扫描拖慢握手是误诊（失败 trace 里安装副本复制仅约 0.2 秒、启动约 3 秒，并无慢扫描）。
- 修复为 `normalizeUrl`（`main/url.ts`）：比较前把 RFC 3986 未保留字符（字母 / 数字 / `-._~`）的百分号编码还原为字面字符，其余编码统一大写；不解码保留字符，不放宽同源判定。所有 URL 比较点两侧统一规范化。
- 回归门禁：安装副本 smoke 的安装目录刻意带 `~`，在所有平台确定性复现该路径形态；新增 `normalizeUrl` 单测覆盖 `%7E`/`~` 等价与保留字符不解码。
- 连接就绪兜底从 30 秒放宽到 90 秒，supervisor 握手与 smoke 超时同步放宽：这是给冷启动留余量，不是上述挂死的修复。真正失败仍由 `host.unavailable` 事件立即上报并终止等待，不放宽失败判定的速度。
- preload 故障投递修正：连接前到达的 `host.unavailable` 现在无条件终止 ready 等待（旧「仅无监听者才 reject」分支因 ViewClient 顶层订阅而从未生效）；`connect()` 的 attach 失败也仍投递连接端口与故障，不再静默挂起。

## 📦 发布链路

- Release 附件去掉 `desktop-<target>__` 前缀：安装包本身已带 `os-arch`（如 `Kapibala-0.1.2-mac-arm64-test.dmg`），直接用原名；只有各平台同名的 `SHA256SUMS.txt` / `test-build.json` 追加平台短名（`-mac-arm64` / `-win-x64` 等）区分，避免互相覆盖。
- 产物路径在安装副本 smoke 之前写入 `GITHUB_OUTPUT`：smoke 失败时脚本直接退出，原先末尾才写的路径拿不到，导致连 Playwright trace 都上传不了。
- 打包失败时新增上传 `test-results/` 诊断产物，下次安装副本 smoke 失败可直接取现场离线复现。

## ⬆️ 升级

从 v0.1.1 升级无需迁移动作：

```bash
npx @kiturone/kapibala-cli@0.1.2
npm install -g @kiturone/kapibala-cli@0.1.2
npm install @kiturone/kapibala@0.1.2
```

已知限制与 v0.1.1 相同：桌面包未签名（macOS 需右键打开或 `xattr -dr com.apple.quarantine`，Windows 触发 SmartScreen）。
