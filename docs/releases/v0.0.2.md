# Kapibala v0.0.2：可信执行与项目指令

本次发布同时提供 `@kiturone/kapibala@0.0.2` Core SDK 和 `@kiturone/kapibala-cli@0.0.2` CLI。

## 新增能力

- 四态权限模式 `Approval`、`Plan`、`Auto`、`FullAccess`，所有工具执行前统一授权，支持人工审批及精确范围的会话批准。CLI 的 `FullAccess` 只能在本次会话显式选择，仍受显式规则约束。
- 默认脱敏结构化运行日志与逐工具审计，可通过 `/logs` 回溯，并用 `/status` 查看模式、执行环境和日志位置。`--debug` 增加诊断，不控制日志或审计是否启用。
- 多层 `AGENTS.md` 项目指令，在每轮边界刷新；`/instructions` 展示来源。指令文本不能放宽权限或注册工具。
- 默认可用的跨平台 `run_command`：Windows 按 native Bash → WSL → PowerShell 兜底，支持 `--shell` 显式选择和 `--disable-shell` 关闭。
- 稳定工具错误码与重试策略；审批拒绝、取消、超时及审计异常均保持工具历史闭合，结果未知时不自动重试。

## 可靠性与执行边界

- 提前结束会话事件迭代时，取消并等待在途工具清理，工具事务落盘后才释放会话锁；已完成工具保留真实结果。
- 普通日志写入失败报告安全诊断并继续问答；审计写入失败阻止尚未执行的工具，执行后失败报告结果未知。
- 审批提示转义控制字符与双向文本控制符，避免命令被终端重绘隐藏。
- 命令输出归一为 UTF-8，在完整字符边界截断：模型内联最多 64 KiB，受管文件最多 16 MiB；较大输出可通过 `read_file` 读取。
- Git Bash 中止与超时同时终止 MSYS 进程组并确认退出，避免仅终止 Windows launcher 后留下子进程。

命令以当前系统用户权限运行；工作目录及文件工具的 PathSandbox 不提供命令进程隔离。本地审计不具备防篡改能力。

## 升级须知

**SDK 工具授权行为有不兼容变化**：`AgentSession` 默认使用 `Approval`。旧工具未声明 `metadata.permissions` 时需要人工批准；宿主未提供 `approvalChannel` 的待审批调用会被拒绝。请按实际能力补声明和审批通道，不要以默认开启 `FullAccess` 代替迁移。

旧配置与 JSONL 历史仍可读取。详细配置、日志失败处理、迭代器清理约定与回退限制见 [迁移说明](../migration/v0.0.2.md)。

```bash
npx @kiturone/kapibala-cli@0.0.2
npm install -g @kiturone/kapibala-cli@0.0.2
npm install @kiturone/kapibala@0.0.2
```
