# Kapibala v0.0.5：技能体系与过程输出折叠

已于 2026-10-11 发布至 npm 与 [GitHub Release](https://github.com/tedburner/kapibala/releases/tag/v0.0.5)，远端验收见 [验收记录](../verification/v0.0.5.md)。

本版建立可复用、可发现、按需加载的技能体系：技能摘要常驻提示词目录，正文与配套资源按需读取；技能限制只收紧既有权限，来源随历史落盘但永不恢复授权。CLI 默认以摘要展示过程输出，完整内容随时可取。

- 有界发现与信任：项目 `.kapibala/skills`、`.agents/skills` 按序覆盖全局同名目录再覆盖内置；五级优先稳定裁决，软链防环与物理授权边界分别检查，深度/目录/条目上限与 `.gitignore` 子集全程可诊断。
- Frontmatter 有界子集：支持 BOM/CRLF、引号与行尾注释、块标量折叠、字符串列表与一层 metadata，值中孤立引号按纯标量保留；fork/hooks/动态 shell 等执行扩展明确标为不可执行并给出迁移诊断，不静默降级。
- 目录预算与遗漏发现：L2.5 目录默认 min(2000, 窗口 1%) 估算 tokens，描述 250 code points，超限整条移除并给出遗漏数量；`list_skills` 分页查询预算遗漏的技能，游标绑定快照，过期明确报错。
- 共享加载与落盘：`load_skill` 统一模型调用与用户显式入口，正文包装 contentDigest、兼容说明、当前有效工具与限量资源清单；`skillSource` v1 随 TextBlock/ToolResultBlock 落盘，JSONL schema 与记录类型不变，两个内置 Store 均可往返。
- 只收紧的执行限制：`allowed-tools` 兼容归一化并按多技能取交集，未声明不参与；强制检查复用 PermissionPolicy 硬拒绝通道，FullAccess、审批缓存与用户允许均不能绕过；同批加载的资源访问在消息完整提交前返回 SKILL_NOT_COMMITTED。
- 受控资源：`read_skill_resource` 只服务本轮已提交技能包内的相对 UTF-8 文本，单页 64 KiB 以 nextOffset 接续；拒绝越界、盘符、二进制与外部链接，读取独立审计。脚本执行仍走 `run_command` 既有目标识别与审批，读取不等于执行。
- 上下文生命周期：正文有效性按实际投影与 renderedDigest 判定，摘要压缩后保留 requires_reload 重载标记；恢复、切换与新运行不继承活动技能或授权，不重放工具。
- CLI 过程折叠：默认 summary 展示思考/工具/技能摘要，Ctrl+O 切换本轮详情（1 MiB 缓存上限）；`--output-detail detailed` 提供非交互完整公开过程；新增 `/skills [query]` 与 `/skill <name> <task...>`，技能名 Tab 补全。

普通用户默认获得技能能力：项目技能首次使用时确认信任，关闭或禁用走 `skills.enabled` / `skills.disabled`，项目配置只能收紧不能放宽。SDK 宿主不提供 `skills.roots` 时行为与旧版完全一致，Core 不隐式扫描 home；提供时须显式声明项目信任与物理边界。接入与命令示例见 [技能指南](../skills.md) 与 [迁移说明](../migration/v0.0.5.md)。

本地类型检查、全量测试、lint、构建、跨协议 Session、Windows 与 POSIX 真实进程/终端验收已执行，两项已授权真实模型验收完成，证据与限制见 [验收记录](../verification/v0.0.5.md)。单次模型遵循不作为普遍质量保证。

需要 Node.js 20 或更高版本。按版本安装：

```bash
npx @kiturone/kapibala-cli@0.0.5
npm install -g @kiturone/kapibala-cli@0.0.5
npm install @kiturone/kapibala@0.0.5
```
