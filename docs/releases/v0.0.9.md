# Kapibala v0.0.9：本地客户端契约与发布前加固

本版在现有 CLI 包内交付版本化本地协议、Headless 本地宿主、双向审批、一致性快照与 Node 客户端，提供 `serve --stdio`、`daemon start|status|stop` 和 `connect`；直接 CLI 行为保持不变，仍发布 Core、CLI、MCP 三个包。实现与验收见 [验收记录](../verification/v0.0.9.md)，兼容边界见 [迁移说明](../migration/v0.0.9.md)。

## 新增能力

- **本地宿主与连接模式**：提供 `serve --stdio`、`daemon start|status|stop` 和 `connect`，连接模式支持文本任务、`/status`、`/history`、`/close` 与 `/exit`。
- **协议与 Node 客户端**：JSON-RPC 2.0、独立版本 1.0；CLI 包新增 `@kiturone/kapibala-cli/protocol` 与 `/client` 子路径。
- **会话控制与恢复**：同一会话单控制者、单运行，控制代际校验，运行操作 ID 去重；同一工作树子目录复用会话身份。重连通过有界一致快照恢复，不自动重发任务或重放工具。
- **审批、取消与隔离**：复用 Core 五选一审批与工具事务闭合，控制连接断开时取消相关工作。宿主内共享工作区写租约；审批显示绑定后的完整 shell 命令、目录和解释器，控制字符可见转义，超出预算或无法安全展示时拒绝。
- **生命周期与可观测性**：一次性连接结束回收句柄；交互连接可用 `/close` 释放配额。提供工具目标、进度、结果预览、运行诊断和 daemon 私有日志；运行清理失败会显式诊断并清除活动围栏，允许重试关闭；运行时与会话清理成功后才释放存储锁。

## 本版明确未交付

- 不提供 GUI、TCP/HTTP/WebSocket 监听、系统服务安装、自动更新或崩溃后的自动任务续跑。
- 不提供跨连接事件重放；快照总预算为每连接 8MiB，超限明确失败。不同 conversation 的跨进程工作区写入不具备统一互斥。
- 连接模式不承诺全部高级 Slash 命令或任意自定义工具均可人工放行。
- Linux、真实 Windows named pipe/ACL、Node 20，以及真实终端审批、MCP 完整生命周期与长时间资源验收尚待补齐；现有 macOS 证据不能替代这些平台门禁。

## 安装与升级

需要 Node.js 20 或更高版本。升级前请阅读 [迁移说明](../migration/v0.0.9.md)。

```sh
npx @kiturone/kapibala-cli@0.0.9
npm install -g @kiturone/kapibala-cli@0.0.9
npm install @kiturone/kapibala@0.0.9 @kiturone/kapibala-mcp@0.0.9
```

发布标签触发 Actions 完成全量验证、三包发布、公共 registry 安装 smoke 与 GitHub Release；本地构建方式见 [本地宿主说明](../local-host.md)。

## 验证

本地最终门禁：145 个测试文件、1253 项测试通过；全量类型检查、Core/CLI/protocol 边界、展示独立导入、秘密扫描与 Biome 通过。三个发布包与 CLI 的 view-model/protocol/client 产物构建通过；三包 tarball 在隔离目录安装通过，子路径导入不增加进程监听器；macOS / Node v26.12.0 真实 daemon 平台检查通过。完整记录与待补齐的平台门禁见 [验收记录](../verification/v0.0.9.md)。
