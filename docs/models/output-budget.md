# 模型输出预算

`ModelProfile.maxOutputTokens` 是主任务的可覆盖输出上限，必须是正安全整数。
该数值包含思考或推理消耗，不代表全部可见文本配额，也不保证每次请求都会用完。
内置原生 OpenAI 模型建议值为 32768、Claude 5 为 16384；兼容模型缺省仍为 4096。
这些默认值由模型清单提供，Core 不按协议重新猜测或强制提高预算。

有效输出预留为目的上限与窗口 12.5% 的较低值。窗口未知时使用保守的 32000，
因此实际预留最多为 4000；另留窗口 5%（至少 128）的安全余量，其余为输入预算。
例如 1M 窗口和 32768 上限时，输出预留为 32768；128K 窗口下相同上限被约束为 16000。

主任务准备、请求 `maxTokens` 与上下文快照共用同一有效值。
Profile 设置更低值时，不会继续发送原生模型较高的建议上限；SDK 请求显式提供更低
`maxTokens` 时，输出预留与实际字段都会同步降低。请求不能提高 Profile 上限。
配置中的零、负数、小数、NaN、Infinity 或超出安全整数范围的值在调用模型前失败，
不能通过窗口裁剪或目的上限把非法值隐藏为合法预算。

同 run 的签名或加密续答可调用 `ContextManager.prepare()` 第六个参数
`allowCompaction: false` 冻结历史前缀。此时预算检查仍生效；输入过大则明确失败，
不会为继续请求而剪裁前缀或调用摘要模型。

摘要有独立输出目的：先校验所选 Profile，再取 `4096`、Profile 上限和窗口约束的
较低值。即使 summary 路由回退到主任务的 32768 原生模型，摘要也不扩大到主任务上限。
若 Profile 覆盖为 2048，摘要实际请求也最多为 2048。

摘要请求在兼容 Chat 中保留 `temperature: 0`，原生协议沿用各自的采样默认。
summary 未配置时使用 default；明确配置但缺密钥时请求前失败，不静默更换模型。

协议适配器把准备完成的 `maxTokens` 转为对应输出字段：Anthropic 的 `max_tokens`、
Responses 的 `max_output_tokens`，或兼容 Chat 的显式能力字段。会话内的实际 Profile
由当前运行绑定确定，准备请求和 `/context` 使用同一预算来源。
直接调用 Provider 的 SDK 调用者仍需自行传入目标预算，适配器不读取外部 Profile。

上下文估算会计入请求文字、工具 schema、协议内容及合法私有状态的成本。
没有当前请求的服务端 usage 时，上下文保持估算标记；私有状态的字符估算不等于
精确 token 或真实费用。服务端 usage 有效时只校准对应的最终请求与模型。
