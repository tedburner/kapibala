# 011 — v0.1.4 MCP 管理与分发更新

> 状态：**初稿，待维护者终审**。2026-11-16 维护者决策：MCP 管理与分发更新统一并入 v0.1.4（第四主题），
> 与 008（watch）/ 009（技能）/ 010（会话看板）并列为四主题；排期裁决与依赖见 §5。
> 分发更新明确**不走签名链路**（未签名个人自用版定位延续），更新通道只用 GitHub Releases。

## 0. 两块能力的共同语境

- **MCP 管理**：`/mcp` 命令族（v0.0.6）只有运行时观测与会话内启停，配置级增删改只能手编 `mcp.json`；本主题把 MCP 配置管理升级为命令与桌面界面能力，并与 009 的「从其它 Harness 导入」框架对齐。
- **分发更新**：v0.1.0 起自动更新被显式排除、各版悬空；本主题接球，定位是**未签名自用版的轻量更新检查**，不做静默安装链路。

## 1. MCP 管理（M = mcp）

### 现状核实

- 配置真源：`~/.kapibala/mcp.json`（全局）+ `<projectRoot>/.kapibala/mcp.json`（项目级）；
- `/mcp` / `/mcp tools / reconnect / enable|disable`：观测与纯内存启停，不写磁盘；
- 写回纪律：配置写路径必须走既有配置事务模式（对齐 `mutateGlobalSettings` 的事务边界），禁止散落写 JSON。

### 任务拆解

| ID | 任务 | 说明 | 验收 |
|---|---|---|---|
| M0.1 | MCP 配置事务与 CLI 命令 | `/mcp add <name> --transport stdio|http ...`、`/mcp remove <name>`、`/mcp edit <name>`；全局/项目级二选一显式声明；写回走配置事务，非法 JSON 中止不落盘 | 命令族覆盖增删改；与手编文件互不踩踏；`/mcp` 列表即时反映 |
| M0.2 | 从其它 Harness 导入 | 对齐 009 导入框架：Claude Desktop / Cursor / VS Code 的 MCP 配置读取、transport 字段转换、同名冲突默认跳过、导入预览、写 `.imported-from.json` 溯源；一次性拷贝不自动同步 | 三种源格式用例通过；冲突跳过与溯源文件正确 |
| M1.1 | 桌面设置 MCP 管理区块 | 设置弹窗新增 MCP 分区：服务清单 + 连接状态、增删改表单、导入入口；状态展示与 `/mcp` 同口径 | 界面与命令写同一配置事务，无第二真源 |

### 明确不做

- 不做 MCP 服务器市场/远程目录；不做 OAuth 流程的服务器；不改 MCP 子进程生命周期模型；
- 会话内 enable/disable 仍保持纯内存语义，不与配置级 enabled 混用。

## 2. 分发更新（U = update）

### 定位决策（维护者 2026-11-16）

- **不签名**：延续未签名个人自用版口径，签名与公证不进入本版，不作为更新前置；
- **因此不做静默安装**：electron-updater 的静默替换在 macOS 无签名时不可用（Squirrel 校验签名失败），统一降级为「检查 → 下载 → 提示手动安装」三步，三平台一致。

### 任务拆解

| ID | 任务 | 说明 | 验收 |
|---|---|---|---|
| U0.1 | 版本检查通道 | 读 GitHub Releases 最新 release（`releases/latest`），按桌面 target 匹配安装包资产；semver 与 `app.getVersion()` 比较；网络失败静默降级为「未知」不弹错 | 单元用例覆盖比较与资产匹配；离线不阻塞启动 |
| U0.2 | 下载与打开 | 下载到系统下载目录后 `shell.openPath` 提示手动安装（保留 macOS quarantine 右键/xattr 提示文档口径）；不做差分包、不做强制更新 | 下载可取消、失败可重试；安装包 SHA 与 Release `SHA256SUMS.txt` 校验一致才打开 |
| U1.1 | 设置页更新区块 | 「关于」分区：当前版本、检查更新按钮、新版本条目（版本号 + release 链接 + 下载进度）；不弹系统级打扰 | 区块随设置弹窗主题令牌走；与既有分区同层级结构 |

### 明确不做

- 不做签名/公证/公证簿（维护者决策，未签名自用）；
- 不做静默安装、自动重启安装、delta 更新、多更新通道（stable/beta）、强更弹窗；
- 不做 CLI 的自更新（`kpbl` 走 npm，包管理器负责）。
