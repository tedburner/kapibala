# 006 — 桌面视觉精修

> 状态：P0 与 P0 收口均已实施。本文是 [004 桌面宿主设计](004-v0.1.0-desktop-harness.md) 的增量补充，不改变其章节编号、布局骨架与交互决策。
> 技术栈、进程边界和安全约束仍以 004 与 [桌面开发指南](../desktop-development.md) 为准。

## 1. 要解决的问题

004 已规定「紧凑的黑白纸面、扁平 assistant、淡色 user 气泡、细工具行」，但首版实现把「紧凑」落成了「信息裸露」：

- 顶栏直接显示工作区绝对路径，侧栏底部显示内部句柄计数；
- 每条消息重复「你 / Kapibala」，一轮对话没有节奏；
- 工具调用逐条铺开且带分隔线，读起来像日志；
- composer 拆成输入框、空间、模式、模型、发送多行；
- 首页只有一行字，设置是横向标签页 + 表单堆叠，详情抽屉像调试面板。

结论：方向没有错，缺的是**层级纪律**和**产品化表达**。本设计只做执行度补足。

## 2. 目标与非目标

**目标**

1. 一屏之内先读到「任务与结论」，过程信息退后一层。
2. 用固定的表面、墨色、字号、间距档位替代逐处微调。
3. composer 成为唯一输入入口，空间 / 模型 / 模式 / 发送收进一张卡。
4. 空态、加载、错误、运行中都有明确形态，不再临时拼字。
5. 保留水豚品牌识别，但强调色只作信号。

**非目标**

- 不引入第二套组件库、图标库或动画库。
- 不复制 Qoder 的双窗口 / 任务面板，也不复制 PiDeck 的文件树、Git、终端三栏。
- 不改变会话、运行、审批、信任的任何 Host 语义。
- P0 不做搜索、命令面板、右栏任务面板。

## 3. 方向

**黑白纸面 + 克制的水豚暖色。**

结构仍是「256px 侧栏 + 单一阅读列 + 360px 详情抽屉」。视觉上把界面分成三层：

| 层 | 内容 | 表达 |
|---|---|---|
| 结论层 | 用户问题、assistant 正文 | 最高对比度、最大字号、唯一阅读轴 |
| 过程层 | 思考、工具、执行摘要 | 次级墨色、成组折叠、无分隔线堆叠 |
| 框架层 | 侧栏、顶栏、composer 卡、抽屉 | 弱边框、少层级、固定档位 |

## 4. Token 档位

所有值仍只写在 `theme-kapibala.css`，组件内不出现十六进制色值。

### 4.1 表面阶梯

沿用 Kumo 语义 token，建立四档，不再新增色板：

| 档 | Token | 用途 |
|---|---|---|
| sunken | `kumo-canvas` | 应用底色、抽屉外侧 |
| base | `kumo-base` | 主阅读面、composer 卡 |
| raised | `kumo-elevated` | 浮层、卡片 |
| recessed | `kumo-recessed` | 悬停、分组头、次级区域 |

规则：同一屏内最多出现三档；边框只用 `kumo-line` 与 `kumo-hairline`，不为每个区块加框。

### 4.2 墨色

- `kumo-strong`：标题、用户消息、关键数值。
- `kumo-default`：正文。
- `kumo-subtle`：元信息、时间、路径、状态说明。
- 占位符只用 `kumo-placeholder`，不拿 subtle 代替。

### 4.3 信号色

新增两个主题变量，仅用于「正在发生」的状态：

```css
--kapibala-signal: #b0653a;        /* 浅色：水豚暖棕 */
--kapibala-signal-soft: rgb(176 101 58 / 12%);
```

深色主题取 `#d9a075` / `rgb(217 160 117 / 18%)`。

使用范围：运行中的状态点与文字、品牌标记旁的活动提示。
**不用于**：正文、链接、大面积背景、普通按钮、装饰。

这两个变量是**应用自有变量**，不并入 004 §6.3.4 的主题表：那张表逐项对应 Kumo 语义 token，混入非 Kumo 变量会让「主题只有一处真源」的对应关系失效。新增同类变量的登记位置是本文件，落地位置仍是 `theme-kapibala.css`。

### 4.4 字阶、间距、圆角

- 字号四档：12（元信息）/ 13（控件与工具行）/ 14（界面正文）/ 15（对话正文）；正文行高 1.75。
- 间距只用 4px 网格：4 / 8 / 12 / 16 / 24 / 32。
- 圆角三档：`rounded-md`（控件）/ `rounded-lg`（分组、输入）/ `rounded-xl`（仅 composer 卡与首页引导卡）。
- 对话列宽度保持 848px；用户气泡最大 85% 宽。

## 5. 结构规则

### 5.1 顶栏

- 第一行：`空间名 / 会话标题`。
- 第二行：可读状态（运行中、待审批、可以继续对话、新建对话或选择历史），**不显示绝对路径**。
- 右侧只保留：审批入口、会话状态、关闭会话。
- 路径只在详情抽屉与信任弹窗中出现。

### 5.2 侧栏

- 品牌位使用 `assets/icon.svg` 派生标记，文本固定 `Kapibala`。
- 窗口与 Dock 图标使用 `assets/icon.png`：构建期已把它拷到 main 产物同目录（打包配置也指向该文件），主进程在 ready 后显式覆盖 Dock，`BrowserWindow.icon` 与托盘复用同一路径。开发态不覆盖就会一直显示 Electron 自身图标。
- 顶部动作：「新建对话」与「添加项目」采用一致的轻量导航行；主操作排在首位，不用独立描边卡片。默认空间入口按需出现。
- 主操作下方一行搜索框，按空间名与已打开空间的脱敏会话标题搜索；历史在 Host 侧筛选后分页，不改变运行状态或句柄预算。最近项目需先打开才能搜索其历史。
- 空间行只显示：图标、名称、状态（运行中 / 待审批 / 清理未完成）。
- 删除空间下的父目录片段与「句柄 x/y」计数；有效信息改为会话数量或直接留空。
- 「空间」与「最近项目」各有 12px 分组标题；会话相对空间名称缩进，仅当前对话使用选中底色。搜索命中的空间自动展开，全部未命中时给出文字提示。
- 底部只保留设置入口；运行中任务数在本机有任务时以一行弱提示出现。

### 5.3 轮聚合

一轮的边界是「一条 user 消息 + 其后的 assistant / tool 消息」。

- 用户消息右侧气泡，不显示「你」标签；位置和气泡形状已经表达身份。
- assistant 消息只在轮内首次出现时显示一次 `Kapibala` 标记；连续 assistant 消息不再重复。
- tool 角色的消息不单列角色标签，归入过程层。
- 轮与轮之间用 24px 间距，轮内消息用 6–8px 间距。

### 5.4 过程层

- 一条 assistant 消息内连续的 tool 块合并为一个「执行组」：
  - 组头：状态图标 + `执行 N 步` + 状态词 + 展开箭头；
  - 组内：每行一个工具，名称 + 截断的调用摘要 + 状态点 + 图标式「查看详情」；
  - 默认展开，可折叠；折叠状态是易失 UI 偏好，不写回历史。
- 状态点语义：运行中 = 信号色；成功 = `kumo-success`；失败 = `kumo-danger`；中断 = `kumo-subtle`。状态点必须有可读的无障碍名称。
- 思考块收成一行：图标 + 「思考过程」+ 箭头，默认折叠；流式生成时展开。
- 「复制正文」只在悬停或键盘聚焦时出现，不占据常驻视觉。

### 5.5 Composer

一张带边框的卡片，内部三段：

1. 无边框输入区（2–6 行自适应）；
2. 工具条左侧：空间、模式、模型；
3. 工具条右侧：发送 / 停止，圆形按钮。

卡片宽度与对话列一致，最大 848px，窄窗口随容器收缩；输入时宽度保持稳定，避免工具栏和发送按钮横向跳动。

规则：

- 输入区不显示独立边框或焦点环，焦点环由卡片整体承担。
- 空间、模式、模型都是低权重文字按钮，不抢输入区。
- 空间按钮在会话内外都保留：换空间不必先回侧栏；切空间会关闭当前会话视图，运行中的任务仍在后台继续。
- 模型菜单只列**已配置凭证**的模型（`credential.configured`，不代表连接已验证）。未配置密钥的内置模型不进选择入口；设置页保留全量清单并标注「未配置密钥」，那里才是补密钥的地方。
- 一个新对话没有会话配置，模型按钮展示**当前空间生效的默认模型**并允许改选；改选必须在创建会话后、首个任务启动前经 `session.configure` 落地，只改显示文案视为缺陷。
- 模式按钮只在已打开会话出现：新会话模式由全局设置决定，界面不猜一个值出来。
- 解释性文案不再常驻；只有「空间未信任」「没有可用模型」这类阻断原因才出现在卡片下方，并各自给出处理入口。
- 运行中把发送换为停止，展示取消 / 清理阶段。

### 5.6 空态

新对话首页使用正式引导结构：品牌标记、一句定位、三条可点击的起步示例。
示例只把文本填入草稿，不自动发送，不创建会话。

示例下方补一行上下文：当前空间名与工作目录（目录中段省略，完整路径只在悬浮提示与详情抽屉里），再加「新建对话」「添加项目」两个次级动作。这是 §5.1「路径只出现在抽屉与信任弹窗」的唯一例外，只放弱化后的目录，不把绝对路径摆到首屏正文。

空态高度由剩余空间决定，不写死；窗口最小时允许内部收缩，不出现横向滚动。

### 5.7 设置

- 左侧固定宽度分组导航，右侧内容滚动；分组使用 Kumo Tabs 原语（`role=tab` 与键盘方向键保持）。
- 分组：模型与服务商、默认模型与路由、外观、诊断。
- 「诊断」独立成末级分组，承载版本、运行时、通知 / 托盘、复制诊断与退出。
- 关闭、焦点约束、Escape 仍由 LayerDialog 提供。

### 5.8 详情抽屉

- 顶部：标题 + 当前空间 / 会话标题。
- 工具详情首屏顺序：状态与耗时、实际调用、结果与错误。
- 路径不作为首屏内容；放入「运行事实」的次级信息。
- 观察摘要、技能、MCP、子任务仍保留，但归入「运行事实」之后。

## 6. 交互与无障碍

- 不新增动画；只使用 Kumo 内置过渡，减少动效时全部归零。
- 所有图标按钮必须有中文 `aria-label`；状态点不能只靠颜色表达，需带文本或无障碍名称。
- 工具行、执行组、空态示例都必须可键盘到达，焦点可见。
- 保留现有 E2E 入口名：`发送消息`、`发送`、`查看详情`、`打开设置`、`新建对话`、`添加项目`、`审批 N`、`会话状态`。
- 详情抽屉关闭后焦点回到触发按钮；轮聚合与折叠不得改变这一点。

## 7. 验收

1. `pnpm typecheck`、`pnpm test`、`pnpm lint` 通过。
2. `packages/desktop/e2e/desktop.spec.ts` 与 `visual-matrix.spec.ts` 通过，不修改既有断言语义。
3. 在 1280×800、800×800、1280×600、800×600 四组窗口截取首页、对话、设置、审批、详情：
   - 无横向滚动；
   - 顶栏不出现绝对路径；
   - 侧栏不出现句柄计数；

## 9. 修订记录

### 2026-10-26 — P0 收口

首轮 P0 落地后仍有三处「设计写了、实现没跟上」，本次一并补齐，并明确与 004 的边界：

- **侧栏搜索从 P2 提前到 P0。** 只做视图过滤，不引入命令面板；「命令面板、任务面板、可选右栏」仍留在 P2。
- **composer 在新对话下暴露模型。** 默认值取当前空间生效的默认模型，改选后在创建会话时先 `session.configure` 再启动，避免「显示 A、实际用 B」。
- **空态补空间与目录上下文。** 目录以省略形式出现在首屏，完整路径仍在悬浮提示与抽屉，§5.1 的意图不变。
- **文案去术语。** 侧栏菜单、外观说明与清理失败提示里的「句柄」全部换成用户能理解的说法；`shared/rpc.ts` 的错误文案同样在约束范围内。
- **分组标题落地。** 「空间」「最近项目」各用一行 12px 弱化标签，最近项目行不再重复父目录片段，路径交给悬浮提示。

未做且明确不在本文件范围：工具 diff 内联、审批内联到工具行、会话分组——它们是 P1。

### 2026-10-27 — 输入区与可用性修订

真实窗口试用后的四处反馈，全部落在 composer 与品牌外观上：

- **composer 宽度改成随内容自适应**（§5.5）。固定 848px 会让短句右侧留出整条空白，现在按最宽一行与工具条取大，320–848px 之间浮动。
- **空间入口常驻**（§5.5）。原来只在未打开会话时出现，用户必须先回侧栏才能换目标空间；现在会话内也可切换，切换会关闭当前视图、运行中的任务留在后台。
- **模型选择只列可用模型**（§5.5）。`credential.configured` 为 false 的内置模型不再出现在菜单里；设置页保留全量并标注「未配置密钥」，作为补密钥的入口。一个可用模型都没有时，卡片下方直接说明原因并给出设置入口，发送按钮保持禁用。
- **品牌图标进窗口与 Dock**（§5.2）。开发态 Electron 显示自身图标，主进程 ready 后覆盖 Dock；窗口 `icon` 与托盘复用构建期已拷贝到 main 产物旁的 `icon.png`，不再复制第二份资产。

### 2026-10-27 — 交互审查修订

输入卡采用稳定宽度，用户消息气泡按内容收缩并右对齐；侧栏搜索覆盖已打开空间的全部历史页，待审批和运行中会话优先。新对话模型以界面实际展示的可用项配置，切换空间清除临时选择。

### 2026-10-27 — 历史与结果预览

工具行可展开有界结果或统一 diff 预览，完整结果仍在详情中。侧栏显示历史活动时间，运行时操作在悬停或键盘聚焦时显示；搜索先对标题脱敏再筛选，匹配结果分页。

### 2026-10-27 — 侧栏布局修订

参考 Codex、Qoder 与 WorkBuddy 的侧栏层级，将顶部动作改为对齐的轻量导航行，搜索框贯穿内容宽度，空间和会话以缩进建立层级；侧栏采用独立的浅灰或深色表面。
