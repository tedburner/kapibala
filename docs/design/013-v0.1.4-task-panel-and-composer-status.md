## 0. 一句话定义

会话任务面板 = **模型声明、宿主重算、两端只读展示的会话级任务清单**：`todo_write` 全量替换清单 → 宿主从历史投影 `ViewTodoState` → 桌面以输入框上方 pill 与浮层展示，CLI 同口径输出 `/todos`。

## 1. 与相邻能力的分界

| 能力 | 语义 | 数据源 |
|---|---|---|
| 执行组「执行 N 步」（[006 §5.4](006-desktop-visual-refinement.md)） | 一条 assistant 消息内的工具过程聚合 | `ViewTool` 流 |
| U1.8 分组汇总 | 连续同类调用的过程汇总（「读取 3 个文件」） | `ViewTool` 流 |
| `StatusFacts.tasks` | 子代理 / 委派任务状态 | AgentRuntime |
| [010](010-v0.1.4-session-evidence-dashboard.md) 会话看板 | 会话「做了什么、依据什么」（变更 / 引用 / MCP / 委派） | 工具与消息事实 |
| **本文任务清单** | **模型对「打算做什么、做到哪」的自我声明** | `todo_write` 工具调用 |

结论：过程证据无法反推语义计划（「Service 与 Controller 实现」只有模型知道），任务项必须由模型显式声明；U1.8 只优化过程行，不替代本能力。

## 3. 工具与领域模型

```ts
/** 任务状态；只表达计划状态，不承载执行结果与工具关联。`cancelled` 表示模型主动撤销，不等于「未开始」。 */
export type TodoStatus = 'pending' | 'in_progress' | 'completed' | 'cancelled';

/** 一条任务项；id 由模型生成并在清单内唯一，宿主不落盘、不改写。 */
export interface TodoItem {
  id: string;
  title: string;
  status: TodoStatus;
}
```

`todo_write`（Core builtin）：

- 入参 `{ items: TodoItem[] }`，**全量替换**语义：每次调用提交完整清单，不做增量合并；历史重算只需最后一条成功调用。
- 校验（自定）：1–50 条；`title` 非空且 ≤200 字符；`id` 清单内唯一；状态四态
  `pending / in_progress / completed / cancelled`；**`in_progress` 允许 0..N 个**，不硬拒多个。理由：ZCode 的契约注释明确允许多个进行中，硬拒会让模型为通过校验而漏写并行任务组；oh-my-pi 也选择在写入侧接受、展示侧归一。展示层取第一条为「主任务」，其余折叠为 `+N`（见 §6）。
  归一：重复 `id` 与空标题属结构非法直接拒绝；状态词非法同样拒绝——这些是「清单坏了」，与「并行任务多」不是一类。
- **写互斥**：`todo_write` 是「读当前分支历史 → 全量替换 → 追加记录」的读-改-写；委派会话与父会话
  可能并发提交，必须在会话内加写互斥（复用既有写租约 / 会话锁），否则全量数组会 lost update。
  锁只覆盖单次写入，不跨工具调用持有。
- 无文件 / shell / 网络副作用；不声明 `permissions`（无匹配 `Capability`）；不设 `readOnlyHint`（会改变会话状态）；Plan 模式放行——规划阶段正是本工具的主要场景。
- 结果文本返回归一化确认（`任务清单已更新：4/8 已完成，进行中「…」`；多个进行中时追加 `（另有 N 项进行中）`），供模型自检；UI 不消费结果。
- 显示名登记：[tool-presentation.ts:106](../../packages/host/src/host/ui/tool-presentation.ts#L106) 的 `BUILTIN_TOOL_DISPLAY` 增加 `todo_write: 更新任务清单`。U1.1 约定：新增内置工具漏登记即门禁失败。
- 实现位置：`packages/core/src/capabilities/tools/builtin/todo.ts`（新），并加入 `builtinTools` 数组（[fs.ts:452](../../packages/core/src/capabilities/tools/builtin/fs.ts#L452)）。

## 4. 落盘与重建（关键决策）

**不新增落盘记录类型**：清单状态从当前分支历史中**最近一次成功（status = completed）`todo_write`
调用的入参**重算，与 010「从既有记录重算」同口径；失败或被中断的调用不改变视图（否则一次失败
写入会把面板闪成空），工具结果只作过程证据。`cancelled` 条目保留在清单中，由模型显式声明。

压缩保护（必做）：把「包含最近一次成功 `todo_write` 的交互」并入 `protectedMessageIds`（在 [history.ts:211](../../packages/core/src/context/history.ts#L211) 现有规则旁增补），保证旧清单声明不会先于最后一次成功交互被压缩。**拒绝新增 `todo_state` 控制记录**：需要三处类型同步与两份元数据重建（AGENTS.md 已记录两次静默丢状态），收益仅是省一次投影重算，不值得。

- 分支切换：按当前分支历史重算，任务清单天然按分支隔离；
- 会话恢复 / 重启：从 sidecar 历史重放得到同一清单，无需额外持久化；
- 空历史或从未调用：`todos` 为 `undefined`，面板与 pill 隐藏。

## 6. 桌面交互（对标 Qoder，取三段）

1. **输入框上方 pill**：`任务 4/8 · <主任务标题>`（标题过长截断）；存在多个 `in_progress` 时追加 `+N`；点击开合浮层；010 变更统计落地后追加 ` · N 个文件 +A −D`；无清单不显示；运行中随工具终态实时更新。
2. **任务浮层**：锚定 composer 上方；每项 = 状态图标 + 标题，`in_progress` 信号色 + 旋转图标（多进行中全部保留该态，不把 `+N` 降级成 `pending`），`completed` 成功色勾选，`pending` 灰圈，`cancelled` 删除线弱化色（与 `pending` 视觉可区分）；**每项必须有可读无障碍名**（状态不得只靠颜色，项目契约）。只读：用户不增删改，清单由模型维护。
3. **输入框下方状态条**：一行弱化文本 `本地 · <空间名> · <分支> · 上下文 29%`，全部来自既有 `StatusFacts`（`gitBranch`、`contextUsage.percent`）；分支缺失不占位；点击段打开详情抽屉「运行事实」。**不新增探测**：`GitStatusCache` 已有 TTL 缓存与非阻塞语义。
4. 窄窗口：pill 与状态条允许整行截断，不换行撑高；浮层最大高度 40vh 内部滚动。

不复制：Qoder 右侧「提交或推送」动作（git 写操作不在本版）、常驻任务栏、多面板体系；右侧摘要 / 产出 / 来源归 010 / 012。

## 9. 明确不做（v0.1.4）

- 不做用户手动编辑任务、不做任务持久化控制记录、不做跨会话任务聚合；
- 不做任务与工具调用的自动关联（不猜测某次调用属于哪个任务）；
- 不做右侧面板内的任务分区（浮层已覆盖，010 看板不加任务分区）；
- 不做任务通知 / 提醒（与 008 watch 无关）。

## 10. 已定口径（2026-11-20 确认）

1. pill **仅在有清单时显示**，无清单不占位。
2. 底栏第一段**以空间名优先**，无空间时回退「本地」。
3. `todo_write` **在子代理会话注册**，互不影响；父会话只投影自己的分支。
4. 进度分母为**全部条目**，分子为 `completed`。
5. `in_progress` 允许 0..N，不硬拒；第一条为主任务，其余 `+N`（2026-11-20 版本设计 014 定，替代原「至多一个」）。
6. 多进行中在浮层里全部保留进行中样式，不降级展示（2026-11-20 版本设计 014 定）。
7. 状态四态含 `cancelled`；读路径取最近一次**成功**调用；写入加会话内互斥（2026-11-20 版本设计 014 拍板，R8）。
