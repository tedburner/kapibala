# 009 · v0.1.4 技能管理与跨 Harness 导入（设计）

> 状态：规划中（v0.1.4 第二主题；主题一为[会话级监视 watch](008-v0.1.4-session-watch.md)，两者无依赖、可并行）
> 依赖：v0.0.5 已交付的技能发现 / 加载 / 信任与 `/skills` 列表
> 范围：Core 技能诊断事件、宿主导入服务、宿主协议方法、CLI `/skills` 子命令、桌面设置页技能管理

## 1. 定位

技能只从**自有目录**读取与写入，这是维护者 2026-11-16 的明确决策：

> agent harness 只需要管理自己的和使用自己的；可以在管理界面新增从别的 agent harness 导入的功能。

因此本版只解决两件事：

1. **看得见**：技能为什么没生效（未信任 / 格式非法 / 同名覆盖 / 预算省略 / 显式禁用）要能解释清楚。
2. **搬得进来**：用户显式把其它 Harness 的技能**一次性拷贝**进自有目录，之后只认自有副本。

明确不在本版：长期读 `.claude/skills` 等外部目录、导入后的自动同步、技能执行语义变更（`context: fork`、`model` 覆盖、hooks）。

| 缺口 | 影响 |
|---|---|
| 无导入入口 | 用户在 Claude Code / Codex / Cursor / opencode 里已有的技能只能手工复制 |
| 无生命周期事件 | 桌面与 CLI 各自拼装状态，诊断口径不一致 |

只取与本版两件事相关的做法，其余（fork 执行、运行时修饰、远程分发）记为后续，不进本版。

| 项目 | 可借鉴 | 证据 |

结论：**导入是 mutation，不是 discovery**。一旦把「读外部目录」和「自己的目录」混在一起，信任、同名覆盖与变更检测都会变成两套语义；显式拷贝能保持单一真源。

## 5. 导入设计

### 5.1 来源检测

只在**用户打开导入界面时**扫描一次；不进入运行期发现链，不参与预算，不参与同名优先级。

| 来源 | 全局目录 | 项目目录 |
|---|---|---|
| Claude Code | `~/.claude/skills` | `<project>/.claude/skills` |
| Codex | `~/.codex/skills` | `<project>/.codex/skills` |
| Cursor | `~/.cursor/skills` | `<project>/.cursor/skills` |
| opencode | `~/.config/opencode/skills` | `<project>/.opencode/skills` |
| Kapibala（对照） | `~/.kapibala/skills` | `<project>/.kapibala/skills` |

检测规则：

- 目录不存在即跳过，不产生告警；存在但不可读产生 `import_source_unreadable` 告警。
- 只认目录内包含 `SKILL.md` 的技能包，沿用既有有界发现上限（深度 6 / 2000 目录 / 20000 条目 / 单文件 128 KiB）。
- 符号链接按物理边界校验，越界即跳过并诊断，不做跨根复制。

### 5.2 候选与预览

每个候选展示：名称、描述摘要、来源 Harness 与原路径、文件数与总字节、是否含 `scripts/`、**将被剥离的 frontmatter 字段**、与自有技能的冲突状态。

冲突判定按最终写入名（frontmatter `name`，缺省目录名）比较：`none` / `exists-enabled` / `exists-disabled`。

### 5.3 导入动作

- **单个导入**：选中一个候选 → 校验 → 临时目录写入 → 原子 rename 到目标根 → 写溯源文件。
- **全部导入**：遍历候选，逐个执行同一流程；**默认跳过冲突项**（不覆盖），结束时给出汇总：`导入 N / 跳过 M（冲突 X、超限 Y）/ 失败 Z`。
- **目标根**：默认全局 `~/.kapibala/skills`；`--project` 或界面切换为项目 `.kapibala/skills`，项目未信任时拒绝。
- **覆盖**：仅在用户显式选择「覆盖」或 `--force` 时允许；覆盖前先把旧目录移到 `.kapibala/skills/.backup/<name>-<时间戳>`，失败可回滚。
- **幂等**：目标已存在且内容摘要相同 → 返回 `unchanged`，不写盘。

### 5.4 frontmatter 处理

Kapibala 只支持自有字段子集（见 [skills.md](../skills.md)）。**导入时执行一次显式归一**：

| 字段 | 处置 |
|---|---|
| `name` / `description` / `license` / `compatibility` / `when_to_use` / `argument-hint` | 保留 |
| `allowed-tools` | 保留，但继续只收紧权限；含未知工具或参数模式时整条丢弃并诊断 |
| `metadata`（一层字符串） | 保留 |
| `disable-model-invocation` / `user-invocable` | 保留 |
| `context: fork` / `agent` / `model` / `effort` / `hooks` / shell 表达式 | **剥离并写诊断**，不得静默保留成「看起来能用」 |
| 未知普通字段 | 剥离并诊断 |

归一结果写入目标 `SKILL.md`，同时在溯源文件里记录被剥离字段清单。

### 5.5 溯源文件

目标技能根写入 `.imported-from.json`（隐藏文件，不参与资源列表）：

```json
{
  "version": 1,
  "harness": "claude-code",
  "sourcePath": "/Users/me/.claude/skills/review-guide",
  "importedAt": "2026-11-16T10:20:31.000Z",
  "contentDigest": "sha256:9f1c…",
  "strippedFields": ["context", "model"]
}
```

- `contentDigest` 基于导入后的完整包（文件路径 + 内容）计算。
- 「重新导入」时对比来源当前摘要：相同则提示无需导入；不同则列出差异文件，由用户确认覆盖。
- **不做自动同步**：来源后续变化不会影响自有副本，除非用户再次导入。

### 5.6 明确不做

- 运行期长期读外部目录（兼容根）；
- 导入时执行脚本或探测环境；
- 导入后自动更新、watch 外部目录；
- 跨 Harness 的技能依赖解析（`dependencies` 字段继续剥离）。

## 6. 管理面

### 6.1 CLI

```
/skills inspect [--json]            发现模式、扫描根、每个技能的来源/路径/告警
/skills manage [--project]          交互式管理：启用/停用、详情、导入
/skill import                       列出可导入来源与候选（非 TTY 只打印表格）
/skill import <name> [--from <harness>] [--project] [--force]
/skill import --all [--from <harness>] [--project]
```

- 全部复用既有 `ctx.select` 分页菜单；非 TTY 输出表格与汇总，不交互。
- 命令注册需同时改 `COMMAND_CATALOG` 与 `assemble.ts` 的 handler 表。

### 6.2 桌面

- 设置页技能区（`settings-dialog.tsx:1107-1131`）增加「从其它工具导入」按钮与导入抽屉：来源分组 → 候选列表（支持全选 / 单选）→ 预览剥离字段 → 执行 → 汇总。
- 执行后刷新 `resources.readSkills`；失败项保留在抽屉内可重试。
- 无 hover 设备上导入按钮与复选框必须始终可达（键盘 focus 不跳）。

### 6.3 宿主协议

新增两个方法（与既有 `resources.readSkills` 同族）：

```ts
'resources.inspectSkills': { workspaceId: string };
'resources.importSkills': {
  workspaceId: string;
  scope: 'global' | 'project';
  items: Array<{ harness: string; name: string }>;  // 空数组 = 全部
  overwrite?: boolean;
};
```

- 三处登记缺一不可：`packages/host/src/protocol/types.ts`、`schema.ts`（`REQUEST_SCHEMAS` 白名单）、`results.ts`；桌面还需在 `packages/desktop/src/preload/index.ts` 的 `contextBridge` 暴露面同步。
- 只传来源身份，不传正文；正文一律由宿主读取（与跨会话引用同一条信任原则）。
- wire 版本：两个方法属于新增能力，跟随 v0.1.3 的协议次版本决定，不单独再升。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 从不可信来源导入（技能内含提示注入） | 导入前预览正文；导入后仍是普通 `SKILL.md`，权限只收紧；`allowed-tools` 未知项直接丢弃 |
| 导入覆盖用户已有技能 | 默认跳过冲突；覆盖需显式确认并先备份到 `.backup/` |
| 全部导入把大量技能塞进预算 | 沿用既有 L2.5 目录预算；导入汇总提示「已导入但目录中省略 M 条」 |
| 剥离字段导致技能行为与来源不一致 | 预览与汇总都列出被剥离字段，并在溯源文件保留清单 |
| 项目级导入绕过项目信任 | 项目作用域导入在未信任项目上直接拒绝，不进入确认流程 |

## 10. 已定口径

1. 来源检测**只在打开导入界面时扫描一次**，不在桌面启动时预热（2026-11-20 确认，避免启动 I/O）。
2. 全部导入的**默认作用域为全局**；项目作用域需用户显式切换（2026-11-20 确认）。
3. 导入后**默认保持启用**（2026-11-20 确认；剥离后已是合法技能，禁用只会多一步操作）。
