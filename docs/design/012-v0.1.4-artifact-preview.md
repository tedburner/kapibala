# 012 — v0.1.4 右侧产物预览（图片自动预览）

> 状态：**初稿，待维护者终审**。2026-11-20 由维护者提出：对标 ZCode / maka 的右侧工作面板
> （side pane），v0.1.4 只取其中最小切片——**agent 生成的图片文件自动在右侧预览**。
> 浏览器 / 终端 / 计划等面板类型是远期扩展，本文不承诺（见 §5 / §6）。

## 0. 一句话定义与会话内呈现

右侧产物预览 = **工具调用写盘了可预览产物（图片）时，宿主把产物路径投影给桌面端，
右侧 dock 自动切到预览模式渲染图片**：自动弹一次（防打断契约），工具行保留常驻 chip
入口，随时可再开。

对标（已核实，参考仓源码）：ZCode `useAppPanels.ts` 的 side pane 体系（30+ 种面板，
按任务 scope 记忆展开状态）；maka 资源面板的文件预览。对标只取「agent 驱动联动 +
右侧 dock」的信息架构；tab 复用、PTY 保活、多面板体系是后续版本的事。

## 1. 数据通道现状（逐条核实）

| 环节 | 现有通道 | 缺口 |
|---|---|---|
| 右侧容器 | `DetailsDrawer`（`kapibala-dock`，`wide` 非模态常驻模式，`--kapibala-dock-width: 360px`）已具备 dock 形态 | 只差「预览」展示分支（现只有工具详情 / 会话状态两种） |
| 图片安全预览 | `kpbl-preview` 协议：`preview.file()` 主进程读取本地图片回 data URL（`IMAGE_MIME_BY_EXTENSION` 白名单 + `IMAGE_PREVIEW_LIMIT` 字节上限）；HTML 走沙箱 iframe（`PREVIEW_SCHEME`，断网禁外链） | **已实现**，渲染层直接复用 |
| 工具事件流 | `PresentationChange.tool_changed` / `message_committed`（带 `ViewTool`），host 投影单调推进 | 事件源现成 |
| 结构化产物 | `ViewTool` 只有脱敏字符串（`input` / `result`），**没有产物路径字段**——宿主投影层不知道某次调用写了图片 | **唯一新数据通道**，见 §2 |

结论：容器、安全预览协议、事件源三块全现成，真正的新增只有「产物投影」一条通道。

## 2. 产物投影的最小方案（自定决策）

在宿主投影层识别，不动 Core 工具协议：

- `ViewTool` 增加 `artifacts?: readonly ViewArtifact[]`，`ViewArtifact = { kind: 'image'; path: string; ext: string }`；
- 识别规则（v1 口径保守，只认宿主能确认的事实）：
  - `write_file` 入参目标路径命中图片扩展名白名单（png / jpg / jpeg / gif / webp），
    且结果为成功终态 → 投影该路径；
  - `edit_file` 不投影（改图非生成图场景）；
  - `run_command` 等间接产物**不投影**（无法可靠归因，与 010 看板「不计命令行间接改动」同口径）；
  - MCP 工具：仅当工具显式声明输出文件路径字段时投影（v1 不做结果文本正则猜路径）；
- 路径投影前经宿主确认文件存在且未超 `IMAGE_PREVIEW_LIMIT`；超限只投影文件名 + 提示，
  不给渲染层半张图。

## 4. 交互信息架构（我们自定的选择）

1. **自动弹一次**：`tool_changed` 终态事件携带首个 image artifact 时弹出右侧预览；
   同一会话同一产物不重复自动弹（对齐审批面板「仅新增时弹」的可达性契约）；
2. **常驻入口**：工具行显示产物 chip（图片扩展名图标 + 文件名），点击打开 / 聚焦预览；
3. **预览面板**：标题为文件名 + 扩展名徽章，主体居中渲染，底部一行尺寸 / 字节事实；
   多产物依次出现在同一 dock 内替换显示（v1 不做 tab 切换）；
4. **关闭即收起**：关闭后不自动再弹同批产物；新工具调用的新产物才触发下一次自动弹。

## 5. 明确不做（v0.1.4）

- 不做浏览器 / 终端 / 计划 / 白板等面板类型（PTY 保活与浏览器进程管理是独立工程量，另立文档）；
- 不做多面板 tab 体系与任务级记忆（ZCode 式 sidePaneOwnerKey，v0.1.4 单 dock 单内容）；
- 不做 PDF / Office / 视频预览（HTML 预览已有，其余按需另立）；
- 不做产物编辑 / 标注（只读预览）；
- 不新增落盘记录类型——历史会话重放时从工具块重算产物，与 010 口径一致。

## 6. 决策点（待维护者定）

1. **识别范围**：v1 只认 `write_file` 成功终态是否够用？若日常以 MCP 图片生成工具为主
   （如 ImageGen 类），可能需要为 MCP 增加「输出文件字段声明」，量级另估；
2. **SVG 档位**：走沙箱 iframe（安全正确但交互与位图不一致）vs v1 先不投影 SVG
   （更保守）；建议后者，SVG 场景极少且可后补；
3. **自动弹的开关**：是否需要设置项（默认开）；参考实现均为默认自动弹，v1 建议不加设置；
4. **与 008–011 的并行排期**：P0/P1 与看板（010）共享工具行界面线改动，合并顺序待排；
   `ViewTool` 新字段随 008 / 009 / 010 的 wire 版本升级统一裁决（一次 minor 升级）。
