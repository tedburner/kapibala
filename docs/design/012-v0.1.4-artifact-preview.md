# 012 — v0.1.4 右侧产物预览（图片自动预览）

> 状态：**终审稿**（2026-11-20 随[版本设计 014](014-v0.1.4-version-design.md)收敛）。2026-11-20 由维护者提出：对标 ZCode / maka 的右侧工作面板
> （side pane），v0.1.4 只取其中最小切片——**agent 生成的图片文件自动在右侧预览**。
> 浏览器 / 终端 / 计划等面板类型是远期扩展，本文不承诺（见 §5 / §6）。

## 0. 一句话定义与会话内呈现

右侧产物预览 = **工具调用写盘了可预览产物（图片）时，宿主把产物路径投影给桌面端，
右侧 dock 自动切到预览模式渲染图片**：自动弹一次（防打断契约），工具行保留常驻 chip
入口，随时可再开。

对标（已核实，参考仓源码）：ZCode 的 side pane 体系在 `packages/ui/src/hooks/useAppPanels.ts`，
面板种类是 `packages/ui/src/lib/workspaceSidePane.ts` 的 26 个 `WorkspaceSidePaneTab` 成员，
展开状态按任务 scope 记忆；maka 侧是 Workbar 的文件区与 Artifact Pane（并非「资源面板」）。
对标只取「agent 驱动联动 + 右侧 dock」的信息架构；tab 复用、PTY 保活、多面板体系是后续版本的事。

## 1. 数据通道现状（逐条核实）

| 环节 | 现有通道 | 缺口 |
|---|---|---|
| 右侧容器 | `DetailsDrawer`（`kapibala-dock`，`wide` 非模态常驻模式，`--kapibala-dock-width: 360px`）已具备 dock 形态 | 只差「预览」展示分支（现只有工具详情 / 会话状态两种） |
| 图片安全预览 | `kpbl-preview` 协议：`preview.file()` 主进程读取本地图片回 data URL（`packages/desktop/src/shared/preview.ts:28-44` 的 `IMAGE_MIME_BY_EXTENSION` 白名单 + 8 MiB `IMAGE_PREVIEW_LIMIT`）；HTML 走沙箱 iframe（`PREVIEW_SCHEME`，断网禁外链） | **已实现**，渲染层直接复用 |
| 工具事件流 | `PresentationChange.tool_changed` / `message_committed`（带 `ViewTool`），host 投影单调推进 | 事件源现成 |
| 结构化产物 | `ViewTool` 只有脱敏字符串（`input` / `result`），**没有产物路径字段**——宿主投影层不知道某次调用写了图片 | **唯一新数据通道**，见 §2 |

结论：容器、安全预览协议、事件源三块全现成，真正的新增只有「产物投影」一条通道。

## 2. 产物投影的最小方案（自定决策）

在宿主投影层识别，不动 Core 工具协议：

- `ViewTool` 增加 `artifacts?: readonly ViewArtifact[]`，`ViewArtifact = { kind: 'image'; path: string; ext: string }`；
- 识别规则（v1 口径保守，只认宿主能确认的事实）：
  - `write_file` 入参目标路径按 **MIME 优先**判定：扩展名经 `imageMimeByExtension` 映射到
    png / jpg / jpeg / gif / webp / bmp / svg 才投影；SVG 与位图共用 `preview.file()`
    的 data URL 通道进 `<img>`，脚本不执行、外链不加载（与 §6 第 2 条一致）；
  - 目标路径经 `fs.realpathSync.native` 后按**固定允许根**校验：会话工作区、OS 临时目录与固定应用
    目录可读；**整根排除 `~/.kapibala`**（该根含 `settings.json` 等凭据）；先判边界再判存在，
    越界返回 `path_not_allowed`，不存在返回 `file_not_found`，两个拒绝码不得合并；结果为成功终态 → 投影该路径；
  - `edit_file` 不投影（改图非生成图场景）；
  - `run_command` 等间接产物**不投影**（无法可靠归因，与 010 看板「不计命令行间接改动」同口径）；
  - MCP 工具：仅当工具显式声明输出文件路径字段时投影（v1 不做结果文本正则猜路径）；
- 路径投影前经宿主确认文件存在、是常规文件且未超 `IMAGE_PREVIEW_LIMIT`；超限只投影文件名 + 提示，
  不给渲染层半张图；
- 同一工具调用的同一路径只投影一次（去重按 `toolCallId + path`）。

## 4. 交互信息架构（我们自定的选择）

1. **自动弹一次**：`tool_changed` 终态事件携带首个 image artifact 时弹出右侧预览；
   去重键是 `(workspaceKey, toolCallId)`，不是会话内全局「仅第一次」——同一会话后续工具调用
   的新产物仍可自动弹，而 attach 快照重放与窗口重建不会重弹（对齐审批面板「仅新增时弹」）；
2. **常驻入口**：工具行显示产物 chip（图片扩展名图标 + 文件名），点击打开 / 聚焦预览；
3. **预览面板**：标题为文件名 + 扩展名徽章，主体居中渲染，底部一行尺寸 / 字节事实；
   多产物依次出现在同一 dock 内替换显示（v1 不做 tab 切换）；
4. **关闭即收起**：关闭后不自动再弹同批产物；新工具调用的新产物才触发下一次自动弹；
5. **顶栏手动入口**：当前会话存在可预览产物时，顶栏显示「打开产物预览」按钮，点击打开
   最新产物；没有产物时不渲染，避免出现点了没有内容的入口。自动弹只覆盖新产物一次，
   该按钮负责关闭后的主动重开。

## 5. 明确不做（v0.1.4）

- 不做浏览器 / 终端 / 计划 / 白板等面板类型（PTY 保活与浏览器进程管理是独立工程量，另立文档）；
- 不做多面板 tab 体系与任务级记忆（ZCode 式 sidePaneOwnerKey，v0.1.4 单 dock 单内容）；
- 不做 PDF / Office / 视频预览（HTML 预览已有，其余按需另立）；
- 不做产物编辑 / 标注（只读预览）；
- 不新增落盘记录类型——历史会话重放时从工具块重算产物，与 010 口径一致。

## 6. 已定口径

1. **识别范围**：v1 只认 `write_file` 成功终态的图片产物；MCP「输出文件字段声明」不在本版（2026-11-20 确认）。
2. **SVG**：v1 纳入投影（2026-11-23 维护者确认；经 `<img>` data URL 渲染，脚本不执行、外链不加载）。
3. **自动弹**：默认自动弹，不加设置项（2026-11-20 确认）。
4. **并行排期**：P0/P1 与看板（010）、任务面板（013）共享工具行 / 输入区界面线改动，
   合并顺序见 014 §4.7 的共享文件合并顺序；`ViewTool` 新字段随 v0.1.4 一次性进入整数协议版本 2。
5. **路径信任**：产物路径按**固定允许根**校验（会话工作区 / OS 临时目录 / 固定应用目录），
   `realpathSync.native` 后**先判边界再判存在**；整根排除 `~/.kapibala`；拒绝码
   `path_not_allowed` / `file_not_found` 分离；只认常规文件（2026-11-20 版本设计 014 拍板，D5）。
6. **BMP / SVG**：投影判定跟随 MIME 白名单放行；SVG 自 2026-11-23 起纳入，经 `<img>` 渲染。
