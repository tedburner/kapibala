# 008 · v0.1.4 会话级监视（watch）设计

> 状态：**终审稿**（2026-11-20 随[版本设计 014](014-v0.1.4-version-design.md)收敛；主题一「会话级监视」，主题二「技能管理与跨 Harness 导入」见[设计 009](009-v0.1.4-skills-management-and-import.md)，两者无依赖、可并行）
> 依赖：v0.1.3 交付的 `SubagentOutbox` / `SessionInbox` 通知通道与 `send_agent` 续聊语义
> 范围：Core 控制记录与投递、宿主触发源、CLI `/watches`、桌面徽标

## 1. 定位

让模型或用户在当前会话内登记一个**外部条件监视**（文件变化、端口就绪；进程退出顺延 v0.1.5，见 §5），本轮正常结束；条件命中（或超时）后，由宿主以背景消息落盘并**自动续跑一轮**，让对话继续。

这与三类相邻能力的分界：

| 能力 | 执行体 | 生命周期 | 触发源 |
|---|---|---|---|
| 子代理（`spawn_agent`） | 独立 `AgentSession` | 有 run、有终态 | 子代理自身结束 |
| 委派会话（v0.1.3 detached） | 独立 `AgentSession` | 终态保留、可续聊 | 用户或父模型发起 |
| **监视（本文）** | **无执行体** | 只是一条控制记录 | **外部条件** |
| `Schedule`（平台定时任务） | 宿主外部 | cron 周期 | 时间 |

结论：它是**会话级异步唤醒**，不是第四种 agent，也不复用 `Schedule` 的 cron 语义。

## 2. 现状核查

已实现：

- `spawn_agent`（`packages/core/src/runtime/agent/tools.ts:31`）
- `SubagentOutbox`（`packages/core/src/runtime/agent/outbox.ts:111`）：JSONL 持久化 + `eventId` 幂等
- `SessionInbox`（同文件 `:228`）：回读父历史按 `payload.subagentSource.eventId` 去重，写 `role: 'user'` 背景消息
- 全局控制记录机制（`session-store.ts:26`、`:53`）

**未实现**（本版要补）：

- 没有任何 `watch` / `wait_for` 工具或命令（全仓检索无命中）
- 没有 watcher 的落盘类型，也没有「外部条件 → 会话消息」的触发源
- 通知通道目前只有「子代理终态」一个触发源

所以这是全新能力，且刻意放在 v0.1.3 之后：v0.1.3 正在把 detached 续聊接入同一通知通道，同版本再改通道会互相干扰。

## 3. 为什么不做模型侧轮询

| 打法 | 问题 |
|---|---|
| 模型自调 `sleep` + `check` | 每轮烧 token 与上下文，轮次上限先到，跨小时不可行 |
| 工具内阻塞等待 | 占住一整轮 run，取消/超时语义难做，且无法跨重启 |
| **事件驱动续跑（本文）** | 零空转，可跨小时与跨进程，复用既有幂等通道 |

## 4. 领域模型

```ts
/** v0.1.4 收窄后的触发源集合；`process_exit` 已摘除，顺延 v0.1.5 接线（见 §5）。 */
export type WatchKind = 'file_change' | 'port_ready';

/** 一条监视的规格；deadlineAt 必填，杜绝无限期监视。 */
export interface WatchSpec {
  kind: WatchKind;
  /** file_change: 工作区相对路径；port_ready: 端口号（仅 127.0.0.1） */
  target: string;
  /** 轮询间隔，仅 file_change / port_ready；下限 2000ms，默认 5000ms */
  intervalMs?: number;
  /** 截止时间；到期投递 timeout 通知并关闭监视 */
  deadlineAt: number;
}

/** 监视状态；作为 watch_state 控制记录的载荷。 */
export interface WatchState {
  watchId: string;
  spec: WatchSpec;
  state: 'armed' | 'fired' | 'timeout' | 'cancelled' | 'orphaned';
  /**
   * 已确认看到的事件时间水位（毫秒）。恢复时只有事件时间晚于它才补投；
   * 这是幂等判定依据，取代布尔型 `delivered`。
   */
  lastSeenAt: number;
  /** 最近一次实际投递时间；仅用于冷却与诊断，不参与「是否欠一次补投」判定。 */
  lastNotifiedAt?: number;
  /** 登记时的分支；通知必须落回该分支。 */
  branchId: string;
  armedAt: number;
  closedAt?: number;
}
```

## 5. 触发源（v0.1.4 交付 `file_change` / `port_ready`；`process_exit` 顺延 v0.1.5）

- **`file_change`**：轮询 `stat` 的 `size + mtimeMs`，变化后计算内容哈希确认；忽略 `.git`、`node_modules` 与 dist 产物。事件先经 300ms 去抖窗口合并、按路径排序去重；同一路径在窗口内只保留最后一次变化（对齐 codex file-watcher 的固定去抖语义）。测试成本最低，作为 W1 首个落地源。
- **自写限制**：v1 不识别「本会话自己写入的路径」，对 agent 自己写入的文件登记监视可能自触发；文档标注该限制，由使用侧避免（见 §11）。
- **`process_exit`（2026-11-21 摘除，顺延 v0.1.5）**：句柄契约缺失——shell 工具未向模型暴露进程句柄，
  裸 pid 有复用风险。本版 Core `WatchKind`、wire 枚举与工具 enum/描述同步收窄；登记遗留 kind 报
  `WATCH_KIND_UNSUPPORTED`；历史落盘的遗留记录按残缺数据整条跳过并输出诊断，不让单条坏记录阻断会话恢复。
  v0.1.5 以「shell 工具返回 handle id + 会话级子进程登记表（持 `ChildProcess` 引用与退出码）+ 宿主三态回调」
  正接线，届时仍禁止任意 pid，进程已不存在时直接 `fired` 带退出码。
- **`port_ready`**：`TCP connect 127.0.0.1:<port>` 成功即 `fired`；仅 localhost，禁止外网地址。

v1 不做：webhook 回调（需要公网暴露）、CI/远端状态（需要 provider 适配，留 v2）。

## 6. 落盘与重建（关键约束）

新增全局控制记录 `watch_state`，**必须五处同步**，漏任一处会静默丢状态（`archived` / `pinned` 各踩过一次，见 AGENTS.md）：

1. `SessionRecordType` 联合（`session-store.ts:26`）
2. `SessionStore` 内的全局类型集合
3. `isGlobalControlRecordType`（`session-store.ts:53`）
4. `SessionManager.buildMetadata` 的元数据重建（`session-manager.ts:763` 附近）
5. `CrossProjectSessionCatalog` 的内联扫描（`catalog.ts`）

约束：`watch_state` 的 `parentId` 为 `null`，**不推进上下文叶子，也不改会话活动时间**；多次变更以「同 `watchId` 追加新记录、读时取最后一条」为准，不改写历史。

## 7. 投递与续跑

触发后：

1. 生成 `WatchNotification { eventId: watchId, watchId, kind, target, state, firedAt, detail? }`；
   一条监视至多产生一条通知，因此 `eventId` 直接取 `watchId`；
   `detail` 是可选的人类可读事实摘要：`file_change` 带内容摘要，`port_ready` 带连接耗时
   （`process_exit` 的退出码摘要随 v0.1.5 接线恢复）
2. 以 `role: 'user'` 背景消息落盘到 `branchId`，正文为 `<watch-event watch=... kind=... state=... firedAt=...>` 结构化标签 + 人类可读摘要
3. 消息级元数据 `watchSource`（与 `subagentSource` 同层，不进 Provider wire），去重靠回读 `payload.watchSource.eventId`
4. 投递成功后写入 `lastSeenAt = firedAt`、`lastNotifiedAt = 投递时刻`

**串行化**：`SessionInbox` 的去重与并发合并逻辑抽成共享 helper（`consumeBackgroundMessage`），`SessionInbox.consume` 对外行为不变，`WatchInbox` 复用同一实现，避免两套去重逻辑漂移。

**水位而不是布尔闩锁**（2026-11-20 版本设计 014 拍板）：`watch_state` **不存 `delivered: boolean`**；
「是否欠一次投递」由 `lastSeenAt < 事件时间` 判定。崩溃、断电、切宿主后只要没确认过就仍欠着，
确认过就自然不欠；布尔标记表达不了「错过了多次」。补投内容是**一条简报**（最新用户提示、
最近一次 assistant 回复摘要、触碰过的文件、工具调用计数、`needs_from_user`），不逐条重放历史。
忙碌期间的多次唤醒进入 pending 队列并按 2s 合并窗口坍缩为一次；60s 冷却与「每会话每分钟最多
1 次自动续跑」保留为硬上限。背景消息固定最低优先级，用户输入不被系统事件饿死。

**归属与租约**：CLI 与桌面可能同时打开同一会话。只有**持会话写租约**的宿主恢复 watcher、
布置触发源并投递（复用 `WorkspaceLeaseCoordinator`）；其余宿主只读 `watch_state`，不补投、
不续跑。水位机制解决「是否欠投」，租约解决「由谁投」，两者不可互相替代。

**投递时机**（防与用户输入竞争）：

- 仅在会话**空闲**（无在途 run、无待审批）时投递并自动续跑；
- 有在途 run 时进入 pending 队列，`run_finished` 后 flush（多事件按 2s 窗口合并）；
- 每会话每分钟最多 1 次自动续跑，超出只落盘不续跑（防止文件频繁变动造成风暴）。

**超时与取消**：`deadlineAt` 到期投递 `state: 'timeout'`；`watch_cancel` 投递 `cancelled`；两者都是终态，不再触发。

**跨重启**：`watch_state` 恢复后，仅持会话写租约的宿重新布置触发源；若水位落后于最后事件时间，
补投**一条简报**并推进 `lastSeenAt`，同一事件不重复投递；历史落盘的遗留 `process_exit` 记录
按残缺数据整条跳过并输出诊断（见 §5），**不以静默失败阻断会话恢复**。

## 8. 工具与命令面

| 面 | 入口 | 说明 |
|---|---|---|
| 模型 | `watch_start` / `watch_cancel` | 参数即 `WatchSpec`（kind 仅 `file_change` / `port_ready`）；受权限与数量上限约束 |
| 用户 | `/watches` | 列表（监视中/已触发/已超时/已取消/已失联）、`cancel <watchId>` |
| 协议 | `watch/list`、`watch/cancel` | 需同时改 `protocol/types.ts`、`schema.ts`、`results.ts` 与桌面 `preload`；随 v0.1.4 整数协议版本 + `watch` 能力 |

宿主状态（2026-11-22 同步）：daemon（`kpbl serve`）、CLI 与桌面均经 `SessionManager.open` 的会话单写者锁（`SessionLock`）保证同一会话同时只有一个宿主恢复并布置触发源；自定义无触发源宿主下 `watch/list` 返回空列表、`watch/cancel` 返回 `INVALID_REQUEST`。

术语遵循设计 007 §11：叫「监视」，状态词固定为**监视中 / 已触发 / 已超时 / 已取消 / 已失联**；不得称「定时任务」（与 `Schedule` 冲突）或「后台任务」。

工具显示名（别名）优化已移交 v0.1.3（[设计 007 §5.4](007-v0.1.3-cross-session-reference-and-delegation.md)），本版的 `watch_start` / `watch_cancel` 直接复用该投影层，不再各端单独实现。

## 9. 权限与安全

- 路径目标必须 `fs.realpathSync.native` 后在会话工作区根内（AGENTS.md 已记录两次短名失配）
- 端口仅 `127.0.0.1`
- `process_exit`（顺延 v0.1.5）：届时只接受本会话启动的进程句柄，禁止任意 pid；本版登记入口对
  遗留 kind 直接报 `WATCH_KIND_UNSUPPORTED`
- 数量上限：每会话 8 个、全局 32 个；超限直接拒绝，不排队
- 所有 `watch_start` 经既有权限系统裁决，`Plan` 模式下拒绝

## 11. 风险

| 风险 | 后果 | 处置 |
|---|---|---|
| 控制记录漏同步 | sidecar 重建丢失监视状态 | W0 逐处断言 + catalog 重建用例 |
| 多宿主同时恢复同一会话 | 双份通知、双 run 抢写 | 仅持会话写租约的宿主布置触发源并投递；其余只读 |
| 水位写入与消息落盘不原子 | 重复补投或漏投 | 先落盘背景消息再推进 `lastSeenAt`；补投幂等靠 `eventId = watchId` |
| 自动续跑与用户输入竞争 | 双 run 抢写 | 空闲门 + pending 队列 |
| 轮询风暴 | CPU 与事件堆积 | interval 下限 2s、并发上限、每分钟 1 次续跑 |
| Windows 文件时间精度 | 同毫秒内改动漏检 | `size + mtimeMs` 初筛 + 内容哈希兜底 |
| 历史 `process_exit` 落盘记录 | 单条坏记录阻断会话恢复 | 读取侧按残缺数据整条跳过并输出诊断 |
| 无限期监视 | 资源泄漏 | `deadlineAt` 必填 |
| 对 agent 自写路径登记监视 | 自己写入触发自己续跑，形成循环 | v1 不实现自写识别，文档标注限制；使用侧避免对工具将写入的路径登记监视 |

## 12. 已定口径与遗留问题

1. 自动续跑**默认开启**，不要求 `autoResume: true`（2026-11-20 确认；否则能力等同无用）。
2. 桌面通知：**窗口失焦时发系统级通知，前台只更新会话徽标**（2026-11-20 确认）。
3. 监视**不允许**绑定父会话；跨会话唤醒 v1 拒绝（2026-11-20 确认）。
4. 投递判定用 `lastSeenAt` / `lastNotifiedAt` 水位，**不存 `delivered` 布尔值**；恢复补投只发一条简报
   （2026-11-20 版本设计 014 拍板）。
5. 只有**持会话写租约**的宿主恢复 watcher 并投递；多宿主其余只读，不布置触发源
   （2026-11-20 版本设计 014 拍板）。
6. 遗留（v2）：是否接入 CI/远端状态源，以及凭据隔离，届时另议。
