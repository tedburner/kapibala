## 0. 一句话定义与版本承诺

v0.1.5 = **在宿主层新增开放的「外部代理（External Harness）」独立会话域与全图形化管理工作台**：顶层统一一套协议中立的 `ExternalHarnessDriver` 状态机，底层同时提供**通用 `acp` 驱动**（覆盖 Antigravity `agy acp`、OpenCode、DeepSeek Harness、Gemini、Qwen、Oh My Pi、Qoder / Qoder CN、TRAE / TRAE CN、ACP Registry 生态与任意自定义命令）与 **`claude-cli` / `codex-app-server` / `pi-rpc` 三个原生 CLI 直连驱动**（本机已装 `claude` / `codex` / `pi` 零桥接包开箱即用），把流式消息、思考、工具、计划与人工审批投影为与本地会话同构的视图，支持桌面设置页全图形化配置、多工作区并行、有界只读历史归档与受门禁保护的会话恢复；**Core 公共 API 零破坏性改动**。

### 承诺范围

1. **统一外部会话域 + 四套无 SDK 轻量传输驱动**（全部位于 `packages/host/src/host/external/`，0 外部运行时 SDK 依赖）：
   - **`acp`（通用开放生态底座）**：JSON-RPC 2.0 over NDJSON stdio，配极薄 `AcpHarnessFlavor` 钩子与线格式宽容层；原生支持 **Antigravity（`agy acp`）**、**OpenCode（`opencode acp`）**、**DeepSeek Harness（`dsh --profile acp`）**、Gemini CLI、Qwen Code、Oh My Pi（`omp acp`）、Qoder / Qoder CN、TRAE / TRAE CN、官方 ACP Registry 静态模板与任意第三方 **`Local ACP Command`**（自定义命令自动按可执行文件名 / `agentInfo.name` 匹配已知 Flavor）；
   - **`claude-cli`（Claude Code 原生直连）**：直连用户本机 `claude` / `claude.exe` 的双向 `--input-format stream-json --output-format stream-json --permission-prompt-tool stdio` 管道，支持长驻多轮对话、`control_request(can_use_tool)` 交互审批与 `--resume` 恢复，**无需额外安装 `claude-agent-acp` 或捆绑 `@anthropic-ai/claude-agent-sdk`**；
   - **`codex-app-server`（Codex 原生直连）**：直连用户本机 `codex app-server` 双向 JSON-RPC lite 管道，支持 `thread/start`、`thread/resume`、`turn/start`、`turn/interrupt` 及命令/改文件交互审批，**无需额外安装 `codex-acp`**；
   - **`pi-rpc`（Pi Coding Agent 原生直连）**：直连用户本机 `pi --mode rpc` 管道并自动挂载受管只读审批守卫扩展，支持 `extension_ui_request` 交互审批、`abort` 中断与 `--session-id` 恢复，**无需额外安装 `pi-acp`**。
2. **桌面设置页「外部代理」全图形化操作 + CLI `/external` 对等管理**：
   - 在桌面设置弹窗左栏新增一等标签页 **「外部代理」**（Kumo 组件体系），图形化完成：内置代理启用/停用、一键检测连接与版本、路径/参数/`envFrom` 变量名覆盖、从官方 ACP 目录模板一键填充、添加/编辑/测试/删除自定义 `Local ACP Command`（零手改 JSON）；
3. **Windows 无 Shell 安全启动与 GUI 路径兜底**：全程 `shell: false`，支持原生 `.exe` 优先探测、标准 npm/pnpm `.cmd` 三形态静态解包（`.exe` 二进制包 / `.js` 脚本包 / `#!...node` 无后缀脚本）及桌面 GUI 受限 `PATH` 下的常见安装目录只读兜底；
4. **「有界只读展示快照归档」与「权威可恢复门禁」解耦**：在 `~/.kapibala/external/snapshots/` 结算时原子保存脱敏只读展示快照（进程空闲回收或重启后历史输出不丢失），同时严守四项持久身份门禁与启动配置摘要连续性校验（`configDigest`），未通过门禁的会话展示只读归档但禁止伪装续聊；
5. **三端双通道协议对齐**：
   - 本地 Wire **保持整数 `PROTOCOL_VERSION = 2` 不变**（遵守「非破坏性变更不升版本号」硬规则），在 `SERVER_CAPABILITIES` 新增 `'external-session'`；
   - 桌面端走 `packages/desktop/src/shared/contracts.ts` 独立 `external.*` IPC 与 `LatestSnapshot` 通知通道。

### 明确不做（v0.1.5）

- 不做 Git Worktree 自动分支隔离与 Shadow Git 文件级检查点回滚（整体排入 **v0.1.6**，同时服务本地 `/delegate` 与外部代理）；
- 不做反向暴露 `kpbl acp` Server 模式（排入 **v0.1.8+**）；
- 不做后台自动下载解压二进制、`npx` 或 `uvx` 托管包安装，不托管第三方明文 API Key（一律走外部 CLI 自有登录态 BYOS + `envFrom` 变量名白名单转发）；
- 不实现 ACP 客户端侧 `fs/read_text_file`、`fs/write_text_file`、`terminal/*`、`elicitation/create`（一律回 `-32601 Method not found`）；
- 不将 Kapibala 本地的 `Auto` / `FullAccess` 模式映射为自动批准外部审批；
- 不做多会话共享同一外部子进程，不做跨 Agent 自动编排或向本地父会话自动注入结果。

## 3. 领域模型与三套传输驱动契约

### 3.1 Harness 定义与三层配置来源

```ts
/** 外部代理底层传输协议；自定义第三方命令固定走 'acp'。 */
export type ExternalTransportKind = 'acp' | 'claude-cli' | 'codex-app-server' | 'pi-rpc';

/** 一条可启动的外部代理定义；command/args 只存字面量，严禁存明文密钥。 */
export interface ExternalHarnessDefinition {
  readonly id: string;
  readonly name: string;
  readonly transport: ExternalTransportKind;
  readonly command: string;
  /** 逐项字面参数数组（绝不经 shell 拼接）。 */
  readonly args: readonly string[];
  /** 可选显式 Flavor 键；缺省时 acp 驱动按命令名与握手 agentInfo.name 自动匹配。 */
  readonly flavor?: string;
  /** 若由官方 ACP Registry 模板创建，记录模板 id 以便展示安装/文档指引。 */
  readonly registryId?: string;
  /** 非敏感运行环境变量（如 CLAUDE_AGENT_ACP_EXPERIMENTAL_V2=0）；禁止控制字符。 */
  readonly env?: Readonly<Record<string, string>>;
  /** 从宿主环境按名转发的变量名白名单（如 DEEPSEEK_API_KEY）；只落盘名字，不落盘值。 */
  readonly envFrom?: readonly string[];
  readonly builtin?: boolean;
  readonly enabled: boolean;
}
```

**内置预设清单**（代码侧提供，不物化进 `harnesses.json`；默认按本机 `PATH` 与已知安装目录检测结果决定初始 `enabled`——未安装则默认 `enabled: false`；用户在设置页仅保存启停或路径/`envFrom` 覆写差量，支持一键恢复默认）：

| 预设 `id` | 显示名称 | `transport` | 默认 `command` + `args` | 认证与备注 |
|---|---|---|---|---|
| `claude-code` | Claude Code | `claude-cli` | `claude`（驱动内部固定拼接双向 `stream-json` 参数） | 复用 `claude auth login` 或转发 `ANTHROPIC_API_KEY` |
| `codex` | Codex | `codex-app-server` | `codex`（驱动内部启动 `app-server -c thread_unload_delay_secs=0`） | 复用 `codex login` 或转发 `OPENAI_API_KEY` |
| `pi` | Pi Coding Agent | `pi-rpc` | `pi`（驱动内部注入 `--mode rpc --no-approve --extension`） | 复用 `pi /login` 或转发模型 API Key |
| `antigravity` | Antigravity | `acp` (`antigravity`) | `agy` `["acp"]` | 复用 `agy acp --login`（推荐 `>= 1.5.1`，惰性按需调 `authenticate`） |
| `opencode` | OpenCode | `acp` (`opencode`) | `opencode` `["acp"]` | 复用 OpenCode 本地配置与登录态（已于 Windows 1.19.3 实测跑通） |
| `deepseek-harness` | DeepSeek Harness | `acp` (`dsh`) | `dsh` `["--profile", "acp"]` | 复用 DSH 凭据库或 `envFrom: ["DEEPSEEK_API_KEY"]`（已于 0.2.0-rc.2 实测） |

| `omp` | Oh My Pi (OMP) | `acp` (`omp`) | `omp` `["acp"]`（默认 `PI_NO_PTY=1`） | 复用 `omp /login` 或转发模型 API Key |
| `qoder` | Qoder | `acp` (`qoder`) | `qodercli` `["--acp"]` | 复用 `qodercli /login` |
| `qoder-cn` | Qoder CN | `acp` (`qoder-cn`) | `qoderclicn` `["--acp"]` | 复用 `qoderclicn /login`（已于 Windows 1.1.98 实测跑通） |
| `trae` | TRAE | `acp` (`trae`) | `traecli` `["acp", "serve"]` | 复用 `traecli login`（国际版） |
| `trae-cn` | TRAE CN | `acp` (`trae-cn`) | `traecli` `["acp", "serve"]` | 复用 `traecli login`（国内版） |

### 3.2 统一驱动接口（`ExternalHarnessDriver`）与三套协议映射

```ts
/** 协议无关的外部会话驱动接口；任何底层协议帧不得越过此边界进入 Service 或 UI。 */
export interface ExternalHarnessDriver {
  readonly transport: ExternalTransportKind;
  inspect(
    def: ExternalHarnessDefinition,
    cwd: string,
    signal: AbortSignal,
  ): Promise<{
    available: boolean;
    agentName?: string;
    version?: string;
    loadSupported: boolean;
    status:
      | 'ready'
      | 'auth_unverified'
      | 'needs_login'
      | 'not_installed'
      | 'invalid_shim'
      | 'handshake_failed';
    reason?: string;
    loginHint?: string;
    installHint?: string;
  }>;
  open(input: {
    def: ExternalHarnessDefinition;
    workspaceRoot: string;
    nativeSessionId?: string;
    signal: AbortSignal;
  }): Promise<{
    handle: ExternalDriverSessionHandle;
    nativeSessionId?: string;
    resumable: boolean;
    modelLabel?: string;
    modeLabel?: string;
  }>;
}
```

| 统一职责 | `acp-stdio` 驱动 | `claude-cli` 驱动 | `codex-app-server` 驱动 |
|---|---|---|---|

| **工具与计划** | `tool_call` / `tool_call_update` 按 `toolCallId` upsert；`plan`（`entries \| plan` 双读）映射 `ViewTodoState` | `assistant(tool_use)` 建卡，`user(tool_result)` 结卡；识别 `TodoWrite` 工具入参映射 `ViewTodoState` | `item/started` 建卡，`item/completed`（`commandExecution` / `fileChange` / `mcpToolCall`）结卡；`turn/plan/updated` 映射 `ViewTodoState` |

## 4. 进程安全、Windows 兼容与容错不变量

### 4.1 可执行解析与 Windows `.cmd` 三形态静态解包（`external/process.ts`）

1. **禁止相对路径与禁止 Shell**：
   - 包含 `/` 或 `\` 但非绝对路径（`~/` 展开后）的 `command` 直接拒绝，防止执行工作区仓库内的同名恶意脚本；
   - 全程固定 `shell: false, windowsHide: true`，`args` 永远以字符串数组直传系统调用。
2. **GUI 受限 `PATH` 兜底目录表**：
   - 裸命令名先查显式 `PATH`，未命中时按平台只读扫描标准安装目录（Windows：`~/.local/bin`、`%APPDATA%\npm`、`%LOCALAPPDATA%\pnpm`、`%LOCALAPPDATA%\agy\bin`、`%LOCALAPPDATA%\Programs\OpenAI\Codex\bin`、`%LOCALAPPDATA%\qwen-code\bin`、`~/.bun/bin`、`~/.volta/bin`；POSIX：`~/.local/bin`、`/opt/homebrew/bin`、`/usr/local/bin`、`~/Library/pnpm`、`~/.local/share/pnpm`、`~/.bun/bin`、`~/.volta/bin`）。
   - Windows 同目录扩展名优先级固定为 **`[".exe", ".cmd"]`**（如 `codex.exe` 优先于 `codex.cmd` 直启）。
3. **Windows `.cmd` 垫片三形态静态解包**（已于本机 `opencode.cmd` 与 `dsh.cmd` 实测验证）：
   - 仅扫描包含 `%*` 的执行行（防 `npm 12+` 变量赋值行误匹配）；
   - 提取目标路径后经 `fs.realpathSync.native` 校验必须位于 `<shimDir>\node_modules\`（或本地 `.bin` 对应的受管 `node_modules\`）内部，拦截 `..\..\` 目录穿越；
   - **后缀与文件头分流**：
     - 目标为 `.exe`（如 `opencode-ai\bin\opencode.exe`）→ 直接 `spawn(targetExe, args, { shell: false })`；
     - 目标为 `.js` / `.mjs` / `.cjs`（如 `@deepseek-ai\dsh\lib\bin.js`）或无扩展名但首 256 字节匹配 `#!...node` shebang → 解析系统 `node.exe` 执行 `[targetScript, ...args]`；
     - 其余任意自定义 `.cmd` / `.bat` / `.ps1` → 拒绝执行并返回 `EXTERNAL_UNSUPPORTED_SHIM` 中文指引。
4. **启动环境白名单（`externalLaunchEnv`）**：
   - 严禁 `{ ...process.env }`；仅拷贝基础系统运行与网络代理白名单变量（绝不含 `NODE_OPTIONS`、`ELECTRON_RUN_AS_NODE` 或宿主内部其它厂商 API Key）；
   - 合并定义中的非敏感 `env`，最后按 `envFrom` 数组显式从父进程按名拷入用户指定的变量。

### 4.2 NDJSON 行通道、超时看门狗与两段式回收

- **分帧与非 JSON 容错**：Buffer 分段切行，单帧硬上限 **8 MiB**（超限报 `EXTERNAL_FRAME_LIMIT` 断开）；非 JSON stdout 行（CLI 启动横幅等）宽容忽略并记入脱敏诊断，但握手完成前累计超过 **64 KiB 或 100 行**非 JSON 输出立即熔断（防用户误填交互式 TUI 命令死等）；大帧让出事件循环时后续帧入同一串行队列防结算超车。
- **分层超时与休眠容忍**：
  - 设置页「检测连接」探针：**15s**；
  - 正式会话启动握手（`initialize` / `session/new` / `thread/start`）：**60s**；
  - 轮次执行无进展看门狗：**10 分钟静默上限**（收到实质流式/工具/计划事件即顺延，系统休眠唤醒容忍 10s 时钟跳变；处于 `waiting_approval` 等待用户点击审批期间暂停看门狗，交由审批单自身的 **120s** 到期拒绝计时器接管）。
- **两段式进程收口**（已于本机四路实测验证）：
  - 监听 `proc.once('close')` 而非 `'exit'`（防丢管道尾帧）；
  - 关闭时先调 `proc.stdin.end()` 给外部 CLI **1500ms** 优雅收尾窗口（保障 `agy` 清理 140MB 自解压临时目录及各 CLI 刷写状态）；超时未退立即升级 POSIX `-pgid` `SIGTERM → SIGKILL` / Windows `taskkill /pid <pid> /T /F`（挂 `error` 兜底 `proc.kill()`）。

## 5. 持久化：只读展示快照与权威恢复门禁解耦

所有外部代理状态均隔离在 `~/.kapibala/external/`（目录 `0700`、文件 `0600`），**零污染 Core 会话目录**：

1. **配置表 `~/.kapibala/external/harnesses.json`**：独占锁 + 重读 + 全量校验 + 原子替换；损坏时拒绝覆盖写入。
2. **会话登记簿 `~/.kapibala/external/sessions.json`**：上限 **50 条**（满额新增时自动淘汰最早已终态记录及其快照，全为活跃会话时拒绝新增），记录：
   ```ts
   export interface ExternalSessionRecord {
     readonly id: string;
     readonly harnessId: string;
     readonly harnessName: string;
     readonly transport: ExternalTransportKind;
     readonly workspaceRoot: string;
     /** sha256(transport, command, args, env, envFrom)；配置变更后禁止盲目原地续聊（对齐 Maka Continuity）。 */
     readonly configDigest: string;
     readonly title: string;
     readonly status: 'starting' | 'idle' | 'running' | 'waiting_approval' | 'cancelling' | 'ended' | 'failed';
     readonly nativeSessionId?: string;
     readonly resumable: boolean;
     readonly modelLabel?: string;
     readonly modeLabel?: string;
     readonly createdAt: number;
     readonly updatedAt: number;
     readonly lastError?: string;
   }
   ```
3. **有界只读展示快照 `~/.kapibala/external/snapshots/<sha256(id)>.json`**：
   - 仅在每轮 settle 与会话关闭时串行原子写盘（流式中间态不写盘；空消息列表绝不覆盖已有快照）；
   - 单会话硬上限 **160 条 `ViewMessage` / 680 KiB**（确保包裹协议帧后恒低于桌面 IPC 与本地 Wire 1 MiB 单帧上限；超限裁剪最旧消息并标记 `truncated: true`），落盘前统一经 `redactText` 脱敏并剥离非文本二进制载荷；
   - **恢复与查看双轨行为**：
     - 当进程因 **30 分钟空闲回收**或客户端重启后，用户点开任意外部历史会话，宿主立即从 `snapshots/` 加载历史消息展示，**绝不出现空白页**；
     - 仅当 `resumable === true` 且当前 `configDigest` 与工作区根未变时，允许用户在输入框发送新轮次（自动拉起子进程走 `session/load`、`--resume` 或 `thread/resume`）；否则会话固定为只读终态，输入框置灰提示「当前为外部代理只读历史归档，如需继续请新建外部会话」。
4. **持久身份门禁（`resumable` 判定）**：必须同时满足 Native Session ID 跨重启稳定、具备稳定轮次边界、重放结果源自外部代理权威历史且不与实时快照冲突；未实测通过的自定义命令默认 `resumable: false`（仅保留只读展示快照）。

| 同工作区并发运行中外部会话上限 | **1**（第 2 个运行请求返回 `EXTERNAL_WORKSPACE_BUSY`，空闲态可并存；同仓多 Agent 并行由 v0.1.6 Git Worktree 解决） |
| 单会话并发活动轮次 | **1**（运行中拒绝并发 Prompt，不隐式排队） |
| 已登记外部会话保留上限 | **50**（满额新增时自动淘汰最早终态记录及快照，全为活跃态时抛 `EXTERNAL_CAPACITY`） |
| 空闲子进程自动回收时间 | **30 分钟**（无在途轮次与待审批时优雅关闭子进程，保留登记与只读快照） |
| 单帧字节上限 / 单会话只读快照上限 | **8 MiB** / **160 条消息且 ≤ 680 KiB** |
| 项目信任前置 | 未通过 `isProjectTrusted` 的工作区在宿主层硬拒全部 `external/*` 会话与探测调用 |
| 跨信任域审批隔离 | 本地 `Auto` / `FullAccess` 绝不自动批准外部审批；超时/断连一律按拒绝/取消处理 |
