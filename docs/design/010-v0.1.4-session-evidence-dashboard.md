## 0. 一句话定义与会话内呈现

会话看板 = **把一个会话「做了什么、依据什么」聚合成一个可折叠的证据面板**：
头部常驻一行摘要（`变更 +N −M · 引用 K 条 · MCP 调用 J 次 · 委派 2 个运行中`），
点开是四个分区，随会话推进逐项追加，终态定格。

对标（**已核实**，维护者提供的 Trae 截图）：头部「变更 +4,760 −460」+「来源」分组清单
（URL 抓取 / MCP 服务器 / 查看全部）。对标结论只取「信息架构」，交互与视觉是我们的选择。

## 1. 数据通道现状（逐条核实）

| 证据面 | 现有通道 | 缺口 |
|---|---|---|
| 引用来源 | v0.1.3 `referenceSource` 随 user 消息落盘（源会话 / recordId / 角色 / 时间戳）；`SessionReferenceReader` 只读不取锁 | 只差聚合投影：按会话枚举所有带引用的消息，无需新事件 |
| MCP 调用 | `ViewTool.name` 保留 `mcp__<server>__<tool>` 原始 id；`ViewTool.status / durationMs / resultMessageId` 已有 | 只差聚合投影：按 `mcp__` 前缀分组计数 |
| 委派任务 | detached 委派头 `header.delegation`（含 requestId 幂等三元组）、`/delegations` 面板、AgentRuntime 任务快照 | 只差把「父会话视角」的委派聚合进看板（现有面板是全局列表） |
| 变更行数 | `ViewTool` 有 write_file / edit_file 的调用事实与结果，但**没有行数语义**（edit 结果只有「替换 N 字符」） | **需要新增聚合通道**，见 §2 |
| 任务进度 / 步骤 | `ViewTool` 逐工具状态流；U1.8 分组汇总（`summary(count)` / `repeated(count, failed)`）已定契约、随工具行增强组顺延本版 | 步骤进度 = U1.8 的看板消费方；终态定格靠既有 status |
| 委派 / 后台进度 | `AgentTaskStatus` 状态机 + outbox 终态通知（`run-N` revision） | 只差投影层把通知流转成看板时间线 |

结论：**四个分区里三个只差聚合投影，真正的新数据通道只有「变更行数」**。

## 2. 变更行数的最小方案（自定决策）

在宿主层聚合，不动 Core 工具协议：

- **只统计成功工具**：status 非 `completed` 的 write/edit 不计；同一文件多次编辑按调用逐次累加。
- `write_file`：目标原不存在 → `+总行数`、`−0`；覆盖已有文件 → 新旧文本做行差（先结构化 diff，退化 LCS）得出 `+N −M`；
- `edit_file`：入参 `targetContent` / `replacementContent` **先走结构化 diff**（有行级上下文时可直接定位替换段），拿不到结构化信息时退化为 LCS 行差；不使用「字符数折算行数」这种近似；
- 单文件参与计算的文本上限 200k 字符，超出按「整段替换」近似并标记 `approximate: true`，面板对近似值加注；
- `run_command` 等间接改动**不计数**（无法可靠归因），面板注明「不含命令行间接改动」；
- 汇总按会话持久在内存投影 + 随会话重建（历史投影时从已落盘工具块重算），不新增落盘记录类型。

为什么不走 git diff：工作区 diff 无法区分「本会话的改动」与用户手工改动，v1 宁可口径保守。

## 4. 分区信息架构（我们自定的选择）

1. **变更**：`+N −M` 总数 + 按文件折叠的明细（工具调用即来源，点击进既有详情抽屉）；
2. **引用来源**：源会话名 · recordId · 角色与时间戳，点击跳引用块原文；
3. **MCP 调用**：按服务器分组计数（「yapi-mcp-server · 5 次，1 次失败」），失败态取自 `ViewTool.status`，不做结果正文解析；复用 U1.8 契约；
4. **委派任务**：运行中在前（状态机实时），终态定格（summary 摘要）；父会话 `run_finished` 时仍在运行的子任务标记「已结束（父会话收尾）」而不是假装完成，操作入口与 `/delegations` 同口径。

## 5. 明确不做（v0.1.4）

- 不做跨会话聚合看板（单会话内闭包）；
- 不计入 run_command 间接改动、不做 token 费用统计；
- 不接入 webhook / CI 状态源（与 008 的边界一致）；
- 不新增落盘记录类型，历史重建全部从既有记录重算。
