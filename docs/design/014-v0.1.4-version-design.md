### 2.2 wire 1.1 兼容策略（关键决策）

v0.1.4 是**一次 minor 升级**，不是四次：

1. **新增方法**：`watch/list`、`watch/cancel`、`evidence/read`、`resources.inspectSkills`、
   `resources.importSkills`。MCP 配置写与管理走既有宿主 / 桌面 IPC 面，不新增 wire 方法。
2. **新增能力**：`watch`、`evidence`、`skill-import`。客户端在 `initialize` 中声明本次依赖的能力，
   服务端不支持即握手失败；不静默降级。
3. **新增字段**：`ViewTool.artifacts?`、会话级 `todos`（`ViewTodoState`）、`evidence/read` 结果。
   桌面 `PresentationStateSchema` 与 preload 契约同步更新；不做「旧客户端忽略字段」的假设。
4. **同版配对**：服务端 minor 升 1.1 后，仍声明 `maxMinor:0` 的旧客户端会在握手阶段得到
   `PROTOCOL_MISMATCH`（`local-client.ts:30-38` 的显式校验），不会读到半套字段。CLI 客户端
   在同一版本内把 offer 升到 `maxMinor:1`；外部本地 wire 消费者需随 v0.1.4 升级。
5. **契约快照**：M0 一次性更新 `types.ts` / `schema.ts` / `results.ts` / `version.ts` /
   `scripts/fixtures/protocol/v1.1/contract.json`，人工执行 `--update` 并评审；`docs/local-protocol.md`
   同步版本段落。`pnpm check-protocol-contract` 不允许在主题 PR 中反复 `--update`。

为什么是 minor 而不是 major：帧格式、错误码语义、连接恢复单位与既有方法行为不变，新增的是
方法、能力与可选字段；这与 007 §0.6 的既有裁决一致。代价是旧客户端必须升级才能连接——本版接受，
并在发布说明中写明。

### 2.3 落盘与不变量

- **唯一新增控制记录**：`watch_state`。必须五处同步（`SessionRecordType`、`SessionStore` 类型集合、
  `isGlobalControlRecordType`、`SessionManager.buildMetadata`、`CrossProjectSessionCatalog` 内联扫描），
  漏一处即静默丢状态。`parentId` 为 `null`，不推进上下文叶子、不改活动时间。
- **其余主题零新记录类型**：010 / 012 / 013 全部从既有历史重算；013 只增补一条压缩保护规则。
- **压缩保护**：包含最近一次成功 `todo_write` 的交互并入 `protectedMessageIds`；不新增 `todo_state`。
- **历史闭合**：监视与导入触发的背景消息仍经 `MessageStore.append` 消息级落盘；
  assistant `tool_use` 与 `tool_result` 的闭合规则不变。

## 3. 开源对标与裁决

### 3.1 会话监视（008）

| 证据 | 结论 | 采纳 |
|---|---|---|
| Claude-Code `LocalShellTask.tsx:106-117`：`notified` 闩锁原子检查后才投递终态通知 | 幂等必须落在存储/状态上，不能只在调度器内存里 | **采纳**：`watch_state` 的 `fired/timeout/cancelled` 终态即投递闩锁 |
| Claude-Code `messageQueueManager.ts:49`：系统通知默认最低优先级（`now > next > later`） | 系统事件不得饿死用户输入 | **采纳**：背景消息固定 `later` 优先级，空闲边界抽取 |
| opencode `session/inbox.ts:176`：首占先得、投递后删除；`run-coordinator.ts:33-43,77-78`：忙碌期唤醒坍缩为一次 | 待投递队列 + 合并窗口比「只限流」更不易丢事件 | **采纳**：`WatchInbox` 复用 pending-only 语义；合并窗口默认 2s，冷却 60s 仍为硬上限 |
| pi `file-trigger.ts:18,28`：`fs.watch` → `sendMessage(..., { triggerTurn: true })` | 外部事件注入 + 续跑的最小闭环 | **采纳**为形态参照；不引入 pi 的扩展机制 |
| codex `file-watcher/src/lib.rs:256`：固定去抖窗口合并文件事件 | `file_change` 必须去抖，否则编辑器保存风暴会刷屏 | **采纳**：去抖 300ms、路径排序去重、监听上限 64（每会话仍限 8） |
| codex `sleep.rs` / `wait_for_environment.rs`：轮询阻塞式等待 | 与我们的「无执行体、跨重启」不同 | **不采纳**；只在文档中说明分界 |
| 全仓无 `port_ready` 先例 | `port_ready` 是自定语义 | **自定**：仅 `127.0.0.1` TCP connect；探测退避从 500ms 起、上限 5s；探测时长计入 deadline |
| 全仓无「错过 deadline / 重启后进程句柄失效」的统一先例 | 必须显式建模，不能静默丢弃 | **自定**：到期投递 `timeout`；重启后 `process_exit` 标记 `orphaned` 并投递一次说明 |

裁决：008 的 §7 补充「投递闩锁 + 合并窗口 + 去抖」；`WatchNotification` 增加可选 `detail`
（`process_exit` 带退出码，`file_change` 带摘要），结构化标签仍由宿主生成。v1 不实现
「本会话自写忽略」机制；在风险表中注明「对 agent 自己写入的路径登记监视可能自触发」，
由使用侧避免。

- 保留五态术语与 `deadlineAt` 必填；`watch_state` 五处同步为 W0 验收硬条件。
- 投递：终态闩锁、空闲边界、pending 队列、合并窗口、60s 冷却、每分钟最多 1 次续跑。
- `process_exit` 只认本会话子进程；重启后 `orphaned` 必须投递说明；`port_ready` 仅本机 TCP。
- 明确限制：对 agent 自己写入的路径登记监视可能自触发，v1 不做自写识别。
- 验收补充：合并窗口不丢最后一个事件；重复事件零重复落盘；风暴下最多 1 次/分钟续跑。

### 5.2 009 技能导入

- 导入是 mutation：预览 → 校验 → 临时目录 → 原子 rename → 溯源；默认跳过冲突，覆盖先备份。
- 批量三桶 `imported / skipped / failed`，单条失败不中断；每源 128 候选、单技能 128 KiB。
- frontmatter 归一为自定白名单；剥离字段在预览、汇总、溯源文件三处可见。
- 删除 `harp`；CodeWhale / PI-Desktop / ZCode 行号按 §3.3 更正；wire 随 1.1。
- 验收补充：symlink 越界、同名冲突、同摘要 unchanged、原子失败回滚、未信任项目拒绝。

### 5.3 010 会话看板

- 四分区 + 头部摘要；变更行数 diff-first + LCS 兜底；`run_command` 不计。
- MCP 分组按原始名，解析失败进「未知服务器」；失败与跳过分列。
- 委派运行中实时、终态定格；操作入口与 `/delegations` 同口径。
- `evidence/read` 走 wire 1.1；桌面面板与 CLI `/evidence` 同口径。
- 验收补充：历史重放与实时投影一致；长会话聚合不阻塞输入。

### 5.4 011 MCP 管理与更新

- 全局写复用 `mutateGlobalMcpConfig`；项目级新增镜像事务并强制项目信任；桌面在既有区块上增补。
- 导入支持 claude-desktop / claude-code / cursor；`sse` → `http` 显式告警；秘密只显示键名。
- 更新：`releases/latest` + 资产矩阵 + `.part` 下载 + `SHA256SUMS.txt` 同名摘要一致才打开；
  缺失摘要拒绝；离线静默降级为「未知」。
- 版本号读取用 `app.getVersion()` / 包清单；删除 `readWorkspaceVersion` 运行期引用。
- 验收补充：未签名三平台「检查 → 下载 → 手动安装」；macOS 右键 / xattr 文案随 U1.1 定稿。

### 5.5 012 产物预览

- v1 只认 `write_file` 成功终态的 png/jpg/jpeg/gif/webp；SVG、edit_file、run_command、MCP 不投影。
- 宿主 realpath + 存在性 + 8 MiB 预检；渲染侧按 base64 长度复算。
- 自动弹消费键 `(workspaceKey, toolCallId)`；历史 / superseded / 已关闭短路；chip 内容键去重。
- 验收补充：自动弹一次且仅一次；失败终态零投影；超限降级为文件名。

### 5.6 013 任务面板

- `todo_write` 全量替换、1–50 条、title ≤200、id 唯一；**允许多个 `in_progress`**，UI 主项 + `+N`。
- 重算锚点为最近一次成功调用的 tool_use 入参；压缩保护整个交互；不新增 `todo_state`。
- pill 只在有清单时显示；浮层只读、键盘可达、Esc 关闭；底栏空间名优先、无空间回退「本地」。
- `/todos` 与桌面同口径；子代理会话独立注册、父会话只投影自己的分支。

## 7. 风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| wire 1.1 旧客户端连新宿主 | 握手失败或误读快照 | 同版配对策略写入协议文档；CLI offer 同步；兼容用例覆盖旧 offer 0 |
| 六主题共享文件并行改写 | 合并冲突、口径漂移 | §4.7 顺序 + 共享文件单一负责人；每主题独立 verify |
| `watch_state` 漏同步 | sidecar 重建丢监视 | W0 五处断言 + 重建用例；代码评审清单 |
| 监视风暴 / 自触发 | 上下文膨胀、重复续跑 | 去抖 + 合并 + 60s 冷却；文档标注自写限制 |
| 重启后进程句柄失效 | 监视永久挂起 | `orphaned` 投递 + 关闭；启动扫描 |
| `todo_write` 压缩后清单丢失 | pill / 浮层错乱 | 保护最近成功交互；重放用例覆盖压缩前后 |
| 看板长会话重算 | 输入卡顿 | 纯函数 + 增量缓存；渲染层 memo；必要时按会话懒加载 |
| 跨 Harness 导入提示注入 | 技能内容不可信 | 预览正文；权限只收紧；未知 `allowed-tools` 丢弃 |
| 项目级 MCP 写入 | 改动随仓库分发 | 仅信任项目；预览与差异确认；不自动同步 |
| 未签名更新被替换 | 供应链风险 | https + 固定资产名 + `SHA256SUMS.txt` 摘要一致才打开；缺失拒绝 |
| 新增 UI 选择器漂移 | e2e 30s 超时 | `aria-label` / 文案与 e2e 同 PR 更新 |
| 版本设计口径与主题文档漂移 | 实现按旧稿走 | 014 为版本级唯一裁决；冲突以 §0 / §8 为准 |

## 8. 终审裁决与开放项

### 8.1 继承已定口径（不重新征询）

- 六主题全量纳入，不设必达 / 弹性分档；不可控风险只顺延单个主题到 v0.1.5。
- 008：自动续跑默认开启；失焦系统通知 / 前台徽标；v1 不允许绑定父会话。
- 009：导入界面打开时才扫描；全部导入默认全局；导入后默认启用；不做兼容根长期读取。
- 010：接受「变更行数不含 `run_command` 间接改动」。
- 011：未签名三平台「检查 → 下载 → 手动安装」；不走签名链路。
- 012：v1 只认 `write_file` 成功终态的图片；SVG 不投影；自动弹不加设置开关。
- 013：pill 仅有清单时显示；底栏空间名优先；`todo_write` 在子代理会话注册；分母为全部条目。
- 010 / 012 / 013 不落新记录类型；仅 008 新增 `watch_state`。

### 8.2 本轮建议默认值（随版本设计一并确认）

| 项 | 建议默认值 | 理由 |
|---|---|---|
| `todo_write` 的 `in_progress` 数量 | **允许 0..N**，UI 主项 + `+N`；不硬拒绝、不自动降级 | ZCode 硬拒绝导致后续调度组跳过；oh-my-pi 自动降级会静默改写模型意图 |
| MCP 项目级写入 | **允许，但仅限已信任项目**；桌面在既有区块上开放编辑 | 延续全量交付；项目配置随仓库分发，信任门禁与 009 项目导入一致 |
| wire 兼容 | **同版配对**；旧客户端握手失败，不做字段级降级 | 桌面 `.strict()` 与 minor 协商已决定；避免半套字段 |
| 更新包摘要 | **缺失即拒绝**，不跳过 | 未签名安装包没有第二道防线 |
| 010 变更行数 | **结构化 diff 优先 + LCS 兜底** | 与 ZCode / opencode 一致；比字面行数差准确 |
| 008 风暴抑制 | **合并窗口 2s + 60s 冷却 + 每分钟 1 次续跑硬上限** | 既不丢事件，也不刷屏 |
| 012 自动弹 | **消费键 `(workspaceKey, toolCallId)`**，跨卸载存活 | ZCode 唯一验证过的「只弹一次」实现 |
| 009 字段剥离 | **自定白名单**，不声称对标 | 开源实现无先例 |
| `todo_write` 的 `id` | **必填且唯一**，宿主不改写输入 | 保持模型声明与展示一致 |
| 010 看板通道 | **`evidence/read` 方法**，不在快照里塞全量证据 | 与 012 / 013 的快照字段分开，避免快照膨胀 |

## 9. 错误码与术语

### 9.1 错误码命名空间

| 前缀 | 主题 | 示例 |
|---|---|---|
| `WATCH_*` | 008 | `WATCH_LIMIT_REACHED`、`WATCH_TARGET_INVALID`、`WATCH_NOT_FOUND` |
| `SKILL_IMPORT_*` | 009 | `SKILL_IMPORT_SOURCE_UNREADABLE`、`SKILL_IMPORT_CONFLICT`、`SKILL_IMPORT_TOO_LARGE` |
| `EVIDENCE_*` | 010 | `EVIDENCE_UNSUPPORTED`（读取失败不阻断会话） |
| `MCP_*` | 011 | 既有 `MCP_CONFIG_BUSY` / `MCP_CONFIG_INVALID`；新增 `MCP_IMPORT_*` |
| `TODO_*` | 013 | `TODO_INVALID`（条数 / 标题 / id 校验） |

### 9.2 术语

- **监视**（watch）：状态固定「监视中 / 已触发 / 已超时 / 已取消 / 已失联」；不叫「定时任务」
  或「后台任务」。
- **任务清单**（todo）：模型声明、宿主重算、两端只读；不叫「待办事项管理」。
- **会话看板**：四分区证据聚合；CLI 命令 `/evidence`，不叫「统计面板」。
- **产物预览**：图片自动预览与 chip 重开；单 dock 单内容。
- **显式导入**：一次性拷贝 + 溯源；不叫「兼容读取」或「同步」。
