### 0.3 证据等级

本轮新增一条硬约束：设计与验收只接受可指到源码的证据。

| 等级 | 含义 | 处置 |
|---|---|---|

| **B 侦察核实** | 侦察员打开源码确认，版本设计未逐行复核 | 可作为依据；实现时复核 |

### 0.4 本轮实质变更（相对 008–013 初稿）

1. **wire 改为整数版本 + 能力集合**：撤回「升 minor 1.1 / 同版配对」的旧方案，改用
   `PROTOCOL_VERSION = 2`（整数）+ `capabilities: string[]`（对齐 opencode `protocol.rs` 的
   整数版本与 CodeWhale `InitializeCapabilities`）。破坏性变更才 +1，新增能力走 cap 字符串；
   旧 `{major:1,minor:0}` 客户端握手即明确失败，不承诺字段级降级。
2. **009 证据更正**：`harp` 仓不存在，删除引用；CodeWhale 的溯源标记是 `.installed-from`，
   我们的 `.imported-from.json` 属自定格式；「剥离 frontmatter 字段」在开源实现中无先例，
   明确标注为**自定决策**。
3. **010 证据更正**：ZCode side pane 路径更正为 `packages/ui/src/hooks/useAppPanels.ts`，
   tab 种类为 26 种；maka 没有「资源面板」，对应物是 Workbar 的 `files`（Artifact Pane）。
4. **011 基线更正**：`mutateGlobalMcpConfig` 与桌面 MCP 区块（全局增删改/启停、项目级只读）
   已存在，M0.1 / M1.1 改为增量交付，不重复建一套；桌面版本号读取用 `app.getVersion()`，
   不是运行期导入发布脚本的 `readWorkspaceVersion`。
5. **013 校验调整**：`todo_write` 允许 0..N 个 `in_progress`，撤回「至多一个」硬拒绝；
   依据是 ZCode 的显式教训（硬拒绝会让后续调度组被跳过）与 oh-my-pi 的自动降级实现。
   pill 显示首个进行中项，多个时追加 `+N`。
6. **008 投递判定改水位**：`watch_state` 存 `lastSeenAt` / `lastNotifiedAt`，**不存 `delivered`
   布尔值**（对齐 jcode `catchup.rs`）；恢复时按时间水位补投**一条简报**而非重放历史；只有持
   会话写租约的宿主恢复 watcher 并投递（复用 `WorkspaceLeaseCoordinator`），避免 CLI 与桌面
   双投。`file_change` 保留去抖窗口、路径去重与监听上限；`process_exit` 通知带退出码摘要；
   「每分钟最多 1 次自动续跑」仍为硬上限，风暴抑制以合并为主。
7. **010 只读持久化事实**：在 `ToolResultBlock.execution.facts` 写入结构化 `diff`（工具执行
   时生成，canonical 落盘、不上 Provider wire），看板只读已持久化事实；缺失显示「未记录」，
   **删除 LCS 兜底**（对齐 opencode `vcs/patch.ts` 的「行数是数、不是算」）；单文件超 10 MB
   只记 `truncated`；`run_command` 间接改动仍不计入。
8. **012 自动弹一次性契约**：自动打开以 `(workspaceKey, toolCallId)` 为消费键并跨卸载存活，

### 2.2 wire 协议版本升级（整数版本 + 能力集合，D1）

v0.1.4 一次性更换协议版本模型：**整数 `PROTOCOL_VERSION` + `capabilities: string[]`**，
取代 `{major, minor}` 与「minor 同版配对」。

1. **握手**：`initialize` 提交整数 `protocolVersion` 与客户端能力集合；服务端严格相等校验版本
   （不等即 `PROTOCOL_MISMATCH`，错误里带双方版本号），能力按交集启用。新增能力不再升版本号。
2. **版本取值**：`PROTOCOL_VERSION = 2`。取 2 而非 1，是因为握手形状本身不兼容 v0.1.3 的
   `{major:1,minor:0}`；整数只表达「破坏性代际」，不承载产品版本语义。
3. **新增能力**：`watch`、`evidence`、`skill-import`。MCP 配置写与管理走既有宿主 / 桌面 IPC 面，
   不新增 wire 方法；纯字段扩展（`ViewTool.artifacts`、会话 `todos`）不单列能力。
4. **新增方法**：`watch/list`、`watch/cancel`、`evidence/read`、`resources.inspectSkills`、
   `resources.importSkills`。
5. **兼容口径**：不承诺旧客户端可连。旧客户端（`{major:1,minor:0}` + `minMinor/maxMinor`）
   在握手阶段得到 `PROTOCOL_MISMATCH`，不会读到半套字段；外部本地 wire 消费者需随 v0.1.4 升级。
6. **能力缺失**：客户端声明依赖但服务端未提供的能力，握手失败并列出缺失项，不静默降级；
   客户端未声明使用的能力，服务端不推送对应事件。
7. **契约快照**：M0 一次性更新 `types.ts` / `schema.ts` / `results.ts` / `version.ts` /
   `scripts/fixtures/protocol/v2/contract.json`，人工执行 `--update` 并评审；`docs/local-protocol.md`
   同步握手段落。`pnpm check-protocol-contract` 不允许在主题 PR 中反复 `--update`。

为什么不再加 minor：本版一次落六个主题，若每次新增都要求两端严格同版，用户升级桌面端就被迫
同步升级 CLI。能力协商把「新增」摊平成 cap 字符串，只有破坏性变更才动整数——代价是旧客户端
必须升级才能连接（本版接受并在发布说明写明），收益是 v0.1.5 起的新增能力可以零版本号演进。
帧格式、错误码语义、连接恢复单位与既有方法行为均不变，因此不构成额外的大版本语义。

### 2.3 落盘与不变量

- **唯一新增控制记录**：`watch_state`。必须五处同步（`SessionRecordType`、`SessionStore` 类型集合、
  `isGlobalControlRecordType`、`SessionManager.buildMetadata`、`CrossProjectSessionCatalog` 内联扫描），
  漏一处即静默丢状态。`parentId` 为 `null`，不推进上下文叶子、不改活动时间；载荷存
  `lastSeenAt` / `lastNotifiedAt` 水位，不存 `delivered` 布尔值。
- **唯一新增 canonical 字段**：`ToolResultBlock.execution.facts`（`{ version: 1, diff? }`），
  由 `write_file` / `edit_file` 执行时写入；只落盘、不上 Provider wire，缺失即「未记录」。
- **其余主题零新记录类型**：010 / 012 / 013 全部从既有历史重算；013 只增补一条压缩保护规则。
- **压缩保护**：包含最近一次成功 `todo_write` 的交互并入 `protectedMessageIds`；不新增 `todo_state`。
- **历史闭合**：监视与导入触发的背景消息仍经 `MessageStore.append` 消息级落盘；
  assistant `tool_use` 与 `tool_result` 的闭合规则不变。

## 5. 七主题终审要点

### 5.1 008 会话监视

- 保留五态术语与 `deadlineAt` 必填；`watch_state` 五处同步为 W0 验收硬条件。
- 投递：`lastSeenAt` / `lastNotifiedAt` 水位、空闲边界、pending 队列、合并窗口、60s 冷却、
  每分钟最多 1 次续跑；**不存 `delivered` 布尔值**。
- 归属：只有持会话写租约的宿主恢复 watcher 并投递；其他宿主只读状态，不布置触发源。
- 补投：恢复时水位落后只发**一条简报**（最新用户提示 / 最近回复 / 触碰文件 / 工具计数 /
  `needs_from_user`），不重放历史。
- `process_exit` 只认本会话子进程；重启后 `orphaned` 必须投递说明；`port_ready` 仅本机 TCP。
- 明确限制：对 agent 自己写入的路径登记监视可能自触发，v1 不做自写识别。
- 验收补充：合并窗口不丢最后一个事件；重复事件零重复落盘；风暴下最多 1 次/分钟续跑；
  崩溃后恢复只补投一次简报，水位一致时零投递。

### 5.2 009 技能导入

- 导入是 mutation：预览 → 校验 → 临时目录 → 原子指针替换 → 溯源；默认跳过冲突，覆盖先备份。
- 隔离：不执行来源代码、不建工作树；按条目读取；`expectedSourceRef` 防预览后来源被替换。
- 批量五桶汇总，单条失败不中断；每来源 200 候选 / 64 MiB 总量、单文件 128 KiB。
- 溯源拆 `sourceRef`（来源身份）与 `installedDigest`（落地副本摘要），两者不可互换。
- frontmatter 归一为自定白名单；剥离字段在预览、汇总、溯源文件三处可见。
- 删除 `harp`；CodeWhale / PI-Desktop / ZCode 行号按 §3.3 更正；wire 随整数版本 + `skill-import`。
- 验收补充：symlink 越界、同名冲突、同摘要 unchanged、原子失败回滚、未信任项目拒绝、
  含可执行脚本的来源包导入后未被运行。

### 5.3 010 会话看板

- 四分区 + 头部摘要；变更行数只读持久化 `facts.diff`，缺失显示「未记录」，无 LCS 兜底；
  `run_command` 不计。
- MCP 分组按原始名，解析失败进「未知服务器」；失败与跳过分列。

- 重算锚点为最近一次**成功调用**的 tool_use 入参；委派并发写入加互斥；压缩保护整个交互；
  不新增 `todo_state`。
- pill 只在有清单时显示；浮层只读、键盘可达、Esc 关闭；底栏空间名优先、无空间回退「本地」。
- `/todos` 与桌面同口径；子代理会话独立注册、父会话只投影自己的分支。

### 5.7 016 权限模型

- 三档对外不变（`Approval / Auto / FullAccess`），内部按「沙箱边界 × 询问策略」组合；`SessionMode`
  与 `ShellCommandSafety` 词表均不改，wire 不新增取值。
- 分级按风险类别（`read / workspace-write / vcs-write / network / destructive / escape / unknown`），
  不再扩程序白名单；`unknown` 保持 fail-closed 询问。
- 目标：Auto 在 §2.1 的 27 条日常命令上从放行 8 条提升到 ≥17 条，且构建/测试/依赖的判定有明确依据。
- 硬禁区（`.git/hooks`、`.git/config`、`.env*`、`.kapibala/**`）由 PathSandbox 直接拒绝，
  **不产生审批请求**；shell 可识别的写入形态同样拦截；规则文件只能由宿主命令写，工具写入必败。
- 审批记忆三级（session / project / global）+ `maxClass` 风险上限，禁止前缀规则跨类别继承。
- 验收补充：27 条回归表、硬禁区三档全拒、规则自我提权失败、`pnpm:*` 规则对 `pnpm publish` 不生效。
- 以上随 2026-11-21 专项评审通过解除前置；P0 未合入前，Release 仍不得声称权限重做已完成。

### 8.2 本轮拍板默认值（2026-11-20 已确认）

| 项 | 建议默认值 | 理由 |
|---|---|---|
| `todo_write` 的 `in_progress` 数量 | **允许 0..N**，UI 主项 + `+N`；不硬拒绝、不自动降级 | ZCode 硬拒绝导致后续调度组跳过；oh-my-pi 自动降级会静默改写模型意图 |
| MCP 项目级写入 | **允许，但仅限已信任项目**；桌面在既有区块上开放编辑 | 延续全量交付；项目配置随仓库分发，信任门禁与 009 项目导入一致 |
| MCP 服务器批准 | **逐服务器批准 + 配置摘要**；任何配置变化重新待批，未批准不自动启动 | 项目信任回答「代码可跑」，不覆盖「常驻联网进程」；无活跃仓先例，按爆炸半径自定 |
| wire 兼容 | **整数 `PROTOCOL_VERSION = 2` + 能力集合**；版本严格相等，能力按交集；旧客户端握手失败 | 新增能力走 cap 字符串，避免每次升级都要求两端同版；破坏性变更才 +1 |
| 更新包摘要 | **缺失即拒绝**；摘要只证明完整性，不证明来源；未签名显式声明 | 未签名安装包没有第二道防线；不得宣称防替换 |
| 010 变更行数 | **只读持久化 `facts.diff`**；缺失显示「未记录」，无 LCS 兜底 | 行数是数不是算；注入式重算会与历史投影漂移 |
| 008 补投 | **`lastSeenAt` / `lastNotifiedAt` 水位 + 恢复一条简报**；仅持锁宿主投递 | 布尔「已投递」无法表达错过多次；多宿主必须归属单一 |
| 009 导入隔离 | **不执行 / 不建工作树 / 临时目录 + 原子指针**；`sourceRef` 与 `installedDigest` 分离 | 导入过程的安全面比字段白名单更根本 |
| 012 预览边界 | **固定允许根，整根排除 `~/.kapibala`**；拒绝码 `path_not_allowed` / `file_not_found` | 数据根含凭据，不能整体授权；先判边界避免存在性预言机 |
| 013 任务状态 | **四态含 `cancelled`；读最近一次成功调用；写入互斥** | 撤销与未开始是两件事；委派并发下全量数组会 lost update |
| 008 风暴抑制 | **合并窗口 2s + 60s 冷却 + 每分钟 1 次续跑硬上限** | 既不丢事件，也不刷屏 |
| 012 自动弹 | **消费键 `(workspaceKey, toolCallId)`**，跨卸载存活 | ZCode 唯一验证过的「只弹一次」实现 |
| 009 字段剥离 | **自定白名单**，不声称对标 | 开源实现无先例 |
| `todo_write` 的 `id` | **必填且唯一**，宿主不改写输入 | 保持模型声明与展示一致 |
| 010 看板通道 | **`evidence/read` 方法**，不在快照里塞全量证据 | 与 012 / 013 的快照字段分开，避免快照膨胀 |
| 016 边界实现 | **轻围栏**：硬禁区硬拒 + 可识别网络程序必问 + cwd 限制；不做 OS 沙箱 | 维护者选定；跨平台三套内核实现不在本版成本内 |

## 9. 错误码与术语

### 9.1 错误码命名空间

### 9.2 术语

- **监视**（watch）：状态固定「监视中 / 已触发 / 已超时 / 已取消 / 已失联」；不叫「定时任务」
  或「后台任务」。
- **任务清单**（todo）：模型声明、宿主重算、两端只读；不叫「待办事项管理」。
- **会话看板**：四分区证据聚合；CLI 命令 `/evidence`，不叫「统计面板」。
- **产物预览**：图片自动预览与 chip 重开；单 dock 单内容。
- **两轴**（016）：沙箱边界 × 询问策略；三档是两者的预设组合，不叫「权限等级」。
- **硬禁区**（016）：即使完全访问也不可写的路径，直接拒绝且不产生审批请求；不叫「敏感目录提醒」。
- **显式导入**：一次性拷贝 + 溯源；不叫「兼容读取」或「同步」。
