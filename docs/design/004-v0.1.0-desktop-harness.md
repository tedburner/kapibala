## 1. 交付目标与边界

用户安装 Kapibala 后，不必另外安装 Node.js 或 `kpbl`，即可使用默认空间（应用自有目录，默认可信、无需确认），或选择项目目录建立项目空间，确认信任、配置模型后在桌面窗口中使用现有 Agent 工具循环。CLI 与桌面端读取同一套模型配置和历史记录，但各自仍是独立宿主。

首版面向 Windows、macOS、Linux，采用单应用实例、单主窗口、多工作区、多会话。界面以简体中文为主，默认白底，支持深色和跟随系统；常态只有空间与会话侧栏、对话主体两栏，工具详情默认关闭，按需在右侧打开，不把代码编辑器或状态面板作为主视图。

核心验收路径是：使用默认空间（默认可信）或选择项目目录并确认信任 → 配置模型 → 发起任务 → 查看工具 → 审批或拒绝 → 取消并等待清理 → 显式继续。默认空间免去目录选择与重复确认，权限检查不变；项目空间仍须显式信任，恢复已有历史也必须走相同的权限与执行边界。

### 1.1 必须保留的 Harness 约束

- `AgentSession` 是唯一会话执行入口，Core 保持 Headless、零外部运行时依赖，不导入 Electron、React 或 CLI。
- 每个会话显式传入规范化的 `workspaceRoot` 和 `executionCwd`，路径身份使用 `fs.realpathSync.native`。不通过修改进程 cwd 切换项目。
- 原始历史仍是唯一耐久事实。user、assistant、tool_result 消息按既有规则落盘，工具事务必须闭合。
- 取消请求、模型或工具终态、清理完成分别展示。清理失败时不得释放执行门并宣称已停止。
- 一次恢复不会自动重放工具、重发用户消息、恢复审批缓存或沿用 `FullAccess`。
- Skill、MCP、子代理与内置工具仍由现有权限系统裁决。桌面桥接不能增加绕过 Core 的执行入口。

### 1.2 本版不做

完整 IDE、Monaco 编辑器、文件编辑工作台、交互式 PTY 终端、Git Worktree、可视化多代理编排、子代理审批冒泡、任务树分层 Token 账本、空闲自动收集、云同步、远程守护服务、插件市场、自动更新、全局快捷键小窗和拖拽附件输入均不进入 v0.1.0。

既有 CLI 的全屏 TUI、鼠标展开与缓存友好压缩专项也不因桌面开发自动纳入。首版不承诺 CLI 的全部 Slash 命令都有图形入口，输入框中的文本不交给 CLI 命令解释器执行。

D06 不根据 `write_file`、`edit_file` 的名称推测文件一定变更成功，不生成未经工具结果证明的 Diff，不在 Markdown 中自动执行代码或打开本地文件。

### 2.1 空间与会话归属

界面统一称“空间”，对应执行层的一个工作区物理根，不增加脱离目录的虚拟项目层。默认空间固定置顶；用户选择项目目录后建立项目空间，同一规范化根只显示一个空间。空间下列出会话，点击空间只切换列表，打开会话才申请运行时句柄。新建会话归当前选中的空间，首次没有选择时归默认空间；已选项目失效时提示处理，不静默改到默认空间执行。

| 空间 | 工作目录与用途 | 会话归属 |
|---|---|---|
| 默认空间 | `<homeDirectory>/.kapibala/workspaces/default`，用于未绑定项目的对话和任务；普通用户界面显示为 `~/.kapibala/workspaces/default` | 所有未绑定项目的新会话共用一个物理根和历史桶，不按会话自动建目录 |
| 项目空间 | 用户经原生选择器选择目录，由既有检测确定最终项目根，再显示并确认信任 | 同一项目根聚合已有 CLI 与桌面历史，不复制到桌面数据库 |

默认目录由 Host 在通过启动恢复检查后、首次进入默认空间时按需创建，路径由显式 homeDirectory 推导，Renderer 不能提交替代路径。它只作为工作产物目录，不把整个 home 或 `.kapibala` 作为执行根；历史仍存放在既有 `<homeDirectory>/.kapibala/sessions/<projectKey>`，共享设置和凭证保持原位置。默认空间中的会话共享文件，互相可见，不宣称会话级文件系统隔离，同目录写操作仍经过共享租约。

添加项目使用两步对话框：先填写项目名称、查看只读设备“此电脑”、原生选择源文件夹，再点击“创建项目”；未信任时叠加“信任此文件夹吗？”确认框，展示最终物理根与权限范围。取消信任返回已填写表单。选择目录不保存最近项目或创建会话；确认后 `workspace.addProject` 在 Host 校验名称、根身份与信任 token，显式同意才登记信任。项目名称仅为 1–80 字符的客户端别名，不重命名目录、不改变 projectKey；Main 按物理根保存并恢复别名，同根复用最近入口。旧信任被外部撤销时必须重新确认，不凭 UI 缓存自动恢复。首版仅本机目录，不提供远程设备选择。

默认根创建后用 native realpath 登记，约定路径以规范化后的 `.kapibala` 为基准。若 `workspaces` 或 `default` 被符号链接或目录联接重定向到约定位置之外，拒绝将其注册为默认空间；不自动接管外部项目。目录被文件占用、不可创建或不可写时保留现场并报错，不回退到 home、进程 cwd 或其它项目。已登记根在信任、打开和运行前继续按第 5.1 节复核，路径身份改变后旧授权失效。

默认空间首次使用也显示真实目录并要求确认信任，可以复用该精确根的既有信任记录。拒绝后不创建会话、不读取该根内的项目配置、不启动项目 MCP；仅保留空间选择入口。全局模型、Skill 和 MCP 继续遵循既有配置，默认身份不授予额外工具权限，也不自动信任父目录、其它空间或已有的目录内容。

默认空间不得向上提升到 home 或其它 Git 根。当前 `detectProjectRoot()` 与 `SessionManager` 的 `resolveSessionProject()` 都会探测父级 Git 工作树，仅传入 `workspaceRoot` 还不足以固定历史桶；精确根装配的改造见第 3.2 节。即使 home 本身是 Git 仓库，默认空间的根、租约和历史归属也必须保持独立；应用不自动执行 `git init` 来制造边界。

已创建会话的空间归属不原地变更。用户想从默认空间转到项目工作时，选择项目并新建会话；不迁移旧历史、不自动搬动文件或把旧授权带入项目。首版不新增空间删除、默认目录改址或会话跨空间拖动入口；旧历史仍留在原项目桶，不批量归入默认空间。

## 3. 进程与包边界

### 3.1 采用单个 utilityProcess Agent Host

```text
Renderer：React + 纯 ViewModel
        ↕ 命名业务 API / 脱敏展示数据
Preload：contextBridge，单文件 CJS
        ↕ Electron IPC
Main：窗口、目录选择、通知、发送者校验、Host 监督
        ↕ 有界 MessagePort
Agent Host：一个 Electron utilityProcess
        ├─ 配置、信任、受管会话、审批与展示投影
        ├─ 一个 WorkspaceLeaseCoordinator
        ├─ AgentSession + AgentRuntime
        └─ MCP 与既有工具进程生命周期
```

Main 不执行 Agent 工具循环，不从配置加载已有凭证，也不解析原始会话历史；新输入密钥仅经专用通道瞬时转发。Host 在主窗口建立后启动，退出随应用清理，不监听 TCP 端口、不使用外部 daemon、不要求用户先启动 CLI。

生产环境显式设置 utilityProcess 的 `stdio: 'ignore'`，避免 Electron 默认继承 stdout/stderr，使底层配置错误或工具输出绕过脱敏出口。可供用户查看的诊断只能从 Host 的脱敏业务通道返回；开发调试也不直接采集原始流到诊断附件。

所有桌面会话放在同一个 Host 中，避免每工作区一个进程使内存写租约失去协调。Host 内各会话有独立 Session、模型绑定、MCP、历史句柄和权限缓存，仅共享明确设计为宿主级的资源。

最小替代方案是 Main 直接装配 Core，少一个进程和传输层，但模型事件、历史解析与引擎故障会直接影响原生窗口。已选择 utilityProcess 隔离，不再并行维护 Main 直连方案。

**关键假设与失效处理**：utilityProcess 能隔离 Main 与引擎故障，但 Host 退出不证明工具后代已经退出。方案因此只对经过验证的正常取消和退出承诺清理；异常退出进入执行阻断和人工确认流程，见第 7 节。不能用进程隔离替代进程回收证据。

### 3.2 共享宿主入口，而非复制 CLI

新增 `@kiturone/kapibala-cli/host`，作为 Node 环境的窄宿主入口。它不能导入 CLI 启动入口、交互输入协调器或终端渲染器，导入本身不得启动进程、读取终端或创建会话。

| 现有位置 | 改造方式 |
|---|---|
| `packages/cli/src/local-host/resources.ts` | 抽取受管会话装配到 `src/host/managed-session.ts`；保留本地协议适配器对 wire 历史格式的输出 |
| `src/host/history-projection.ts`、`session-presentation.ts`、`presentation-store.ts` | 通过 `/host` 导出；增加有序展示事件订阅，不把合并后的通知反推为完整 delta |
| `src/host/status-facts.ts`、`task-observation.ts` | 复用真实状态和只读观察；使用统一的公共数据脱敏出口 |
| `src/settings.ts`、`model-bindings.ts`、`providers.ts` | 导出必要的配置服务和目录元数据；终端提示通过调用方呈现 |
| `src/view-model/*` | 保持浏览器可用、零 Node 依赖，Renderer 只导入这个子路径及桌面 DTO |

受管装配入口接收已确定的绝对工作区根、显式 homeDirectory、conversationId、审批通道和宿主协调器。装配只核对物理根，不再次向上探测项目。返回受管对象只暴露运行、取消、销毁、空闲时更新模型/模式、读取公共展示快照与状态；原始 Session、Provider、历史句柄不进入跨进程 DTO。

homeDirectory 必须贯穿全部用户级路径，不能只传给 SessionManager。共享装配将 `userInstructionsPath` 固定为 `<homeDirectory>/.kapibala/AGENTS.md`，将 `loggingDirectory` 固定为 `<homeDirectory>/.kapibala`，并将 `auditRecoveryDirectory` 固定为其 `audit` 子目录；使用自定义日志器时仍显式传入对应恢复目录。这些值同时传给父会话和子代理执行器创建的每个 AgentSession，设置、历史、全局 Skill/MCP 也使用同一 homeDirectory。不得通过修改进程 HOME/cwd 切换身份；显式用户目录不可用时失败，不回退到真实 home。既有 SDK 未传这些可选路径时保持原行为。

为固定该身份，新增 `SessionManagerOptions.projectRootMode?: 'git' | 'exact'`，`resolveSessionProject(cwd, mode = 'git')` 接收相同策略。未传时保留既有 CLI/SDK 的 Git 分桶行为；`exact` 以显式绝对根的 native realpath 为 projectRoot，复用 Core 的 `computeProjectKey` 计算桶身份。Git 探测只用于状态，且仅在工作树根与该物理根相同时记录分支，不改变根或借用祖先仓库的分支事实。共享装配固定使用 `exact`，本地协议适配器仍先按原规则 `detectProjectRoot` 再传入，桌面项目选择也先检测并确认最终根，默认空间则不走提升检测。列表、新建、打开和子会话都复用同一身份策略，不只在首次创建时生效。

本地宿主与桌面 Host 使用同一装配实现。直接 CLI 的菜单和输入编排不整体搬迁，但模型创建、配置写入和投影继续共用。新增 `/host` 和精确根参数都属于公共 API 差异，必须纳入声明构建、隔离安装、公共 API 基线及 SDK 兼容性说明，不能靠 `dist/*` 深路径绕开审计。保留旧调用的默认分桶与历史位置，不迁移既有会话。

### 3.3 不扩展现役 wire 1.0

现有本地协议仍为 1.0，继续服务 stdio、socket 和 Windows pipe。它没有桌面设置写入、信任确认接口，公开历史块也没有完整的工具关联字段，不能直接当作桌面全量契约。

桌面采用同一安装包内的私有 Typed IPC，不引入 TRPC 或 HTTP 服务。复用现有错误、取消、身份隔离和快照思路，但明确区分桌面 DTO 与 `WireSessionEvent`。Main、Preload、Host、Renderer 随同一个应用版本构建，不增加独立协议版本配置或旧客户端兼容分支。

## 4. IPC、身份与数据一致性

### 4.1 命名接口清单

契约和运行时校验放在 `packages/desktop/src/shared/contracts.ts`。Zod 仅进入桌面依赖，Core 不依赖它。下表记录首版接口；阶段 B 基础业务与阶段 C 观察接口均已实现。私有生命周期名按实际 Host 握手列出。

| 域 | 接口 | 处理方与限制 |
|---|---|---|
| 应用 | `app.getInfo`、`app.requestQuit`、`app.reconnect`、`app.openExternal` | Main；健康连接的 reconnect 先清理旧控制再 reload，异常 guard 需原生人工确认且旧 Host 已退出；外链仅允许明确用户点击的 http/https，拒绝其它 scheme |
| 首帧引导 | `initialTheme()` | 仅同步取得经 Main 校验来源后的内存主题枚举，不开放其它同步业务；在首个样式计算前应用 |
| 桌面偏好 | `preferences.read`、`preferences.update` | Main；read 返回 UI 偏好，update 仅接受 `theme: light/dark/system`；窗口尺寸与最近选择由 Main 根据已确认的操作记录，不接受任意路径或整份状态替换 |
| 工作区 | `workspace.openDefault`、`workspace.pick`、`workspace.openRecent`、`workspace.confirmTrust`、`workspace.addProject` | openDefault 无路径参数，由 Host 创建并登记固定根；项目目录选择在 Main，根身份与信任判断在 Host；Renderer 后续只能使用已登记的 workspaceId |
| 配置 | `settings.read`、`settings.previewProfile`、`settings.saveProfile`、`settings.setCredential`、`settings.setDefault`、`settings.setRouting` | Host；读接口仅返回白名单和凭证元数据，写接口不接受整份 settings 替换 |
| 会话 | `session.list`、`session.create`、`session.open`、`session.close`、`session.configure` | Host；列表不装配模型，打开要求已配置模型；配置修改要求空闲，close 等待清理 |
| 会话观察 | `session.inspect`；通知 `session.inspectionChanged/inspectionInvalidated` | Host；返回当前会话的状态事实、Skill/MCP 诊断及直接子任务摘要；订阅随该会话的展示订阅建立和释放，不启动 MCP、不收集子任务 |
| 后台运行摘要 | `session.runtimeSubscribe`、`session.runtimeUnsubscribe`；通知 `session.runtimeChanged/runtimeInvalidated` | Host；按当前控制连接订阅全部桌面已打开会话的轻量状态，不随当前空间或详细展示退订而停止 |
| 运行 | `run.start`、`run.cancel`、`run.status` | Host；每会话最多一个在途操作；cancel 返回已受理，不伪装成已完成 |
| 审批 | `approval.reply`；通知 `approval.requested`、`approval.closed` | Host 决定请求是否仍有效；Main 校验窗口归属，旧请求无法授权新调用 |
| 展示 | `presentation.subscribe`、`presentation.unsubscribe`、`presentation.resync`、`presentation.installed` | Host 输出快照、顺序增量及状态；退订展示不等于取消运行 |
| 生命周期 | `host.ready`、`attach/detach`、`shutdown`、`host.cleaned`、`exit`、`host.cleanupFailed` | 只在 Main 与 Host 间使用，不向 Renderer 暴露 Host 任意消息发送能力 |

不暴露 `ipcRenderer`、任意 channel、`fs`、shell、原始 `SessionEvent` 或通用 `eval`。Preload 对每个业务方法封装参数和返回值，并返回可注销的订阅函数。

工作区入口返回 `workspaceId`、`kind: default/project`、显示名、规范化根和信任状态；kind 由 Host 决定，不能由 Renderer 声明来跳过检查。默认空间也先登记到 Main 注册表，执行前进入 guard。项目选择命中默认根时复用默认空间身份，不先向上检测成另一个项目。空间分组使用登记身份与历史元数据，UI 偏好不维护第二份会话归属表。

### 4.2 身份与操作受理

Main 持有主窗口与工作区注册表，校验 IPC sender、顶层 frame、开发或生产来源和窗口生命周期。Host 再校验 workspaceId、sessionId、当前控制代次、runId、approvalId 的归属和状态；不能把 schema 校验当授权。

Host 每次启动生成 hostInstanceId，每次 Renderer 重建控制连接推进 controlEpoch。会话展示继续使用 conversationId、branchId、viewEpoch、sequence，不把 viewEpoch 当权限凭证。

`run.start` 由 Renderer 为一次明确发送生成 operationId。Host 同步登记受理状态后才开始异步执行；相同 ID、相同载荷返回原受理结果，不再执行，相同 ID 不同载荷报冲突。超时后只允许查 `run.status`，不自动重发；Host 更换后旧 ID 的结果是未知，不能转成新操作。

`session.inspect` 与变化通知使用同一白名单快照结构，绑定 hostInstanceId、controlEpoch、workspaceId、sessionId 和递增 revision；过期通知丢弃，页面重建后重新读取。观察快照遵守单条 IPC 上限，摘要超限须标记截断和未展示数量，不截断 canonical 历史；不能通过该接口启动探测进程、安装 Skill 或投递任务结果。`run.status` 保留独立控制路径，不依赖观察快照仍然可用。

后台运行摘要与详细展示分开。`session.runtimeSubscribe` 在同一同步边界建立订阅并返回初始快照；后续通知携带 hostInstanceId、controlEpoch 和单调 revision，每次替换完整摘要。每个条目只含已登记的 workspaceId、sessionId、conversationId、当前 runId、运行阶段、最近运行结果、待审批数量及清理状态，不含正文、工具参数、凭证或子任务内容。最多覆盖 8 个桌面已打开会话，单份不超过 64 KiB，每订阅最多保留一份尚未发送的最新快照，合并时保留当前终态事实。该业务订阅不占用独立停止信令队列；会话关闭后从快照移除，历史元数据仍可列出。Renderer 重建或摘要连接失效时清除可信状态并重新订阅，不用旧快照显示空闲；普通空间切换不断开它，不能靠后台详细历史订阅维持侧栏状态。

摘要 revision 允许因合并而跳号，Renderer 只安装同一控制代次中更高 revision 的完整快照，不套用展示增量的连续 sequence 判据。每个控制连接只建立一个摘要订阅，退订与断连都释放监听器和待发快照。

### 4.3 快照先于增量

Host 内 `PresentationStore` 是可重建的展示状态，原始历史仍由 Core 持有。恢复使用 `projectHistory`，实时事件使用 `SessionPresentation`，两者通过同一工具 ID 与提交消息身份对齐。

现有 `PresentationStore.subscribe()` 只通知状态变化，会合并同一微任务内的追加通知。共享层需增加按顺序输出每个已接受 `PresentationEvent` 的订阅；不能通过前后两个 snapshot 猜回中间事件。原有通知语义保持不变。

订阅采用以下顺序：

1. 在同一同步边界注册有界增量缓冲并捕获展示快照与 sequence 水位。
2. 将快照编码为分块传输，所有块带 snapshotId、总字节数、块序号、控制及展示身份。
3. Renderer 完整校验、组装快照后一次性安装，只接收该身份下高于水位的连续增量。
4. 旧代次事件丢弃；同代次出现真实缺口、队列溢出或快照校验失败时停止应用增量并 resync，不悄悄跳过语义事件。

重同步只恢复展示，不重启 run。控制通道失效时触发第 7 节的取消规则；普通侧栏切换与展示退订不导致控制通道失效。

同一超限状态不连续自动重试 resync；展示保持失效提示，等待用户处理或重新订阅，避免无法安装的快照反复占满通道。

### 4.4 固定预算与超限行为

下列是首版实现和测试采用的固定上限，不新增面向用户的调参开关。已有本地协议预算值从现有常量取值，桌面专有预算单独命名，不改变 wire 1.0。

| 项目 | 上限 | 超限处理 |
|---|---:|---|
| 单条 IPC 编码载荷 | 1 MiB | 入站请求拒绝且不执行；已生成的出站增量超限则使展示失效，改走分块快照 |
| 完整展示快照 | 8 MiB | 明确报告快照过大，标记展示过期并阻止新 run，保留独立停止入口 |
| 快照分块 | 256 KiB | 单块有界，接收方累计预算也必须检查 |
| 每端未确认发送队列 | 4 MiB | 关闭失效订阅或控制通道，按其作用域恢复或取消 |
| 每端独立控制队列 | 64 KiB | 只接收 ACK、取消、失效和关闭等小型信令；超限关闭连接并触发本地清理 |
| 在途业务请求 | 64 | 拒绝新增请求，保留取消和清理的控制容量 |
| 桌面已打开运行时会话 / 并行 run | 8 / 4 | 显示已用数量，提供关闭空闲句柄入口或等待；不自动驱逐会话 |
| 待处理审批 | 128 | 超额审批按拒绝处理，通知用户 |
| 操作去重记录 | 1024 | 当前控制代次内不淘汰受理记录；满额拒绝新 run，待无在途操作后可显式重建控制连接 |
| 初始化 / 普通请求 / 审批超时 | 5 秒 / 30 秒 / 120 秒 | 各自独立；长任务不受普通请求超时直接判为失败 |
| 单次历史文件打开预算 | 64 MiB | 打开前检查并在读取过程中限额；超过则保留原文件并拒绝加载 |

MessagePort 的 `postMessage` 没有自动提供上述背压。应用层采用编码字节计数和累计 ACK，最多保留 4 MiB 未确认消息；ACK、取消与关闭信令使用独立的小型控制队列，不能被输出堵塞。

传输接收确认与展示安装确认分开：接收方校验块身份、大小和累计预算后，即按连续 transportSequence 回 ACK 释放发送额度，不等待完整快照安装。快照全部校验并原子安装后，才确认 snapshotId 与展示 sequence 水位。否则 8 MiB 快照会在 4 MiB 发送窗口耗尽后互相等待。ACK 不得超过已发送水位，旧连接 ACK 不释放新连接额度；已接收的快照仍受 8 MiB 累计预算约束。

Main 转发与 Preload 订阅也须有界，不能在 MessagePort 出口另接无界的 `webContents.send` 队列。每一跳只在下一跳接收额度允许时发送；Renderer 只见命名业务方法，内部端口不交给页面。控制通道保留 `run.status` 所需的小型状态回复容量。

`message_committed` 可能包含一整条超过 1 MiB 的已落盘消息，不能用拒绝入站请求的规则处理。Host 经控制通道发送小型 `presentation.invalidated`，冻结该订阅的增量，改传 256 KiB 分块快照；若快照仍超过 8 MiB，Renderer 明确显示展示过期、取消旧的可信空闲标记并禁用发送，仍可用独立控制通道查询状态或停止已有 run。原始消息不删除、不截断，恢复展示不得重放操作。

取消和清理不得依赖 Renderer 及时 ACK。发送通道断开后 Host 仍继续执行取消、事务闭合和落盘流程。

历史读取预算需要补到 `SessionManager`、`SessionStore` 及 JSONL 读取链，不能只在 UI 里检查一次文件大小。新增可选 `maxReadBytes`，由桌面 Host 固定传入 64 MiB，既有 CLI/SDK 未传时行为不变；元数据重建、旧历史复制升级与重载也须传递预算，累计字节检查在解析和尾部恢复写入之前执行。超限记录为独立错误，不当作损坏尾记录修复，不限制正在闭合事务所必需的消息落盘。列表重建遇到超限会话时保留其身份与不可打开提示，不让它阻断其它历史条目。

首版不增加历史分页存储引擎。64 MiB 文件上限与 8 MiB 展示上限是明确的能力边界；虚拟列表只减少 DOM 数量，不解决原始历史的内存占用。超过预算时引导新建会话，不删除或改写超限历史。

## 5. 配置、信任与凭证

### 5.1 共用配置，不复制目录和密钥

继续使用 `~/.kapibala/settings.json`、既有项目配置和会话目录。Profile、厂商名称、模型协议和密钥分组只从已有实现读取，具体默认模型取 `DEFAULT_MODEL_ID`，不在桌面代码中写死。

桌面 UI 偏好放在 Electron userData 下的 `desktop-state.json`，仅含窗口尺寸、主题、最近项目、最近选中的空间和会话定位信息；最近项目最多保留 20 项，默认空间固定显示且不占此名额。主题取 `light`、`dark` 或 `system`，缺省为 `light`。最近空间保存 default 标记或项目根定位，不能把上一 Host 的 workspaceId 当作新启动后的有效授权；恢复时重新登记且不自动发送。它不保存对话正文、模型密钥、审批缓存或权限模式。

项目选择和默认空间首次进入都先显示规范化后的真实根，再确认信任。选中目录或创建默认目录不等于信任其配置，信任空间不等于允许所有工具。既有精确根信任记录可复用，但路径变化必须重新核对；Renderer 不能提交另一个任意路径来扩大授权范围。只读取当前根内的项目配置、Skill 与 MCP，不把默认目录的祖先当作项目配置来源；全局配置按既有入口单独加载。

Host 在确认信任、打开会话和受理 run 前重新按 native realpath 核对已登记根路径；路径失效或解析出的根路径发生变化时拒绝执行并要求重新选择，默认空间则要求修复约定目录后重新登记，不沿用旧 workspaceId 的授权。此检查不能防止任意文件系统替换，具体工具仍由 Core 的既有路径与沙箱策略约束。

### 5.2 全局配置写事务

当前 `saveGlobalSettings()` 已有同目录临时文件和原子 rename，但读取和修改发生在锁外。CLI 与桌面同时更新不同字段仍可能互相覆盖，因此必须共同改造。

在 `settings.ts` 增加同步的 `mutateGlobalSettings` 事务入口：独占锁 → 重读原始配置 → 执行短同步变更 → 现有校验与目录迁移 → 原子替换 → 释放本人持有的锁。独占锁位于配置同目录，使用独占创建和随机所有者标识，记录 PID 仅供诊断。

取得锁失败立即返回 `SETTINGS_BUSY`，不阻塞 Electron Main，不后台覆盖重试。锁内不弹交互、不探测网络、不等待密钥输入。向导和设置页先收集用户改动，提交时只应用字段变更，不能把之前打开表单时读取的整份配置写回。

进程异常留下锁时不靠超时或 PID 不存在自动抢占。错误应给出锁路径与检查说明；用户确认所有配置写入进程已退出后才能移走残留锁。启动目录迁移遇到锁冲突可保留既有告警和延后迁移行为，但不能宣称保存成功。

`trustProject`、目录迁移、`persistDefaultModel`、`persistModelRole`、向导以及 `/model key` 必须接入同一事务。现有原子保存实现降为事务内部写入原语，测试注入点改为事务边界，避免未来调用方绕开锁。

这项互斥只覆盖采用新事务的 CLI 与桌面版本。旧 CLI、外部编辑器和网络文件系统不受该锁约束；发布说明必须提示不要同时用旧 CLI 修改设置，不能宣称存量程序自动获得互斥能力。

### 5.3 凭证出口与变更生效

读取仍走 `resolveApiKeyDetailed`，写入走 `ensureProfile` 与 `updateProfileApiKey`，分组仍走 `credentialGroup` 与 `describeCredentialGroup`。未知厂商继续按 host 隔离，不跨厂商借用密钥。

协议、Base URL 或 `apiKeyEnv` 变化必须另存为新的 Profile ID，原 Profile 和原分组凭证保留，不复制旧内联密钥。仅重算分组不够，因为内联密钥在现有解析器中优先级最高，可能被带到新的服务端。

Host 通过 `settings.previewProfile` 返回实际生效端点、分组和拟使用的凭证来源，不发起网络请求。用户须明确选择复用目标分组凭证、输入新密钥或免鉴权；`saveProfile` 在事务内重算并核对确认时的端点与来源，发生变化则拒绝并要求重新确认。同组新密钥的替换影响所有同组模型，必须在确认中说明；不能把新服务的密钥静默覆盖到旧分组。

预览返回 Host 内保存的随机 confirmationToken，绑定当前控制代次、工作区、Profile 草稿及相关配置值，包括凭证实际值和来源 Profile，而不只比较“shared/env”等来源标签。令牌不含明文或可离线猜测的密钥摘要，30 秒过期、最多保留 64 个，成功提交后失效。提交在配置锁内重读并比对相关值；同组密钥已被另一进程替换、目标 ID 被占用或项目覆盖变化时返回 `SETTINGS_CONFLICT`，即使来源标签相同也要求重新预览。无关字段的变更可合并，不把整份旧表单覆盖回去；密钥写入同样绑定其目标分组的确认。

Renderer 只接收“已配置、来源、分组、环境变量名”等元数据，不读取或回显已有明文值。新输入密钥通过专用方法提交，Main 只转发、不记录，成功或关闭表单后清空输入状态；不承诺 JavaScript 内存可被安全擦除。

不在首版引入 safeStorage 自动迁移，因为 CLI 无法直接读取 Electron 专有密文。文件存储与权限限制不等于系统钥匙串保护，界面必须明确实际保存位置。

设置保存成功后才更新内存。运行中的 Session 继续使用该 run 受理时的模型和凭证绑定，下一次 run 在空闲边界重读配置并更新。全局默认供新建或重新打开运行时会话时选择初始模型，项目配置仍按既有优先级覆盖；已打开会话保留当前选中的 Profile ID 与角色，刷新只更新对应配置和凭证，不因全局默认变化自动切换模型。选中 Profile 失效时提示重新选择，不静默回退到另一模型。当前会话的临时选择不写回全局默认，也不从历史回放成执行配置。

脱敏集在该运行结束前保留旧凭证，防止换密钥后漏掉在途输出中的旧值。项目配置覆盖全局配置时，设置页同时显示配置来源和实际生效值；路由配置的更新在下次 run 的空闲边界生效，不改变在途调用。

### 5.4 公共数据脱敏

Host 的历史投影、实时输出、工具详情、错误、审批描述、任务摘要和诊断走统一白名单出口。现有 `formatToolDetail` 的字段脱敏不是任意字符串的完整秘密检测；增加已知凭证脱敏与跨 delta 边界测试，且不声称能识别所有未知秘密。

原始 Provider 状态、隐藏推理、签名、请求头、环境变量值和 Error 对象不能进入 Renderer。脱敏只改变展示数据，不为 UI 重写原始历史或伪造工具参数。审批匹配使用 Host 保留的原始受控调用身份，不能以脱敏后的文本作为授权依据。

## 6. 前端、安全与环境适配

### 6.1 确定的技术栈

桌面 UI 的每个能力角色只允许一个库。下表是首版唯一选型，括号内版本为 2026-10-24 核对的上游事实，实施时锁定当时的受支持稳定版与 lockfile。

| 角色 | 唯一选型 | 用法与边界 |
|---|---|---|
| 桌面运行时 | Electron | Main、sandboxed Preload、utilityProcess Host |
| 构建 | electron-vite、TypeScript | Main 与 Host 为独立 Node 入口，Preload 单独打包，Renderer 使用 Vite |
| UI 框架 | React 19 | Renderer 只持有展示 DTO 与视图状态 |
| 组件与交互原语 | `@cloudflare/kumo` 2.15.0（MIT，ESM-only） | 已含样式组件与 `@base-ui/react` 原语；侧栏、对话框、抽屉原语、选择器、Toast、代码高亮、敏感输入均取自 Kumo |
| 样式 | Tailwind CSS v4 + Kumo 语义 token | 只写 Kumo token 对应的工具类；主题变量集中在一个主题文件 |
| 图标 | `@phosphor-icons/react`（Kumo 必需 peer） | Kumo 内部组件直接引用 Phosphor，界面图标同源 |
| 动画 | `motion` 12.x（与 Kumo 依赖同一主版本） | 默认使用 Kumo 内置过渡；需要自写动画时显式声明同一主版本，不另装其他动画库 |
| UI 瞬时状态 | Zustand 5.x | 只存选择项、抽屉目标、草稿、队列开关等易失状态，禁止 `persist` |
| 会话展示状态 | 现有 ViewModel、`useSyncExternalStore` | Host 展示状态的唯一来源，不复制进 Zustand |
| 长列表 | `@tanstack/react-virtual` | 按消息虚拟化，不引入聊天状态框架 |
| Markdown | react-markdown、remark-gfm | 禁用原始 HTML；代码块交给 Kumo `CodeHighlighted` |
| 代码高亮 | Kumo `CodeHighlighted`（内置 Shiki 4） | 不直装 Shiki、Prism 或 highlight.js |
| IPC 校验 | Zod 4（仅桌面包） | 桌面共享的判别联合与输入/输出校验 |
| 测试 | Vitest、Playwright Electron | 纯逻辑、真实窗口、Host、安装后冒烟 |
| 打包 | electron-builder | NSIS、ZIP、DMG、AppImage；自动更新不启用 |

首版不安装 `react-resizable-panels` 与 `dnd-kit`：当前功能没有可调分栏、跨空间拖动、会话排序或拖拽附件，侧栏与对话列由 Kumo Sidebar 加 CSS Grid 表达。未来若新增这些交互，唯一允许的选型分别是 `react-resizable-panels` 与 `@dnd-kit/core`，并须先更新本节。

Radix、shadcn/ui（含 Nova 预设）不作为第二套体系引入。Kumo 已捆绑 Base UI primitives 并提供完整样式层；Radix 是无样式原语，shadcn Nova 只是把组件源码生成到应用里的风格预设，二者与 Kumo 叠加会得到两套焦点管理、弹层栈和组合框行为。若未来评估替换，只能整体替换组件体系，不允许并存。

阶段 B 已锁定 Electron 45.0.0、electron-vite 6.0.0、React 19.3.1、Tailwind 4.3.3、Zod 4.6.7 与 Kumo 2.15.0，完整依赖版本见桌面 package.json 和 lockfile。桌面开发 Node 要求为 >=22.12，建议 Node 24；Core、MCP、CLI 保持 Node 20。内部开发包仍使用当前 0.0.10，不提前执行发布升版。

开发开始时锁定上述依赖的受支持稳定版本及 lockfile，Electron 内嵌 Node 与 CLI 支持 Node 20 是两个独立验收对象。不要因为桌面包使用了新运行时而提高 Core、MCP、CLI 的既有最低版本。

Kumo 的接入顺序是硬约束：Tailwind 通过 `@source` 显式扫描 Kumo 产物（Tailwind v4 不扫描 `node_modules`），Kumo 样式必须导入在 Tailwind 之前，应用根元素设置 `isolation: isolate`，否则 portal 层级会被正 z-index 内容覆盖。主题切换使用 Kumo 的 `data-mode="dark"` 与 `light-dark()`，不写 Tailwind `dark:` 变体。

### 6.1.1 成熟组件优先与依赖边界

本节是桌面前端的准入规则，不是风格建议。违反其中任一条的实现不能通过 UI 评审。

**已有依赖能正确表达时，禁止自行实现组件或行为。** 下列能力必须来自选定库，不允许手写等价逻辑：

| 能力 | 必须使用 | 禁止的重复实现 |
|---|---|---|
| 焦点约束、Escape/外部点击关闭、portal 层级、滚动锁定 | Kumo 组件或 `@cloudflare/kumo/primitives/*` | 自写 focus trap、全局 keydown 栈、手动 `createPortal` 层级管理 |
| 下拉、组合框、自动完成、菜单 | Kumo `Select`、`Combobox`、`Autocomplete`、`Dropdown` | 自写过滤、键盘漫游、roving tabindex |
| 弹窗、确认、抽屉、提示、Toast | Kumo `LayerDialog`、`primitives/alert-dialog`、`primitives/dialog`、`primitives/drawer`、`Tooltip`、`Toast` | 自写遮罩、动画队列、堆叠管理；桌面详情使用 Dialog，具体策略见 6.3.2 |
| 折叠、标签页、命令面板 | Kumo `Collapsible`、`Tabs`、`CommandPalette` | 自写展开动画与 roving 焦点 |
| 表单控件与敏感输入 | Kumo `Field`、`Input`、`InputArea`、`Switch`、`Checkbox`、`Radio`、`SensitiveInput` | 自绘开关、自写密码显隐与剪贴板处理 |
| Markdown 解析与代码高亮 | react-markdown、remark-gfm、Kumo `CodeHighlighted` | 自写 Markdown 解析器、正则高亮、复制按钮 |
| 列表虚拟化 | `@tanstack/react-virtual` | 自写窗口化计算 |
| 图标 | Phosphor | 手写 SVG 图标路径（品牌 logo 除外）、混用第二套图标库 |

**组件选择按三层顺序，不得跳级。** 第一层用 Kumo 带样式组件；第二层用 Kumo primitive 加 Kumo token 组合；第三层才在 `renderer/ui/` 写领域组件。领域组件只允许组合布局与数据语义，不得重写键盘、焦点、弹层、虚拟化或解析行为。新增领域组件须在文件头注释写明为何没有 Kumo 组件或原语可用。

**源码可控，但不 vendor 整个库。** 依赖锁定版本并进入 lockfile，只接受源码公开、许可明确（MIT、ISC、Apache-2.0 等已审许可证）且可离线构建的库，不引入闭源组件或需要远程授权的 UI 服务。不把库源码复制进仓库，不修改 `node_modules`。确需修复上游缺陷时只允许 `pnpm patch`，且必须同时留下 upstream issue 链接与移除条件。主题定制只写在 `renderer/theme-kapibala.css`，以 Kumo 语义变量覆盖为主，另允许 6.3.4 节的统一按钮焦点适配；不逐页面或逐实例改组件样式。

**视觉只有一个来源。** 颜色、圆角、阴影、间距、字号都取 Kumo 语义 token 与组件默认形状。禁止在组件里写 `bg-blue-500` 一类原始调色板类、`dark:` 变体、主题文件之外的内联十六进制色值，也禁止自定义第二套圆角或阴影档位。

**新增依赖需要理由。** 新依赖必须说明它填补的角色、许可证、包体与运行时影响，并先更新 6.1 节选型表；同一角色出现第二个库即视为设计缺陷。Kumo 不提供的品牌资产（应用图标、字标）走 `assets/` 既有流程，不从 Kumo 引入 Cloudflare 的品牌组件或橙色主色。

**打包与许可。** 生产包只包含实际被引用的依赖，构建产物附第三方许可证清单；不因为引入了组件库而放宽 Renderer 的 Node 访问边界，也不把组件库的示例页面或演示资源打进应用。

### 6.2 Renderer 不持有执行特权

固定启用 `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`。Main 与 Host 可使用 ESM，沙箱 Preload 单独输出 CJS 文件；它只有 Electron 提供的有限 require 和全局对象，不是完整 Node 环境。

生产页面通过固定应用来源加载打包静态资源，资源处理器只映射 Renderer 构建目录，防止路径穿越。设置 CSP、拒绝非预期导航和新窗口、拒绝网页权限请求；仅对固定来源的主 frame 放行 `clipboard-sanitized-write`，供 Kumo 明确点击复制使用，不授予读取权限。不加载远端脚本或自动加载 Markdown 远程图片。开发服务器只绑定 loopback，并单独校验开发来源。

代码复制只复制用户明确选择的公开文本；链接打开经过 Main 的 scheme 校验，不将模型输出的命令、`file:`、自定义协议或本地路径交给系统执行。系统通知只带应用状态和会话定位 ID，不显示密钥、工具参数或大段对话。

### 6.3 对话式 UI 与交互

#### 6.3.1 主窗口与空间侧栏

界面以阅读、输入和掌握当前任务状态为主，不设置仪表盘首页。默认窗口为 1280 × 800，最小窗口为 800 × 600，尺寸使用逻辑像素。常态两栏，右侧详情只有明确点击后才占用空间：

```text
空间与会话侧栏          对话主体                         按需右侧抽屉
新建会话 / 添加项目     空间名 / 会话标题                 工具详情或会话状态
默认空间               用户消息                         默认关闭，不留空列
  会话列表             助手正文与折叠思考
项目空间               紧凑工具卡片
  会话列表             输入框
设置                   当前模型 / 模式 / 发送或停止
```

| 区域 | 展示与操作 |
|---|---|
| 空间侧栏 | 由 Kumo `Sidebar` 承载，展开宽 275，收起为 56 图标列；默认空间置顶，项目按最近访问排列，名称下可展开会话。相同目录名用父路径区分，完整根可通过空间信息查看和复制。折叠空间仍显示运行、待审批或失败状态 |
| 对话标题栏 | 显示当前空间、会话标题和状态入口，不铺满 Token、MCP 或子任务指标；无 Git 仓库不显示虚构分支。不设常驻审批计数，未处理审批由自动弹出的队列和侧栏「待审批」状态触达 |
| 消息区 | 正文最大宽 760，随可用区域收缩；用户与助手靠角色标签、间距和浅背景区分，不把每条回复包成大卡片。工具与思考依附实际消息顺序 |
| 输入区 | 固定在对话底部，输入框随内容增高到 180 后内部滚动；当前模型、权限模式及发送/停止保持可达，角色选择放在模型菜单内。模型和模式只在空闲时可修改 |
| 空会话 | 显示当前空间与实际工作目录、简短输入提示和必要的信任/配置入口；加载历史时显示加载状态，完成后才显示空态，不用示例对话冒充历史 |

窗口宽度低于 960 时侧栏默认收起为图标列，标题栏按钮只切换受控 `open`；展开动效、焦点管理、收起后的可达名称都由 Kumo `Sidebar` 负责，应用不重写开合逻辑。窗口低于 Kumo 的 768 移动断点时由其内建行为切换为覆盖式面板，最小窗口 800 下不会进入该分支。选择空间后不取消其它空间任务。空间切换保留各会话的未发送草稿和滚动位置，仅驻留当前 Renderer 内存，不写入历史或桌面偏好。若当前会话因额度未能打开，显示原因，不自动关闭运行中的其它会话。

侧栏运行、待审批与清理状态来自独立的后台运行摘要，不要求打开该会话的消息列表或详情。每一行的行菜单都可用：有运行句柄时提供“关闭运行时”（运行中改为“停止并关闭”），清理失败保留占用和“重试清理”；无论是否持有句柄，都另提供“重命名”“置顶/取消置顶”“归档”与“删除”。重命名与置顶只追加控制记录（`title` / `pin_state`），不改正文、不搬动文件、不打断在途任务：句柄在本进程时经其 Store 追加，未打开时由 `SessionManager` 取锁写入后立即释放，因此不会留下写锁把后续操作挡成 `SESSION_LOCKED`。归档追加 `archive_state`（可恢复，归档项在设置 → 会话归档中找回）；删除物理删除正文与 sidecar 缓存，必须先经一次不可撤销确认。运行中的会话禁止归档与删除，仅持有空闲句柄时先关闭句柄再执行。置顶项在列表中整体前置、组内仍按活动时间排序，取消后回到原位。达到 8 个句柄时提示已用数量并列出可关闭的空闲会话，不自动关闭、不把空间切换当成句柄释放；再次打开仍走既有信任、配置和独占锁检查。

#### 6.3.2 工具详情与观察面板

消息流中的工具卡片默认只显示工具名、简短目标、真实状态和查看详情入口；长参数、完整输出、错误上下文放入右侧详情。思考独立折叠，只显示 Provider 允许公开的内容。运行、完成、失败都不自动弹出详情，也不因输出增长将对话推到页面下方。

右侧抽屉默认关闭，宽 360，同一时间只查看一个工具或会话状态。窗口宽度至少 1200 时与聊天并排；更窄时从右侧覆盖，不挤出一块低于可读宽度的聊天列，也不堆到聊天底部。抽屉用 Kumo `primitives/dialog` 组合成侧面板：并排时设置 `modal={false}`、`disablePointerDismissal={true}`，不显示遮罩，点击或 Tab 到输入框后详情继续保持；覆盖时设置 `modal={true}`、`disablePointerDismissal={false}`，显示遮罩并约束焦点，点击遮罩可以关闭。两种模式均支持关闭按钮与 Escape；焦点返回由原语的配置入口指定，触发工具因虚拟化已卸载时返回可聚焦的消息区，不在应用层另写 focus trap 或全局键盘栈。跨 1200 断点切换时保留当前详情身份并应用对应策略，不重建会话或丢失输入草稿。详情内部滚动，长代码横向滚动，不放大整个窗口。

抽屉的 DOM 层级遵循 6.1 节的 portal 与 `isolation: isolate` 约束。Kumo 的 `LayerDialog` 是模态对话框与移动端抽屉，不用于桌面右侧面板；把详情做成 `LayerDialog` 会阻断与正文的并行输入，因此只借用其原语，不借用其模态语义。

查看工具时以 workspaceId、sessionId 和 callId 定位，标题保留空间与会话来源；切换会话关闭旧抽屉，不把迟到结果显示成新会话工具。关闭详情只改变视图，不取消运行、不释放历史句柄，也不重订阅整份历史。会话状态、Skill/MCP 和子任务观察共用这一按需区域，不常驻三个独立面板。

普通工具查看采用抽屉，不逐条打开模态弹窗，以便宽窗口下对照正文继续输入。模态界面用于设置、信任和高风险确认，统一由 Kumo 对话框组件承载。待审批不能只藏在详情里：新请求到达时队列自动弹出，侧栏对应空间与会话标记「待审批」，重新打开该会话即回到队列；标题栏不设常驻计数，避免把未处理数量读成累计统计。用户主动打开集中审批队列后查看完整脱敏描述再作决定。审批队列使用 Kumo `LayerDialog` 加列表组件，来源、工具名和风险说明同屏可见，按钮文案为“批准一次”“本会话允许相同调用”和“拒绝”。会话级选项仅在 Host 提供的 `sessionAllowed=true` 时显示，映射 `allow_session`；它只复用当前运行时会话内的精确调用授权，不持久化、不扩大为允许同名工具，句柄销毁后失效。不允许会话级缓存的请求只提供单次批准或拒绝，Host 仍拒绝伪造的 `allow_session`。切换空间不改变请求归属，关闭队列不等于拒绝；拒绝、过期、已处理和控制代次变化立即使按钮失效，系统通知只负责定位窗口。

#### 6.3.3 设置与当前会话控制

侧栏底部固定设置入口，使用应用内设置对话框，包含三个分区。设置对话框由 Kumo `LayerDialog` 承载，分区导航用 `Tabs`，表单字段用 `Field`、`Input`、`Switch`、`Select`，模型与 Profile 选择用 `Combobox`，密钥输入用 `SensitiveInput`，只读路径与命令用 `InlineCopyText` 展示和复制；模态、标签切换、密钥显隐与复制反馈都不在应用层重写。

| 分区 | 内容与作用域 |
|---|---|
| 模型与服务商 | 内置目录、自建 Profile、协议、端点及凭证来源；沿用第 5.3 节的预览确认，不回显已有密钥 |
| 默认模型与路由 | 新会话的默认模型与现有场景路由；同时显示当前空间的项目覆盖和实际生效值，不能将全局保存成功说成项目覆盖已改变 |
| 外观与应用 | 浅色、深色、跟随系统；实际版本、运行时与脱敏诊断入口；默认空间位置只读展示，不在此修改执行根 |

输入框旁的模型和权限控制仅作用于当前打开的会话，切换模型不会修改设置页的全局默认。具体模型生效顺序按第 5.3 节执行；保存设置不发送消息、不重启任务，也不把当前草稿自动提交。设置对话框独立滚动，关闭后返回触发入口，新输入密钥成功提交或关闭表单后清空。

权限模式沿用 `Approval`、`Plan`、`Auto`、`FullAccess` 的现有定义。首次默认遵循合法配置，持久配置中的 `FullAccess` 仍降为 `Approval`；只有用户在当前会话的独立风险确认中明确选择后才能启用，恢复历史、重启和 Host 更换均不恢复它。默认空间也不例外。

#### 6.3.4 视觉语言、主题与文案

**方向：紧凑的黑白纸面。** 以用户提供的客户端截图为视觉基线：白底、灰色细边、黑色主按钮，系统字体，紧凑表单与较小的确认弹窗。状态仅按语义保留必要颜色。界面没有装饰性渐变、玻璃拟态、霓虹描边或大面积色块，深度只靠分隔线与浮层阴影表达。Kumo 提供形状与交互，产品身份来自本节 token，不继承 Cloudflare 的橙色品牌色或品牌资产。

弹窗宽度统一为：信任、凭证和风险确认 440px；创建项目与审批 500px；完整设置 600px。长表单最高 560px，矮窗口最高为内容区高度减 48px，内部滚动；正文 14px、说明 13px、消息正文 15px。使用公开 Tailwind 尺寸 token 与应用自有浮层标记，不复制组件或重写焦点管理。

**形状与层级。** 圆角、阴影、按钮高度、输入高度全部使用 Kumo 组件默认值，不另设第二套 6/10/14px 之类的档位。Kumo 的 primary 按钮固定白字，并由 brand 与白色混合生成底色和悬停效果，不能靠 inverse token 改变文字颜色。因此主操作底色与文字强调分开：primary 保留白字，两套主题采用黑色底色；正文强调、焦点和状态使用独立 token。主题测试检查实际普通、悬停、焦点及按下状态，不只检查 token 原色；实际主按钮普通、悬停、按下和焦点状态继续由窗口回归计算对比度。首版危险按钮统一使用 `secondary-destructive`，不把浅色 danger 状态色直接用作白字实心按钮底色。浅色靠 `canvas` 与 `base` 的明度差和 Kumo 浮层阴影分层，深色靠 `base`、`elevated`、`fill` 的明度递进分层，不用深色阴影硬撑。鼠标桌面控件采用 Kumo 的标准尺寸，常用图标按钮保留可见焦点与可辨认的点击区域，不通过放大图标撑高所有行。

按钮焦点不借用深色 brand 底色。主题文件统一定义应用自有的 `kapibala-action` 焦点适配类，所有 Kumo 按钮复用：`:focus-visible` 时以 `--color-kumo-focus` 绘制 2px outline、2px offset，确保 primary、危险次按钮与图标按钮在深色背景也有清晰边界。该类只补可达性指示，不改变尺寸、点击、键盘或弹层行为，不依赖 Kumo 内部 DOM 选择器；仍实测相邻背景对比度至少 3:1。

**色彩的用量。** 主操作、焦点和选中状态沿用黑白灰语义 token，成功、错误、审批和危险状态才使用状态色。链接使用 text link token 并保留下划线，选中项和文字强调使用 text brand token，不拿实心按钮底色替代正文链接色。错误、审批和危险操作使用 danger 语义，不把 brand 当作通用高亮。Kumo 主按钮自带的细微渐变作为既有组件样式保留，不新增页面背景或其它装饰性渐变。

**消息与工具。** 助手回复不加气泡、不加卡片边框，正文直接落在 `base` 上；用户消息使用 `tint` 底与 Kumo 默认圆角，和助手形成角色区分。工具行是细线分隔的单行列表，显示工具名、目标摘要、真实状态和详情入口，不把每次调用做成独立卡片。思考内容用 `Collapsible` 折叠，默认收起，只展示 Provider 允许公开的文本。代码块使用 `CodeHighlighted`，语言标签与复制按钮随组件提供，不另造一套工具栏。

**输入区。** 回到底部固定，顶部一条 hairline，控件表面用 `control`，不套大圆角容器。模型与权限模式以紧凑文本按钮呈现，运行中把发送替换为停止；停止是危险语义但保持次按钮形态，避免在输入区出现两块高饱和色。输入框增高到 180 后内部滚动。

**排版。** 字体使用系统栈 `-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`，代码使用系统等宽字体，不下载 webfont，也不引入第二套字体。主题层设置 `--font-sans` 与 `--font-mono`。正文 16px、中文行高 1.7 至 1.8；常规 UI 标签 14px；时间、Token 数、耗时等元信息 12px；设置分区标题 18px。中文与中英混排不做负字间距；数字类动态值使用等宽数字，避免跳动。正文行宽由 800px 的对话列约束，不额外压窄。

**主题切换。** 保存用户选项而非当前计算结果，首次为 `light`，选择 `system` 后才随系统实时切换，显式浅色或深色不受系统改变影响。Kumo 通过 `data-mode="dark"` 与 `light-dark()` 取色，不写 Tailwind `dark:` 变体。Main 设置 `nativeTheme.themeSource` 与窗口初始背景，Renderer 在首帧前写入 `data-mode`，避免深色启动闪白；切换主题不重建 Host 或会话。

**动效。** 默认不做消息入场动画、流式文字动画或面板自动滑出。浮层进出、Toast 和折叠优先使用 Kumo 内置过渡，应用层不叠加第二套动画，也不对同一属性同时使用 Motion 与 CSS transition。应用自写动画只改变 `transform` 与 `opacity`，不动画改变布局尺寸；Kumo Sidebar 的 width、padding、grid 行尺寸等内置布局过渡属于明确例外，不复制实现或另加覆盖动画。所有路径遵守 `prefers-reduced-motion`；Sidebar 使用受控的 `animationDuration` 在减少动效时设为 0，并实测其它组件的对应行为。按下反馈由 Kumo 按钮提供，应用不为键盘触发另加位移动画。静态门禁检查应用源码中的新增动画与 `transition: all`，不将依赖内部默认实现当成应用违规；库升级后仍需跑真实窗口与性能回归。

**文案。** 界面以简体中文为准，术语固定为空间、会话、工具、审批、运行、停止、正在取消、正在清理。按钮以动词开头：新建会话、选择项目、停止运行、复制路径、重试清理。状态写事实而不是鼓励语：运行中、等待审批、清理未完成。错误写原因与下一步，例如“无法写入默认空间，请检查目录权限后重试”，不使用“出错了”“Oops”或感叹号，也不把内部异常栈直接展示给用户。空态陈述当前事实和可做的下一步，不用示例对话或营销句填充。权限模式的显示名为逐次审批、计划、自动、完全访问，代码与持久化仍用 `Approval`、`Plan`、`Auto`、`FullAccess`。

**键盘与可达性。** Enter 发送、Shift+Enter 换行，输入法组合期间 Enter 不发送。所有图标按钮有可访问名称和可见焦点，正文对比度至少 4.5:1，焦点指示与必要控件边界至少 3:1。滚动到底部时自动跟随流式输出，用户向上滚动后停止抢夺位置并显示返回底部按钮；只合并渲染通知，不截掉中间语义事件。工具折叠与抽屉开关属于当前视图，刷新后可重置，不写入历史。停止受理后显示正在取消，清理结束前不恢复发送按钮；设置与覆盖抽屉关闭后不丢草稿。

### 6.4 GUI 启动时的工具环境

Electron 自带 Node 供应用内部运行，不代表系统 `PATH` 已存在 `node`、`npx`、Git 或用户配置的 MCP 命令。Host 沿用现有 shell 探测与 MCP 配置，显示缺少的具体可执行文件，不偷偷安装依赖、不把 `process.execPath` 假装成通用 Node CLI。

首版不自动执行用户登录脚本来导入环境。用户可在系统环境中配置命令或在既有配置支持的位置提供绝对路径；验收必须覆盖从 Finder、开始菜单和桌面启动器启动的环境，不以开发终端启动成功代替。

## 7. 生命周期与故障恢复

### 7.1 正常运行和取消

复用展示状态 `idle → running → cancelling/settling → idle`，运行结果单独记录 completed、failed 或 aborted。Host 自己持有异步迭代器与 AbortController，不能因为页面卸载而提前丢弃迭代器。

停止请求使 Host 取消父 run 和既有活跃子任务，继续消费或清理在途工具，闭合并落盘工具结果。只有迭代结束、子任务清理完成、执行门可释放后才发送 settled。完成的工具保留真实成功结果，不因随后取消被统一改为失败。

会话关闭及应用退出进一步按资源依赖顺序执行 runtime.close、session.destroy、历史句柄 release。沿用“前两者成功才释放句柄”的规则，清理失败保留待清理状态并支持重试未完成步骤。

### 7.2 区分窗口隐藏、连接丢失与退出

| 场景 | 行为 |
|---|---|
| 切换项目、最小化、正常隐藏窗口 | 保留控制所有权与运行；不把隐藏当作断连 |
| macOS 点击关闭 | 隐藏并保留窗口/Host；Dock 激活重新显示；Cmd+Q 进入应用退出 |
| Windows 点击关闭 | 隐藏到托盘；托盘菜单有显示、状态和退出；托盘创建失败时改走退出确认 |
| Linux 点击关闭 | 有可用托盘时同 Windows；没有托盘时走退出确认，不能让用户失去控制入口 |
| Renderer 崩溃或控制连接丢失 | Main 通知 Host 撤销该控制代次、使审批失效、取消所属 run 和子任务；重建页面只订阅事实 |
| 用户明确退出应用 | 停止受理新 run，撤销审批，等待所有受管资源清理，再退出 Host 和 Main |
| 清理超过 10 秒 | 显示仍在清理，提供继续等待或强制退出；10 秒只是提示阈值，不是成功判据 |

### 7.3 Host 崩溃与强制退出

现有 Core 和 MCP 的进程树清理在各自工具或传输生命周期内执行，未向 Electron Main 提供可证明完整的跨 Host 后代管理接口。v0.1.0 不新增未经验证的全局 PID 扫描器，也不按陈旧 PID 盲目终止进程。

Main 在启动 Host 前，先在 userData 原子写入 `host-guard.json`，记录 hostInstanceId、启动时间和受影响工作区 ID/路径，不记录命令与秘密。新增工作区须先更新 guard 再允许其运行，记录失败则拒绝启动或新增执行。只有收到完整清理确认并观察 Host 正常退出后才能清除。它是异常退出提示，不是第二份会话数据库或跨进程工作区锁。

guard 存在但无法读取、JSON 损坏、字段非法或清除失败时，也进入恢复阻断；不能当成首次启动覆盖。人工确认后先确认旧 Host 已退出，再为新 Host 建立 guard；确认失败保持阻断，不并行拉起第二个执行 Host。单实例锁在读取和处理 guard 前取得。

Host 异常退出时，窗口保留最后已确认的展示状态，标记执行结果或清理状态未知，禁止新的 run 和自动拉起执行 Host。下次应用启动若仍有 guard，也先显示恢复提示。用户检查并结束可能残留的工具进程后，才能明确确认重新连接；这条确认记录为人工确认，不能标成自动验证通过。

重新连接创建新 hostInstanceId，从已落盘历史恢复，缺失结果按现有 OUTCOME_UNKNOWN 规则处理，绝不重放工具。确认前可查看恢复说明，但不开放模型和工具执行。若要求强制杀死整个应用后仍自动证明所有后代已退出，需要另行实现并验证 OS 级进程容器，不计入本版承诺。

### 7.4 并发边界

一个桌面应用的所有父子会话使用同一个 `WorkspaceLeaseCoordinator`，现有 FIFO、超时和取消语义不变。多个独立 CLI 进程与桌面 Host 之间没有工作区级跨进程租约；历史文件锁只能阻止同一会话被重复打开，不能阻止不同会话同时修改同一项目。

首版在工作区说明中明确这一限制，不用“单实例桌面”暗示全系统互斥。涉及同一项目的写任务应避免同时在 CLI 与桌面执行。

## 10. 验证命令与验收矩阵

### 10.1 命令接入

三个根命令均已接入；`pack:desktop` 当前只生成测试产物，不签发正式候选。实际结果及平台限制记录于阶段 B/C 与 D1 验收：

| 命令 | 约定行为 |
|---|---|
| `pnpm dev:desktop` | 先构建依赖的共享产物，再由 electron-vite 启动桌面；共享产物变更触发重建，不能继续消费旧 dist |
| `pnpm verify:desktop` | 分进程类型检查 → 桌面边界检查 → UI 依赖与主题检查 → 桌面单测 → 构建 → Playwright Electron；使用临时 homeDirectory 和 userData |
| `pnpm pack:desktop` | 先桌面验证，再隔离部署、检查闭包、生成测试包、启动安装副本并输出校验和与许可；`--dir` 仅目录，macOS 可显式 `--native-dmg`，`--no-verify` 标记调试；不发布、不上传、不创建标签 |

现有 `pnpm verify` 继续表示 typecheck → test → lint，并接入桌面静态检查和单测。需要真实窗口的 E2E 单独由 `verify:desktop` 执行，不能让普通 typecheck 成为 UI 完成依据。既有 `pnpm verify:compat`、`pnpm verify:platform`、`pnpm verify:soak` 保留。

正式候选继续运行 `pnpm verify:release-evidence --sha <最终候选完整SHA> --manifest <审核清单>`；参数语义不变。桌面专项通过 `--desktop-version` 选择性检查，需人工核对时仍可本地执行。2026-11-14 起 Release 工作流默认不执行这项检查（个人自用版口径，只打印 warning），`KPBL_RELEASE_STRICT=true` 恢复六类专项的强制校验；自动门禁（`verify` 矩阵、Node 20、compat、release 长跑、桌面 e2e、registry smoke）不受影响。

确定性 Provider 覆盖三个现役模型协议与出错分支，不需要真实密钥。真实厂商联调另需用户提供隔离测试凭证并确认费用预算；没有实测时只能记录协议夹具通过，不能宣称真实模型质量或付费 API 验收完成。

性能夹具固定为 5000 条消息、累计快照不超过 8 MiB，以及每秒 200 个增量、持续 60 秒的输出。验证事件最终序号、工具关联和最终正文精确一致；人工检查发送/停止按钮在流式期间可交互。正式长跑在预热后比较三段等长窗口的空闲态内存与句柄，后两段内存不持续增长超过首段的 20%，会话关闭后的受管进程和订阅数回到基线。该阈值是待验证的验收标准，不是当前性能数据。

在 Windows 原生终端、macOS 与 Linux 的真实进程场景继续验证 Core/MCP 清理。原 G-N20、G-ACL、G-PTY、G-TREE、G-MCP、G-SOAK 六类证据继续要求，不允许用 Electron E2E 替换这些证据。

## 11. 构建、分发与回退

### 11.1 平台产物

| 平台 | 首版架构与验收环境 | 产物 |
|---|---|---|
| Windows | x64，Windows 11 | 签名 NSIS 安装包与免安装 ZIP；ZIP 内可执行文件也须签名 |
| macOS | arm64、x64，macOS 14 或更新的受支持系统 | 各架构 DMG，签名、公证与票据装订后验证 |
| Linux | x64，Ubuntu 24.04 | AppImage、SHA256 校验和与许可文件 |

不把 arm64 Windows、arm64 Linux 或未测试的旧系统列为首版已支持平台。每个平台在本平台构建和验证，Linux CI 必须具备真实图形测试环境，不通过 `--no-sandbox` 绕过启动问题。

桌面包为 `private: true` 的应用，不进入 npm 发布清单。应用版本与工作区版本一致：在现有四个 package.json 和 CLI_VERSION 的同步基础上加入 desktop manifest，版本推演仍只使用 `scripts/release.ts`。开发阶段不手工提前升为 0.1.0。

`scripts/release.ts` 的 `packageNames` 保持三个 npm 包，分别管理需要同步版本的清单和需要上传的桌面二进制。现有 tarball 构建、registry smoke 与桌面安装包 smoke 分开，不能把 electron-builder 产物当成第四个 npm tarball。

发布分为候选生成和已审核产物发布，保留现有人工推送规则：

1. 功能、迁移说明和发布说明完成后，维护者运行 `pnpm release 0.1.0`，按现有交互创建升版提交和本地标签。以这个升版提交的完整 SHA 冻结候选，不用升版前的 SHA 验收，也不推送标签。
2. 维护者手动推送 main，等待 Verify 通过，再以冻结 SHA 手动触发 `desktop-candidate.yml`。该工作流只做源码与版本预检、原生构建、签名/公证和测试，保存不可变的候选附件，不发布 npm 或 GitHub Release，也不要求尚未产生的制品审核结论。
3. 原六类证据和八类桌面证据都在冻结 SHA 上完成。维护者对实际签名包安装验收，将平台/架构、文件名、SHA256、构建工作流 run ID、artifact ID、签名/公证信息与原始日志纳入审核清单；清单存入现有 `KPBL_RELEASE_EVIDENCE` 审核入口。
4. 证据预检通过后，维护者才推送同一本地标签。正式 Release 工作流校验标签 SHA 和完整证据，按审核清单下载同一批附件，检查来源提交、身份与逐文件哈希，不重新构建或签名桌面包。
5. 桌面产物终审通过后，继续三包 npm 发布、registry smoke 和 GitHub Release 附件上传。附件缺失、过期或哈希不同立即停止；需要重新生成签名包时重新验收并更新审核，不复用旧制品结论。

因此源码预检不能代替制品终审，测试结果也不能自动盖章为人工审核。冻结后若还要修改源码或版本，必须重新确定候选并重做对应证据；不移动已推送的正式标签。

### 11.2 外部前置条件

应用日常运行不需要 Kapibala 云账户。联网模型使用既有 Provider 凭证，本地免密端点沿用既有无密钥配置；MCP 所需命令、服务和凭证由用户配置，桌面不会代为安装。

正式分发需要维护者提供 Apple Developer 的 Developer ID 签名身份及公证凭证、Windows 代码签名身份，以及对应平台的构建资源。凭证通过受控 CI Secret 或签名服务提供，不写入仓库、诊断或构建附件。缺少这些条件只允许交付明确标记的未签名测试包。

本方案以本地参考源码和 Electron 官方文档为设计依据，未安装或运行这些参考客户端，也未验证 Kapibala 的桌面依赖、签名身份或打包链路。实现阶段须按[开发指南](../desktop-development.md)检查工具环境，当前文档不作为构建或平台通过证据。

### 11.3 回退与失败处理

首版不迁移既有 settings 和历史格式，不另建 SQLite 对话库。安全退出并保留用户数据后，可以回退桌面二进制；已执行的工具副作用不随应用回退撤销，旧 CLI 也不会因此获得配置事务锁能力。

安装器默认不删除共享配置、历史或项目文件。桌面 UI 偏好损坏时只重置该偏好文件，不触碰共享数据；异常 guard 不与普通偏好一起静默丢弃。

发布失败不得覆盖已发布的不同内容 npm 包或移动正式标签。尚未发布的构建可在同一候选上重新验证；已经发布部分产物时按既有发布脚本的内容一致性检查继续，出现不一致则停止并由维护者决定新版本发布。
