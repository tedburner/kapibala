# v0.0.4 迁移说明

状态：2026-10-07 实现完成并于同日发布（v0.0.4）。本文描述 v0.0.4 的迁移契约，验收证据见 [验收记录](../verification/v0.0.4.md)；真实付费 API 未验收。

## 默认路径与显式协议

普通启动及未显式选择角色的 `session.run(input)` 使用当前 default 绑定，内置初始默认仍为 `deepseek-flash`。不配置场景映射也能继续单模型工作；不会新增意图分类请求。SDK 可用 `selectModelRole(role)` 明确设置后续主任务选择，用 `run(input, { role })` 仅覆盖本次任务，`getModelRole()` 查询当前选择；新 Session 初始为 default。

`ModelProfile.provider` 现在表示明确的请求协议：

| provider | Provider | baseURL 之后的路径 |
| --- | --- | --- |
| `openai-compatible` | `OpenAICompatibleProvider` | `/chat/completions` |
| `anthropic` | `AnthropicProvider` | `/messages` |
| `openai-responses` | `OpenAIResponsesProvider` | `/responses` |

baseURL 统一是包含版本前缀的服务基址。自建网关保持自己的显式协议，不能凭 Claude/OpenAI 模型名或厂商族推断为原生协议。失败不会自动改端点、降级协议或重放工具。Core 仍为 Headless、运行时零第三方依赖；宿主负责解析密钥、创建 Provider 并绑定模型。

原生接入详细说明：[Anthropic Messages](../models/anthropic.md)、[OpenAI Responses](../models/openai-responses.md)、[Chat 兼容能力](../models/openai-compatible.md)。

原生 Anthropic 沿用模型默认思考行为；Haiku 4.5 不因 supportsThinking 能力标签额外开启旧式延长思考。Responses 首版不主动索要可见推理摘要，只展示服务端明确提供的摘要。

## SDK 绑定与角色

内置 Provider 提供 `binding`，描述实际 protocol、modelName、baseURL 及可选 workspaceId。Session/Router 对 Profile 与 Provider 原子配对；更换请求目标时省略 Provider 会在网络前失败，不复用旧实例。

```ts
session.switchModel(nativeProfile, 'execution', nativeProvider);
for await (const event of session.run('执行已确认的任务', { role: 'execution' })) {
  consume(event);
}
```

示例中的 Profile 与 Provider 由宿主创建，协议、模型、基址、workspace 必须匹配。相同目标的预算等配置更新可复用原 Provider；运行中不允许切换。旧自定义 Provider 的增量接口保留，实际目标未提供可比较 binding 时由宿主保证配对，不能依赖类名猜测协议。

主任务角色为 default/planning/execution/fast。显式 planning/execution/fast 缺绑定或可用密钥时请求前报错；不会回退 default。每个 run 固定绑定快照，工具续答继续使用相同角色，不按步骤号切模型。

summary 只供独立摘要，未配置时回退 default；已配置但缺密钥时保留该绑定并在摘要调用前失败，不改用默认模型。摘要模型、目的预算、usage 和错误单独归属；planning 主任务不隐式改摘要模型。角色选择不追加提示词、不进入 Plan 模式、不批准工具；权限模式和审批仍由现有机制决定。完整示例见 [场景路由](../models/scenario-routing.md)。

## CLI 入口和凭据

| 入口 | v0.0.4 行为 |
| --- | --- |
| `/model planning <id>` 等 | 保存 planning/execution/fast/summary 角色映射 |
| `/model route <role>` | 选择 default/planning/execution/fast 当前任务角色 |
| `--role <role>` | REPL/单次问答使用同样的主任务角色规则 |
| `/model <id>` | 更新当前 default 模型，同时切回 default 角色 |
| `/settings default <id>` | 只更新下次默认启动配置 |
| `/model key` | 更新当前任务角色模型的密钥 |

既有 `--model <id>` 仍配置 default 绑定；同时传 `--role planning` 时，本次主任务使用 planning 映射。缺映射时失败，不让 `--model` 覆盖显式角色选择。summary 不能作为主任务角色。

角色绑定和配置写入成功后才激活；非法命令不会进入模型历史。在 CLI 内切换/恢复历史保留当前选择；新进程默认 default，除非明确传 --role。历史不恢复旧角色、旧权限或审批缓存。非 TTY 缺少必要密钥时不挂起等待输入。

`--base-url` 与 `--api-key` 临时覆盖实际选中的主任务角色，优先于环境端点覆盖，不写入设置。`--model` 仍只设置本次 default 绑定；明确选中的角色可独立运行，未使用的 default 缺密钥不启动向导。

继续使用厂商族凭据分组；未知厂商按端点 host 隔离。同组只保留一份密钥，更新当前角色密钥后刷新所有相关绑定，避免一个角色继续使用旧凭据。输出及错误不显示密钥。

## 配置目录升级

目录版本随本次内置协议变更递增；已存内置 Claude Profile 改为 anthropic，已存内置 OpenAI Profile 改为 openai-responses。Profile ID、API Key、defaultModel、角色引用及合法用户输出上限保留；没有删除 ID 时不添加无理由重定向。

用户没有保存的内置 Profile 仍由代码清单提供，不写入全局用户文件。用户已存合法 `maxOutputTokens` 是覆盖值，缺失时从内置目录继承默认；自建网关 Profile 的显式协议、端点和模型不因厂商推断改变。

配置写入基于原始全局设置。`loadSettings()` 是内置与用户层合并后的读取视图，不可整份写回；CLI 全局设置写入路径使用 `loadGlobalSettingsForWrite()` 等安全入口。损坏/非法全局文件中止写入，不能用空骨架覆盖；写入失败保持原文件和有效内存状态并报告诊断。

升级前保留用户设置和原始会话备份。按同厂商族解析的密钥共享规则继续生效；不把版本升级视作新增账号权限或已确认所有原生端点可用。

## 输出预算与统计

`ModelProfile.maxOutputTokens` 必须是正整数，表示包含思考/推理的总输出预算。兼容 Profile 缺省仍用 4096；内置原生 OpenAI 推理建议 32768，Claude 5 建议 16384。用户更低值与已知模型/窗口限制共同约束有效值，非法预算在请求前失败。

有效值同时用于 ContextBudget 输出预留、请求准备和协议字段：Anthropic `max_tokens`，Responses `max_output_tokens`，Chat 按显式能力选择 `max_tokens` 或 `max_completion_tokens`。不能继续将实际原生请求较高上限配成旧 4096 预留，也不能把预算称为可见文字配额。

摘要目的缺省上限仍为 4096，再受摘要 Profile 更低值及窗口限制约束；主任务 32768 不会扩大摘要目的预算。摘要同样拒绝工具尝试、拒绝结果与异常终态。

摘要请求仅在兼容 Chat 使用原有 `temperature: 0`；原生协议沿用模型采样默认，避免把兼容接口的采样参数强加给原生推理模型。

上下文窗口、usage、错误和日志使用实际角色绑定。没有当前请求 usage 时标注估算，不使用上一步真实数冒充当前消耗，不将私有状态当零 token。密文字符长度不是精确 tokenizer 结果，未知实际费用继续保持未知。

Anthropic promptTokens 包括未缓存输入、缓存读取和缓存创建；cachedPromptTokens 只计缓存读取。Responses output_tokens 已含推理，不能重复累加。预算默认值不表示服务端必定耗尽该数量，也不构成费用估价。

## ModelEvent 和历史消费者

新增的 `message_stop.finalContent` 是完整且有序的 canonical 响应。Loop 优先使用它落盘并提取工具；同时存在的增量只展示，工具、assistant 和 usage 不重复处理。旧 Provider 可继续提供合法增量与完整 message_stop。

思考展示新增 `thinking_block_start`、`thinking_block_stop` 和可带 blockId 的 `thinking_delta`。旧宿主仍可消费 thinking_delta 文本；需要块边界的宿主使用稳定 blockId。签名、脱敏 thinking 和加密 reasoning 不送入可见文本事件。

ContentBlock 联合类型扩展了 `redacted_thinking` 与受控 `provider_state`，thinking 可带 origin，text/tool_use 可带 protocolMeta。使用穷尽 switch、JSONL 校验器、摘要序列化器和自定义日志的 SDK 宿主需要显式处理这些新类型；不要把未知块直接拼成文本或序列化进摘要请求。

所有协议的 `assembleToolResults()` 都返回 canonical `role: 'tool'` / tool_result。Anthropic user-tool_result 和 Responses function_call_output 仅是请求格式，不得写为原始历史角色。恢复缺失结果仍标记 OUTCOME_UNKNOWN，不重放工具。

执行前要求合法终态、整批调用唯一身份、完整 JSON 对象参数及工具输入边界。一个坏调用使整批失败，畸形 JSON 不以 `_raw` 执行。截断、过滤、缺终态和中断均不能触发响应内任何工具；已进入历史的真实工具事务仍须先闭合再退出。

Chat 默认要求合法 finish_reason 与 DONE；只有已验证省略 DONE 的网关可显式配置 `chatCapabilities.requiresDone: false`，仍必须有合法终态。Responses 要求 completed 及完整 Items，拒绝作为明确可见回复，拒绝混合工具失败，只有 commentary 无工具/最终回答失败。

## 鉴权头与截断语义（对照审查修订）

Anthropic 请求同时发送 `x-api-key` 与 `Authorization: Bearer`：官方 API 以 `x-api-key` 为标准鉴权头，部分只识别 Bearer 的网关也能接入；CLI 向导探测使用同一组头。自建宿主不应假设两者互斥。

输出截断由 Loop 统一裁决：Chat（`finish_reason: length`）与 Anthropic（`max_tokens` 等）把截断交付到 Loop——无工具的截断文本按最终回答交付并携带 `finishReason: 'length'`，有工具的整批拒绝执行；Provider 层不再把 Chat `length` 提前收口为错误，依赖旧行为的消费者应改为检查 `finishReason`。Responses 的 `response.incomplete` 仍按不完整失败（对齐 codex）。Anthropic 的 `pause_turn` 表示服务端工具循环暂停，本版不支持其续答，明确返回 `MODEL_INVALID_RESPONSE` 并保留 `providerCode: 'pause_turn'`；不标记任务完成、不调度该响应中的客户端工具，也不自动重发请求；其他未知停止原因携带原始 `providerCode` 明确失败。

跨协议投影到 Responses 时，assistant 历史（含降级后的无来源文本）一律以 `output_text` 回传，`input_text` 仅用于 user 输入；业务 call_id 超出安全形状时使用确定性别名并同步映射调用与结果。

## 私有状态、摘要与新 run

原生内容来源包含版本、协议、模型、Profile、run 和端点/workspace 范围。签名、脱敏状态和加密 reasoning 仅用于同 run、同协议、同模型、同 Profile、同端点且仍有效的工具续答；缺来源的旧 thinking 保留可见语义，不伪造合法签名或密文。

换模型、换端点、换 workspace、恢复后新 run 或未知上下文时，独立请求投影剔除不适用私有状态；原始历史保留。可见思考可降为普通文字。Responses 普通 message phase 在同协议/模型/端点下跨 run 保留，call_id 与源 Item ID 分开；原始参数串和 Item 顺序保持，跨协议不冒用旧身份。

摘要输入排除签名、密文和私有 Item 元数据，只用可见文字及工具语义。摘要或改写后的内容不得保留旧来源身份。同次 Anthropic 含签名工具链冻结系统、工具和签名前历史前缀；动态环境锚点固定，Hook/压缩破坏前缀时停止续答，预算不足不改写该前缀强行继续。

消费者取消或提前结束迭代时等待 reader 与在途工具清理，闭合并落盘已执行结果后再释放 Session 锁；完成工具结果保留真实状态。

## 降级到旧版的限制

旧版 0.0.3 不理解新的 provider 值、来源/Item 元数据和 provider_state 等块，不能承诺直接读取升级后的所有设置或历史。旧版读取失败不能通过删除私有块、工具结果或改写原始 JSONL 解决。

需要回退时使用升级前备份和相应版本的独立配置/会话副本，保留新版原始记录供后续恢复。旧版兼容性、真实 Anthropic/OpenAI 权限及实际模型质量需要独立验证；本轮模拟测试不提供这些保证。发布准备与未验证项见 [发布说明草稿](../releases/v0.0.4.md) 和 [验收记录](../verification/v0.0.4.md)。
