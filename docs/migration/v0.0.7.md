# v0.0.7 迁移说明

实现、本地与验收于 2026-10-16 完成并随 v0.0.7 发布；包版本与 CLI_VERSION 为 0.0.7。设计基线见 [设计说明](../superpowers/specs/2026-10-15-v0-0-7-session-multi-agent-design.md)，验收记录见 [验收记录](../verification/v0.0.7.md)。

## 工作区身份与路径沙箱（破坏性变更）

1. **显式工作区根**：
   `AgentSession`、`SessionManager` 与 `ContextManager` 完全废除了隐式 `process.cwd()` 与 `.` 兜底。构造 `AgentSession` 必须显式传入 `workspaceRoot` 绝对路径（或合法的 `rootDir` 兼容别名），否则抛出 `WORKSPACE_ROOT_REQUIRED` 错误。
   - CLI 在启动初期（REPL / 单次执行）即捕获 `process.cwd()` 并解析为真实工作区根。
   - Core 架构门禁（`check-host-boundary.ts`）已严禁 `packages/core/src` 内部出现非显式的 `process.cwd()` 调用。

2. **会话级沙箱与物理规范化**：
   - `PathSandbox` 废除旧有的全局模块级单例缓存，重构为会话持有的独立沙箱实例；
   - Windows 项目路径身份与边界规范化统一采用 `fs.realpathSync.native`，杜绝 8.3 短文件名与大小写失配；
   - 引入 `WorkspaceLeaseCoordinator`（进程内单例 `sharedWorkspaceLeaseCoordinator`），在单工作区多任务并发写入时实现细粒度写租约互斥，任务取消或异常退出时安全释放。

## Schema v2 会话存储与升级

1. **Schema v2 Envelope 日志格式**：
   会话 JSONL 日志格式升级为 Schema v2：
   - 分离物理时序与因果结构：记录包含物理严格单调递增的 `seq`、前驱校验哈希 `prevRecordId`；以及因果父节点 `parentId` 与所属分支 `branchId`；
   - 支持全局控制记录（如分支切换、状态归档等，`parentId: null`）；
   - 解耦三大版本号：`logRevision`（物理追加版本）、`branchLeafId`（分支当前活动叶子）、`contentRevision`（因果消息变更版本），保障 sidecar 增量更新与物理连续性。

2. **只读保护与安全副本升级**：
   - 存量 Schema v1 会话文件保持严格只读，可供目录扫描与只读回放；
   - 写入或续答 v1 会话自动创建（或幂等复用）`_v2` 升级副本，副本 Header 以 `upgradeIdentity` 记录来源身份；`SessionManager.open` 与 `continueRecent` 默认启用该升级，原 v1 日志文件完整保留，杜绝原地损坏历史数据。

## 持久分支与投影回溯

1. **多分支与因果投影**：
   - 支持多分支操作：`selectBranch`（切换活动分支）与 `createBranch`（分叉创建新分支）；
   - `buildSessionProjection` 算法沿 `parentId` 因果链追溯出当前分支合法的线性消息视图；
   - 严格的分支分叉约束：分叉点必须处于完整交互边界，未闭合的工具事务（`tool_use` 缺少 `tool_result`）严禁分叉，抛出 `UNCLOSED_TOOL_TRANSACTION_FORK` 错误。

2. **分支投影与独立会话导出**：
   - `buildProjection` 沿 `parentId` 因果链追溯出当前分支合法的线性消息视图；
   - `forkSession`：支持将当前分支的有效线性消息投影导出为全新独立会话，并在 Header 中记录来源 Session ID 与分叉切点；导出的历史消息带 `importedFromFork` 标记且不计入新会话费用，新会话独立计费、与原会话完全解耦，同时剥离来源副本的 `upgradeIdentity` 以防劫持 v1 升级查找。

## 后台多智能体运行时（AgentRuntime & Subagents）

1. **任务树调度与状态机**：
   - 引入 `AgentRuntime` 后台任务调度器，统一管理层级子代理状态机：
     `preparing` → `accepted` → `running` → `waiting_children` → `completed`（或 `failed` / `cancelled`）；
   - 内置注册四大子代理管理工具（需 `agent:spawn` 权限声明）：
     `spawn_agent`（派生子任务）、`list_agents`（列出子任务状态）、`wait_agent`（等待任务完成）、`cancel_agent`（取消任务树）。

2. **启动事务即刻闭合**：
   父代理调用 `spawn_agent` 后，工具执行层仅需登记任务并回填 `agentId`，即刻生成 `tool_result` 闭合工具事务，父代理无需同步阻塞等待即可继续自身工作。

3. **终态通知耐久化与显式投递**：
   - `SubagentOutbox` 以追加日志（`notification` / `ack` 两类记录）耐久保存子任务终态与执行摘要，构造时读回日志，进程重启后未确认通知仍在；单条写入失败静默忽略，不影响任务终态；
   - `SessionInbox` 把通知转换为带 `subagentSource` 标记的背景消息写入父会话历史，按 `eventId` 幂等去重，同实例并发 consume 合并为单次写入；
   - 投递入口是 `/agents collect <id>`（显式拉取），来源分支与当前活动分支不一致时拒绝写入并提示先切换分支；**空闲自动唤醒投递本版未接入**。

4. **限额管理与子会话授权边界**：
   - 容量硬限额：默认限制单会话最大深度 3、活动任务槽位 4、运行时 8、累计 16、每子代理步数 15、超时 5 分钟；达到最大深度时自动剥夺子代理 `spawn_agent` 工具权限以防止递归爆炸；
   - 子会话按 `deriveChildPolicy` 求交出的 `effectivePolicy`（模式、工具白名单、预算）独立运行，历史写入自身独立会话文件；`modelOverride` 在受理前校验 profile 是否存在，无效值直接拒绝；
   - 子会话未继承父终端审批通道：`Approval` 模式下缺少通道时敏感工具按 `deny_once` 保守拒绝，不存在静默放行；
   - 本版不提供跨任务树 Token 分层账本（`ownUsage` / `descendantUsage` / `summaryUsage` 聚合与整树预算校验）与父终端审批冒泡队列，二者排入 v0.0.8。

5. **Worktree 物理隔离（本版未交付）**：
   - `spawn_agent` 的 `isolation: 'worktree'` 在受理前抛出 `CONFIG_INVALID`（「当前环境暂不支持 worktree 物理隔离模式」），调用方必须改用 `inherit`；
   - 不提供 Git Worktree 独立执行目录、脏基线检查（原计划 `WORKTREE_DIRTY_BASE`）与安全回收能力，`WorkspaceIsolationAdapter` 已从本版代码中移除，整项能力排入 v0.0.8。

## CLI 命令与交互整合

1. **命令扩展**：
   - `/history`：支持 `--tree`（因果分支树展示）、`--search <query>`（跨项目全文检索）、`--all [page]`（跨项目全局会话漫游）、`--agents`（后台子代理任务树）；
   - `/branch`：无参查看所有分支、`switch <branchId>` 切换活动分支、`create <recordId> [name]` 基于历史记录分叉；
   - `/fork [title]`：将当前分支的历史导出并原子切换至独立新会话；
   - `/archive`：`list [page]` 列出已归档会话、`<id>` 逻辑归档指定会话（活动中会话禁止归档）、`restore <id>` 恢复已归档会话；
   - `/agents`：列出子任务树、`show <id>` 查看详情、`cancel <id>` 取消任务、`collect <id>` 收集结果（来源分支不匹配时给出友好提示）。

2. **终端体验增强**：
   - 状态底栏：紧凑展示运行中子代理状态行（如 `🤖 子代理: 1个运行中`）；
   - 详情折叠：`Ctrl+O` 快捷键展开完整多智能体任务状态树；
   - 秘密输入保护：在密码与 API Key 输入期间，自动缓冲后台任务产生的任何异步输出，待用户输入完毕后安全刷新，杜绝终端乱码与密钥泄露风险。
