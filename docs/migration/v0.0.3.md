# v0.0.3：历史会话与上下文管理

本版直接重构 Core 内部目录，公开 SDK 符号保持兼容。历史会话、当前模型上下文和运行日志是三种独立数据：会话保存原文，上下文保存有效投影及检查点，日志只记录脱敏运行事实。

## CLI 用法

普通 `kpbl` 和 `kpbl -p "问题"` 默认新建独立会话。`kpbl --continue` 继续当前项目最近有内容的会话，没有历史则新建并提示。`kpbl --resume <id>` 支持完整 UUID 或唯一前缀；不存在、歧义、被其他写者占用或正文损坏时明确失败，不创建替代会话。`--continue` 与 `--resume` 互斥。

| 命令 | 行为 |
|---|---|
| `/history [page]` | 按项目列出历史，每页 20 项；浏览不更新最近活动时间 |
| `/resume [id]` | 指定 ID 续答；TTY 无参数使用分页选择，非 TTY 只列历史和用法 |
| `/new`、`/clear` | 保留旧文件，切换到新会话 |
| `/rename <title>` | 保存完整标题尾部，转义控制字符并限制长度 |
| `/context` | 显示输入预算、保护范围、剪裁、检查点及估算来源；TTY 显示比例条 |
| `/compact` | 空闲时手动摘要旧完整交互，不增加用户任务、不执行工具 |
| `/model [id]`、`/model key [id]` | 切换当前模型或秘密输入更新密钥；管道无参数只列模型 |
| `/settings`、`/config` | 查询配置；`default <id>` 设置下次启动默认模型，`setup` 打开向导 |
| `/permissions [mode]`、`/mode` | 查询或切换权限；FullAccess 必须显式确认 |
| `/status`、`/logs [count]`、`/instructions` | 只读查询当前状态与既有诊断 |
| `/help [command]`、`/exit`、`/quit` | 查询统一命令目录，或取消并等待清理后退出 |

`/model setup` 兼容 `/settings setup`；`/model set-default <id>` 兼容 `/settings default <id>`。默认模型写入成功后才更新内存，不隐式热切换当前模型，不把完整内置模型清单物化进用户配置。

菜单使用同一输入协调器：按编号选择并 Enter 确认，Esc/Ctrl+C 取消菜单；EOF 结束输入。密钥、审批和菜单答案不会作为普通消息发送给模型。任务、摘要、切换或清理期间拒绝变更命令；只读命令读取快照。取消任务后仍需等清理完成才能切换。未知 Slash 和非法参数不进入模型，也不落为用户消息。

## 存储与项目归属

目录为 `~/.kapibala/sessions/<project-key>/`。项目键是规范化真实工作树根的 SHA-256；同工作树子目录共用历史，不同 Git worktree 独立。非 Git 项目以真实 cwd 分组。目录移动会产生新项目键，首版不自动跨项目搬迁或检索。

每个会话使用 `<timestamp>_<conversationId>.jsonl` 正文、`<conversationId>.meta.json` 可重建列表缓存和 `<conversationId>.lock/owner.json` 单写者锁。缓存记录标题、消息数、创建/活动分支、最近模型和正文版本；缓存失效时逐行重建，有效缓存列表不读取正文。缓存写入失败只诊断，不撤销已保存消息。

恢复不执行 checkout，不改变 cwd，不重放工具，不恢复旧审批允许缓存。模型和权限来自当前宿主配置；旧模型仅作元数据展示。目标加载成功才发布新活动引用；旧插件清理失败时保留受管句柄与写锁，不回滚到已销毁对象。

锁拥有者包含 PID、随机 nonce 和创建时间。仅能确认进程死亡且复查身份未变时回收；不按超时时间抢占，不把 EPERM、损坏 owner 或 PID 复用当作死亡。遇到未知锁，应先确认没有运行进程、保存会话备份，再人工处理；正常退出会先等工具、模型/摘要和存储清理。

旧 cwd/根目录 `.kapibala/history.jsonl` 按真实来源与内容哈希幂等导入，标为“旧历史导入”，源文件保留。导入先写临时正文并 fsync，源快照未变化才独占安装；安装身份写在头部，因此缓存丢失或中途退出不会重复导入。源正在变化则延期；无法导入时报告诊断，不伪造成功。

## 版本化记录与 canonical 规则

Envelope 为 `schemaVersion: 1`、`type`、UUIDv7 `recordId`、`timestamp`、`parentId` 和 `payload`。`parentId` 当前表达追加前驱，为后续 DAG 留接口。首条必须是 `header`，包含 conversationId、projectRoot、initialCwd、createdAt 和可选 gitBranch/importIdentity。

消息记录为 `message`，payload 保留 role/content/timestamp、稳定 id、interactionId 和终态。状态记录包括 run_started/run_finished、message_state、history_repair、usage、context_pruned、checkpoint、compaction_state、title、reset、legacy_import。运行实例、用户交互、内部步骤与模型尝试分开标识；恢复按 attempt 身份幂等记账。

新工具调用记录可选 `executionRoot`，由执行器写入本次绝对工具根目录，仅用于历史路径解析，不恢复旧授权。同一会话从不同子目录续答后，摘要仍按每次调用的执行目录记录文件事实。旧记录缺少目录证据时保留原相对路径并标明基目录未知，不按项目根猜测；旧检查点若因此无法通过文件事实校验，则回退原始历史。

所有正文写入串行并 fsync，写失败后拒绝该写者继续追加；正文变化未经当前写者验证时也拒绝追加。只有最后 JSON 残片可隔离为 `.corrupt-*` 后修复，缺少末尾换行会补齐；中部损坏、重复身份、断裂前驱或未知版本拒绝加载。读取以 64 KiB 分块逐行解析；加载选中会话仍需将其原始消息保留在内存，首版不做单会话正文归档。

规范化只产生独立请求视图，不修改原始消息：合并连续纯文本同角色消息，跳过空或非完成 assistant；工具结果仅满足紧邻 assistant 的调用集合，重复、迟到和孤儿结果不进入视图；重复调用 ID 明确失败。缺失结果保留 `OUTCOME_UNKNOWN`/`after_user_action`，通过 history_repair 幂等落盘并插回原工具事务，不伪造成功。

run_started 缺少终态视为中断。旧历史仅在闭合事务后有非空最终回答时推断成功；空回答、截断回答和失败消息不能作为成功交互。当前任务、最近成功完整交互及其后的失败/中断尾部完整保护；没有成功历史时保护全部。

SDK 的 `reset()` 仍保留清空语义，通过持久 reset 边界同时废弃旧正文投影、摘要、剪裁和失败状态；受管 CLI `/clear` 的新建语义与它不同。

## 预算和两级压缩

窗口 C 未知时使用保守 32K 控制预算。输出预留 R 为 `min(4096, floor(C × 0.125))`，安全余量 S 为 `max(128, ceil(C × 0.05))`，输入硬预算 B 为 `C − R − S`，触发阈值为 `0.85B`，目标为 `0.65B`。估算覆盖最终 system、tool schema、消息与协议开销，并在 model:before Hook 之后执行；真实 usage 仅校准相同请求/模型，缺失 usage 不推断为零。

一级只剪裁保护范围外、已完成旧交互中成功的内置 read_file/glob/grep 结果正文，保留调用意图、结果身份和完整事务。失败、未知、命令、写入和插件结果不剪裁。候选必须降低占用且满足硬预算，先提交 context_pruned 再激活，原文始终保留。剪裁后低于触发阈值则不调用摘要模型；否则尝试二级摘要，失败时保留有效剪裁。

二级摘要走 summary 路由，无配置则回退当前 default。不执行主 Loop、Hook 或工具。输入为旧有效摘要加新增原始完整前缀；工具结果保留总计 2000 Unicode code point 首尾片段及省略标记，整请求另受摘要模型预算约束。批次以完整交互为单位，整次操作最多 4 次调用、120 秒。无法拆分的单个交互超限则失败，当前任务不作内部摘要。

保护范围外、有运行终态来源且工具事务闭合的失败/中断旧轮次也可参与二级摘要，不将未知写入视作成功；缺少终态证据或工具结果时保守保留。一级剪裁仍仅针对成功完成旧轮次。

摘要严格 JSON 字段为 schemaVersion、goal、constraints、decisions、completedWork、pendingWork、references、unknownEffects；来源引用必须是真实消息 ID。文件观察由实际调用和结果确定性提取到 checkpoint.details，区分读、修改、失败和未知，滚动合并且限制大小；恢复复算事实，不相信模型编造的文件列表。

检查点包含策略版本、前驱、sourceDigest/范围、首条保留消息、摘要、文件观察、模型及 usage。来源、完整交互边界、保护范围、输出完成原因和实际缩减都通过后，fsync 提交再激活。恢复逐条验证检查点和剪裁链，坏候选回退到上一个已验证投影。摘要是历史背景，不是系统指令或授权。

同一失败 fingerprint 不重复自动摘要；连续 3 次自动操作失败暂停自动摘要，剪裁仍可工作。新输入改变 fingerprint，但不清零失败计数；有效配置变化开启新周期，成功提交清零，取消不计失败，手动失败不解除暂停。状态保存失败与模型失败分开处理。

Provider 只有明确超限错误且未出现任何文本、思考或工具调用时才允许压缩后重发一次；请求未变化不重发。普通 HTTP 400、鉴权/网络失败、部分输出及工具执行不进入这条重发路径。受保护内容加固定请求超过 B 时明确停止；应选择更大窗口或拆分任务，首版不承诺超长单任务无限续跑。

## SDK 接入与分层

```ts
const manager = new SessionManager({ cwd: process.cwd() });
const handle = await manager.create(); // 或 manager.open(id)、continueRecent()
const session = new AgentSession({
  defaultProfile, defaultProvider,
  store: handle.store, conversationId: handle.conversationId,
  rootDir: process.cwd(),
});
try {
  await session.init();
  for await (const event of session.run('继续工作')) consume(event);
} finally {
  await session.destroy(); // 等候清理，失败时保留 handle 供后续收口
  await handle.release();
}
```

`getHistory()` 返回原始历史的独立快照；`getContextHistory()` 返回有效投影。无 Store 时可以内存压缩；原自定义 MessageStore 继续工作，但没有 appendRecord/loadState 能力时禁用持久压缩并报告诊断，不往旧正文里混写状态。旧 JSONLMessageStore 保持可用并保留可选身份字段，受管 CLI 使用 SessionStore。

事件新增 session_resumed/session_switched、compaction_start/finish/failed、context_budget_exceeded。运行日志关联持久 conversationId 和运行实例 sessionId，失败分类不含模型输出或 Provider 响应正文。主任务与摘要 usage 独立统计，失败摘要也记实际消耗；只有提交成功才计摘要成功。缓存命中量仅在 Provider 明确提供时展示。

`/status`、`/context` 读取快照，不调用 Hook/Provider；静态估算、过期快照、未知动态内容、实际 usage 分别标注。系统环境前缀固定，精确时间放在请求动态后缀，不落为原始用户消息。字节稳定不等于保证缓存命中。

请求底栏优先展示最近一次请求的真实 prompt usage；流中断或 Provider 未返回 usage 时，使用该次最终请求的预算估算，`ContextUsage.estimatedUsage` 为 true，终端明确显示“估算”。不借用前一步 usage，也不将估算计入 Token 消耗；未收到实际消耗的请求保持 `usageKnown: false`。请求准备前失败且无当前估算时仍显示未知。

DeepSeek 官方端点的 OpenAI 兼容适配完整回传 assistant `reasoning_content`，包括此前非工具轮次；其他端点默认不发送该扩展字段。SDK 自建兼容网关可通过 `OpenAIProviderOptions.replayReasoningContent` 显式开启，CLI 共用厂商族识别。流中断按模型错误码和受控 `transportCode` 诊断，不记录原始连接异常或自动重放工具。

模型失败统一为 `ModelError` / `ModelErrorInfo`：分类、HTTP 状态、服务端码/类型、连接码、失败阶段、脱敏原因及重试策略。协议适配器提取服务端信息，主任务 `error.modelError` 与 `RunMetrics.failure` 传递同一说明；摘要 `compaction_failed.modelError` 复用该契约，失败保留最近有效投影。CLI 展示具体原因和操作建议，底栏汇总主任务或摘要失败。日志只保留分类标识、状态和阶段，不落盘服务端报错正文；非法摘要或响应不回显模型生成内容。当前已接入 OpenAI 兼容协议，未来原生协议沿用此契约，不代表原生协议已实现。

实现目录为 types/errors、runtime、context、capabilities、models、extensibility；内部旧目录直接搬迁，公开 index 导出不变。runtime 通过共享 RequestPreparation 契约调用预算能力，不依赖具体 ContextManager/Store；架构门禁同时检查 Headless 和该依赖方向。未承诺兼容内部源码深层路径，宿主请从包的公开入口导入。

验收入口：`pnpm verify`、`pnpm dev --no-start`、`node scripts/v0.0.3-platform-check.mjs`。真实模型质量样本与平台结果见 [验收记录](../verification/v0.0.3.md)，结果未知的项目不会标为通过。
