# v0.0.5 迁移说明

工作区实现与本地验收于 2026-10-11 完成，尚未发布；包版本与 CLI_VERSION 仍为 0.0.4。使用入口见 [技能指南](../skills.md)，证据见 [验收记录](../verification/v0.0.5.md)。

## CLI 与配置

默认启用技能。项目来源为 Git 根（无 Git 时为当前目录）下的 `.kapibala/skills`、`.agents/skills`，全局来源为 home 下的同名目录。项目技能需要信任真实项目根；只有技能而没有 settings 时也要询问。非交互环境排除未信任项目技能，仍可使用全局技能；未信任项目 settings 的既有启动规则继续适用。

新增 `skills: { enabled?: boolean, disabled?: string[] }`。缺省开启；非法类型拒绝。全局与已信任项目配置按 enabled 逻辑与、disabled 并集合并，项目只能收紧。信任写入原始全局配置，避免把合并后的内置模型清单写入用户文件。

`/skills [query]` 检查元数据与诊断；`/skill <name> <task...>` 显式调用并保留任务空白、引号和换行。技能名支持 Tab 补全。关闭技能仍可检查目录；`--disable-shell` 不关闭文件技能。

过程输出缺省为 summary，所有回答文本仍完整流式显示。TTY 使用 Ctrl+O 切换本轮过程详情，菜单、审批及密钥输入期间禁用。自动化日志需要完整公开过程时使用 `--output-detail detailed`；非 TTY 无 ANSI，detailed 流不受 1 MiB 展示缓存上限限制。debug 仍独立输出到 stderr。

## SDK 与持久化

AgentSession 的 `skills.roots` 必须由宿主显式提供，Core 不读取 home 或自动信任项目。项目根须声明 `trusted: true`，可提供 `boundary` 限制物理边界。通过 `getSkills()` 获取快照，`runSkill(name, task, options?)` 使用同一个运行锁、权限与事件生命周期。已有不提供 skills 的宿主无需改动。

TextBlock / ToolResultBlock 增加可选 `skillSource` v1，JSONL schema 与记录类型不变；内置 Store 保留来源。自定义 Store 应保留可选字段，丢失字段时仍保留文本，但不能恢复技能事实或资格。没有 Store 的宿主通过完整内存事务提交，skill_loaded 的 persistence 为 memory。

历史来源仅记录事实。恢复、跨项目续答、新任务、取消及切换都不继承活动技能或审批授权；每次新运行重新发现、核验与激活，不重放脚本。正文移出摘要投影后显示 requires_reload，不能用旧调用记录代替正文。

## 执行边界

Frontmatter 是有界 YAML 子集，支持范围与容量见技能指南。fork/hooks/动态 shell 等执行扩展明确不可执行。allowed-tools 只收紧白名单，多个技能取交集；FullAccess 与审批缓存均不能绕过硬拒绝。控制工具仍受宿主 deny/ask 裁决。

load_skill 的 pending 限制立即约束同批后续工具；资源资格在完整正文消息提交及审计完成后生效。read_skill_resource 仅允许本轮已提交技能包内的相对 UTF-8 文本，单页最多 64 KiB，以 nextOffset 接续；普通 read_file 的工作区沙箱不扩大。脚本仍按既有目标识别及审批规则执行。

正文、来源信息与序列化开销共同计入输入预算；完整正文放不下时拒绝加载。文件或根发生变化需开始新运行。错误 retryPolicy 是调用方提示，加载器不内部循环重试。
