# v0.0.10 迁移说明

v0.0.10 是稳定整合版，不新增产品能力面，但收口了 v0.0.9 的并发默认值、客户端结果形状与 runner 装配。本版有 9 处公开差异，分别覆盖类型/接口种类、导入、并发、客户端运行时及 runner 装配，**不是"完全兼容"的小版本**。完整盘点见 [SDK 兼容性说明](../sdk-compatibility.md)。

| 变化 | 影响 | 迁移方式 |
|---|---|---|
| `SessionConfig` 至少提供一个根字段，`interface` 改为联合 `type` | 缺少两字段的调用、接口继承/合并用法需要调整；`rootDir`-only 保持有效 | 优先 `workspaceRoot`；兼容 `rootDir`；扩展配置改用交集或 `SessionOptions` |
| 删除 `sharedWorkspaceLeaseCoordinator` 导出 | 导入旧单例的 SDK 代码需要调整 | 显式创建 `WorkspaceLeaseCoordinator` 并注入需要共享的会话 |
| 缺省协调器改为会话独占 | 独立 SDK 会话不再暗含全局串行关系 | 同一业务宿主持有并注入共享实例 |
| `LocalClient.call()` 结果具体化 | 依赖宽泛结果做不安全索引的调用需收窄类型 | 使用方法结果类型；cursor 快照按分块结果处理 |
| 显式 cursor 从误重组分支改为原始续块返回 | 运行时返回形状/失败路径变化，不只是类型收窄 | 读取正文用无 cursor 调用；手动分页处理 chunk/cursor |
| attach 中途取消、重组或缓冲回放失败明确拒绝并关闭整个连接 | 同一连接的其他控制会话也会断线收口；不再允许异步 `close` 后仍返回快照 | 新建连接后按需重新 attach，不重发写任务；独立控制需求使用独立连接 |
| `SpawnContext` 必须携带协调器，runner 接收第三个运行上下文；CLI runner 工厂协调器必填 | 自定义 `prepareSpawn`/runner 装配及 CLI 工厂调用需更新 | 注入父 Session 实际实例，消费 runner 上下文，不序列化该实例 |
| `LocalTransport` 增加必填 `setLimits(limits: TransportLimits): void` | 自定义传输实现需支持握手后收紧帧与发送队列预算 | 导入公开 `TransportLimits`，修改实现；缺少能力时连接失败，不静默使用默认值 |
| 清理异常改用类型化 code | 部分原先退化为 `INTERNAL_ERROR` 的清理失败会细化到既有 `SESSION_CLEANUP_FAILED` | 调用方按既有业务码处理可重试关闭，不将取消请求失败理解为任务已停止 |

## 1. 会话根字段

```ts
// v0.0.9：允许两个根字段都不填，运行时按 process.cwd() 兜底
new AgentSession({ defaultProfile, defaultProvider });

// v0.0.10：至少一个绝对根，优先 workspaceRoot
new AgentSession({ workspaceRoot: '/absolute/project', defaultProfile, defaultProvider });
// 兼容旧写法：只给绝对 rootDir 仍然有效
new AgentSession({ rootDir: '/absolute/project', defaultProfile, defaultProvider });
```

- 两者都缺失：类型层拒绝；JS 绕过类型仍抛 `WORKSPACE_ROOT_REQUIRED`。
- 两者同时提供但物理身份冲突、或提供相对路径：抛 `CONFIG_INVALID`，不静默选择其中一个。
- `packages/core/src` 不再读取 `process.cwd()`（架构门禁拦截），SDK 调用方必须自己给出绝对路径；Windows 上的项目身份比较使用 `fs.realpathSync.native` 语义。
- Session 只读输出 `workspaceRoot` / `rootDir` / `executionCwd` / `projectKey` 保持规范化派生语义。

`SessionConfig` 由 `interface` 变为交集联合 `type`，会影响 `interface X extends SessionConfig`、`class X implements SessionConfig` 与模块声明合并：

```ts
// 旧写法（本版不再可编译）
interface MyConfig extends SessionConfig { tenant: string }

// 新写法一：交集类型
type MyConfig = SessionConfig & { tenant: string };

// 新写法二：扩展非根选项接口后再与根联合相交
type MyConfig =
  & SessionOptions
  & { tenant: string }
  & (
      | { workspaceRoot: string; rootDir?: string }
      | { workspaceRoot?: never; rootDir: string }
    );
```

`resolveWorkspaceContext` 的宽输入接口保留，用于处理 unknown、旧式配置与预期的运行时失败，不要为它另写一套校验。

## 2. 写租约：从全局单例到宿主持有

```ts
// v0.0.9：模块级单例，所有会话隐式共享
import { sharedWorkspaceLeaseCoordinator } from '@kiturone/kapibala';

// v0.0.10：显式创建并按宿主注入
import { WorkspaceLeaseCoordinator } from '@kiturone/kapibala';
const coordinator = new WorkspaceLeaseCoordinator();
const a = new AgentSession({ workspaceRoot: root, ..., leaseCoordinator: coordinator });
const b = new AgentSession({ workspaceRoot: root, ..., leaseCoordinator: coordinator });
```

不注入时的语义变化必须确认：每个会话自建独占协调器，同一进程内两个 SDK 会话对同一工作区的写操作**不再互斥**。需要串行就注入同一实例；可编译示例见 [examples/shared-lease.ts](../../examples/shared-lease.ts)。

不做的事：不提供新的全局开关、不在模块顶层创建协调器、不通过静态属性或服务定位器恢复共享，也不增加第二套文件锁。租约仍按 native 物理工作区分桶，写分类、FIFO 排队、取消与 finally 释放沿用现有执行器；外部 MCP 未明确只读的调用继续进入写租约。跨进程（直接 CLI 与 daemon 的不同 conversation）本来就不互斥，本版不改变。

## 3. 子代理 runner 装配

三处必须同步改动，缺任何一处都会在运行时以 `CONFIG_INVALID` 拒绝，而不是静默降级：

1. `SpawnContext.leaseCoordinator` 改为必填；缺失时在受理、持久副作用与启动子会话之前失败。
2. `SubagentSessionRunner(record, signal, context)` 增加第三个参数 `SubagentRunnerContext`，`context.leaseCoordinator` 是父会话实际实例。创建子会话必须注入它。
3. `CliSubagentRunnerOptions.leaseCoordinator` 改为必填，工厂缺参在创建 Store 之前失败；执行时与第三参数做身份核对，不一致以 `CONFIG_INVALID` 失败。

旧的二参数回调在 TypeScript 结构上仍可能通过编译，但忽略第三参数不会自动共享租约——库无法证明任意自定义回调内部遵守约定，因此这是**运行时约定**，装配自定义 runner 的宿主需要按示例核对。该引用只存在于内存：不进 `AgentTaskRecord`、outbox、模型请求或 wire，任务回滚、清理完成或关闭后释放。

## 4. 本地客户端结果类型与 cursor

`LocalClient.call()` 现在按方法与参数返回具体结果，`session/attach` 返回完整重组后的 `ClientSnapshot`：

```ts
// 读取正文：不要传 cursor
const snapshot = await client.call('session/attach', { sessionId, mode: 'control' });
console.log(snapshot.history.length, snapshot.live.length, snapshot.openSessions);

// 手动分页：显式 cursor 只返回原始续块
const page = await client.call('session/snapshot', { sessionId, cursor });
// page 的形状是 { chunk, cursor }，不含 history / live
```

v0.0.9 的旧客户端在显式 cursor 分支会误走重组逻辑并让连接失效；候选端修正为原始续块返回。这是运行时形状变化，依赖旧行为的调用方需要改成上面两种用法之一。类型层面若原先把 `call()` 结果当作 `Record<string, unknown>` 做索引访问，现在应改用方法结果类型（`RequestResults` / `WireResult` / `ClientResult`）。

attach 或无 cursor 快照的重组失败（缺口、缓冲溢出、回放不连续）现在明确拒绝并关闭**整个连接**：所有 pending 请求被拒绝、审批回调被撤销、该连接上其它已附着会话同时失效。恢复方式是新建连接、重新握手、按需 `attach`；不自动重发 `run/start`，因为客户端超时不能证明服务端没有执行。需要独立控制面的场景请使用独立连接。

## 5. 自定义传输

```ts
import type { LocalTransport, TransportLimits } from '@kiturone/kapibala-cli/client';

const transport: LocalTransport = {
  setLimits(limits: TransportLimits) {
    // 同步收紧已有解码缓冲与发送队列；现存数据超限时关闭并抛错
  },
  messages,
  send,
  close,
};
```

`setLimits` 是必填成员：握手后服务端下发的帧上限与发送队列预算必须能立即生效。实现不具备该能力时连接失败，不静默沿用默认值。

## 6. 清理错误分类

会话/运行清理失败不再统一表现为 `INTERNAL_ERROR`，而是既有业务码 `SESSION_CLEANUP_FAILED`（wire 与 Core 均已类型化）。调用方按可重试关闭处理：保留存储锁，清理完成后才允许其它写者重新打开。`run/cancel` 成功只表示取消请求已传达，终态以 `run_settled` 为准；取消请求失败不等于任务已停止。新增的稳定分类入口是 `createSessionError(code, message)` 与 `SessionErrorCode`，内部诊断 message 保留但对外只承诺 code 与安全文案。

## 7. 数据与配置：本版不需要用户迁移

- **会话历史**：v1 语料在只读复制路径升级为独立 v2 副本，v2 分支语料按活动分支直接读取；尾部损坏与未知 schema 明确拒绝（`Session corrupt` / `Unsupported session schema`），拒绝路径零工具重放。语料固定于 `packages/core/tests/fixtures/compat/`（manifest 记录 sha256 与期望），普通 CI 只比较、不写回 fixture。
- **配置**：v0.0.9 的 `~/.kapibala/settings.json` 语料可直接被本版读取。启动迁移 `migrateGlobalSettingsCatalog()` 会重定向旧模型 id（密钥一并带走）、同步目录字段并把 `builtinCatalogVersion` 对齐，第二次执行返回空变更（幂等）；同厂商族密钥回退与"同组只保留一份密钥"的清理规则不变，`loadGlobalSettingsForWrite()` 不会把未启用的内置模型物化进用户文件。语料文件本身在迁移前后 sha256 不变，fixture 也不含真实凭证。
- **协议**：wire 仍是 1.0，v0.0.9 客户端与 v0.0.10 宿主、v0.0.10 客户端与 v0.0.9 宿主的四组合都由 `pnpm verify:compat` 用真实进程比较，旧端已知缺陷（显式 cursor 分支）按"旧端缺陷"记录，不被当作新端成功。

因此本版**没有**一次性迁移接口需要用户调用；不要为了"看起来兼容"添加 `required=false` 的过渡开关。

## 8. 迁移自查

```sh
pnpm verify                       # typecheck → test → lint（含公共面、协议、边界、密钥门禁）
pnpm verify:compat                # 旧新产物四组合真实进程比较
tsx scripts/check-public-api.ts   # 相对 v0.0.9 tarball 的导出差异
```

编译期最常见的三类失败依次是：`SessionConfig` 缺少根字段、`interface/class` 继承或实现 `SessionConfig`、`SpawnContext`/CLI runner 工厂缺 `leaseCoordinator`。行为层面重点回归共享租约假设与 attach 失败后的重连策略。
