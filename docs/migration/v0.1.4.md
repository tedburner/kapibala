# v0.1.4 迁移说明

> 状态：开发中。本文件随 v0.1.4 主题落地持续补充；发布前以 `pnpm flow release --scaffold`
> 生成发布说明并与 `docs/sdk-compatibility.md` 对齐。

## 1. 本地 wire 升级到整数协议版本 2（破坏性）

v0.1.4 把本地宿主协议从 `{ major: 1, minor: 0 }` 的区间协商改为**整数代际 + 能力集合**：

- `PROTOCOL_VERSION` 现在是整数 `2`，`initialize` 提交 `protocolVersion: 2` 与 `capabilities`；
- 服务端严格相等校验版本，失败返回 `PROTOCOL_MISMATCH`；
- 新增能力走能力字符串（`watch` / `evidence` / `skill-import`），不再升版本号；
- 客户端声明依赖但服务端未提供的能力会握手失败，不做静默降级。

**影响**：v0.1.3 及更早的 CLI、桌面端与第三方本地 wire 消费者无法连接 v0.1.4 宿主。升级时请同时
更新 CLI 与桌面端；官方不承诺字段级兼容或旧客户端降级连接。

**迁移动作**：

1. 从 `@kiturone/kapibala-cli/protocol`（或宿主层同名子路径）导入 `PROTOCOL_VERSION`，不要写死版本号；
2. 把 `{ major, minMinor, maxMinor }` 报价替换为 `{ protocolVersion, clientName, capabilities, token? }`；
3. 读取握手结果时使用 `protocolVersion` 与 `capabilities`，删除对 `major` / `minor` 的引用；
4. 只声明本次真正依赖的能力，并按缺失能力给出可行动提示。

## 2. ViewModel 新增字段

`ViewArtifact`、`ViewTodoState` / `ViewTodoItem` / `ViewTodoStatus` 为纯新增类型；`ViewTool.artifacts`
与会话快照 `todos` 均为可选字段，旧渲染忽略即保持原行为。产物路径的可预览性由宿主按固定允许根
判定，渲染层不得自行放行。

## 3. 会话级监视（watch）

新增内置工具 `watch_start` / `watch_cancel`、CLI 命令 `/watches` 与本地 wire 方法
`watch/list` / `watch/cancel`。行为边界：

- 监视没有执行体，只是一条 `watch_state` 控制记录；命中或超时后，宿主把通知作为 `role: 'user'`
  背景消息落回登记分支，**并在会话空闲时自动续跑一轮**。自动续跑会额外追加一条可见的用户消息
  （正文为「会话监视事件已触发，请根据上一条通知继续。」），历史中会看到它，这不是模型伪造。
- 通知去重依赖消息元数据 `watchSource.eventId`（等于 `watchId`），与子代理通知共用同一投递通道；
  重复投递不会在历史中产生第二条消息。
- 只有持有会话写租约的宿主布置触发源；CLI 与桌面同时打开同一会话时，另一侧只读 `watch_state`。
- `file_change` 以工作区相对路径为界，忽略 `.git` / `node_modules` / `dist`；v1 不识别「本会话自己
  写入的路径」，对工具即将写入的文件登记监视可能自触发，请由使用侧避免。
- `process_exit` 只接受本会话工具启动的子进程；当前宿主尚未维护子进程 PID 注册表，因此该类型会
  以 `WATCH_PROCESS_NOT_OWNED` 拒绝登记，直到归属信息接入。
- 桌面端 v0.1.4 只提供会话徽标与系统级通知，没有监视面板；取消请使用 CLI `/watches cancel <id>`。

## 4. 技能导入与诊断

新增 `/skills inspect [--json]`、`/skill import`（CLI）与 `resources.inspectSkills` /
`resources.importSkills`（桌面 IPC），宿主内部新增导入服务。行为边界：

- 外部 Harness 目录**只在打开导入界面 / 执行命令时扫描一次**，不进入运行期发现链，不参与预算、
  同名优先级或自动同步；这条边界是刻意设计，不是尚未实现。
- 导入是显式 mutation：预览 → 隔离写入 → 原子替换 → 写 `.imported-from.json`；不执行来源代码，
  不建工作树；符号链接越界跳过；冲突默认跳过，覆盖需显式选择且旧副本移到技能根之外。
- frontmatter 在导入时归一：`context` / `agent` / `model` / `effort` / `hooks` / `shell` 与未知字段
  被剥离并写诊断；`allowed-tools` 含参数模式时整条丢弃。来源技能行为可能与原 Harness 不同，这是
  预期的安全收敛，不是兼容缺陷。
- `/skill import` 是 `/skill` 的保留子命令，因此名为 `import` 的技能不能从 CLI 直接激活。
- `getSkills()` 返回值附加 `enabled` / `roots` / `lifecycle` 字段（纯新增）。生命周期事件只记录
  发现事实与原因码，不携带正文；上限 200 条。
- `resources.importSkills` 要求项目作用域仅在已信任项目上可用；未信任直接拒绝，不进入确认流程。

## 5. MCP 配置级命令

新增 `/mcp add|remove|edit`，在既有 `mutateGlobalMcpConfig` 基础上泛化为 `mutateMcpConfig`：

- 全局与项目级共用同一事务实现（独占锁、损坏中止、全量校验、tmp + rename 原子写）；
- `--project` 只在已信任项目上可写，未信任由 `resolveMcpConfigTarget` 直接拒绝
  （`MCP_PROJECT_UNTRUSTED`），不提供交互确认绕过；
- 会话内 `enable` / `disable` 仍保持纯内存语义，与配置级 `--disabled` 不混用；
- 配置写入后需新建会话才进入工具集；当前会话只能对已存在服务执行 `/mcp reconnect`。

### 5.1 逐服务器启动批准

新增 `/mcp approve|revoke <server>` 与持久批准记录 `~/.kapibala/mcp-approvals.json`：

- 批准绑定「作用域 + 服务名 + 完整配置摘要」，命令 / 参数 / 环境键值 / URL / headers 任一字段变化
  即视为新配置，旧批准失效并回到待批准；未批准的 server 不启动、不后台拉起、不进入工具集；
- 记录只保存摘要与时间戳，不保存环境变量值与请求头原文；
- **升级提示**：旧版本没有批准记录，升级后每个 server 首次启动会重新请求一次批准；
  交互环境按提示确认即可，非交互环境需要先 `/mcp approve <server>` 再启动会话。

### 5.2 桌面 MCP 区块补齐

桌面设置页的 MCP 区块由「全局可写、项目只读」扩展为完整管理面：

- `resources.saveMcpServer` / `deleteMcpServer` / `toggleMcpServer` 新增可选 `scope`；
  项目级写入只在已信任项目上可用，未信任由宿主返回 `MCP_PROJECT_UNTRUSTED`；
  写入仍复用 `mutateMcpConfig`，与 CLI `/mcp add|remove|edit` 同一事务、同一把锁。
- 新增 `resources.approveMcpServer` / `revokeMcpServer`：逐服务器批准与撤销，绑定当前配置摘要；
  返回的服务器条目带 `approval`（是否已批准 + 最近批准时间），不含任何配置值。
- 新增 `resources.inspectMcpImport` / `importMcp`：一次性扫描并导入 Claude Desktop / Claude Code /
  Cursor 的 MCP 声明。预览结果是**脱敏投影**，不包含 `config` 正文（env / headers 值留在宿主）；
  同名默认跳过，`overwrite` 才替换。
- `resources.readMcp` 的诊断条目新增 `severity` 字段，与宿主 `McpConfigDiagnostic` 对齐。
- 连接状态取当前会话的 `Inspection.mcp`，与 `/mcp` 同源；未打开会话时仅展示配置事实。

### 5.3 桌面更新检查与下载（U0.1 / U0.2）

新增桌面 IPC `app.checkUpdate`（主进程处理，不进入宿主子进程）：

- 只读查询 GitHub Releases `latest`，返回 `update-available / up-to-date / no-asset / unknown`；
  `unknown` 覆盖离线、HTTP 非 2xx、非法版本与未知平台，页面静默降级；
- 结果只含版本号、发布页、安装包与 `SHA256SUMS` 资产地址，不含下载内容；
- 检查只由用户点击「检查更新」触发，启动时不自动联网。

新增 `app.downloadUpdate` / `app.cancelUpdateDownload` 与进度通知 `update.downloadProgress`：

- 下载入口无参数，URL 只取主进程保存的上一次检查结果，页面无法注入下载地址；
  两者都必须指向 `https://github.com/`，否则返回 `UNTRUSTED_SOURCE`；
- 先取 `SHA256SUMS` 并确认存在目标条目，再流式下载到系统下载目录；摘要缺失、
  条目缺失或哈希不一致都拒绝落地，不一致时删除临时文件（不提供跳过校验）；
- 成功后 `shell.openPath` 唤起安装包，由用户手动完成安装；未签名，不静默安装；
- 下载可取消、失败可重试，同一时刻只允许一个下载；进度经主进程节流后以
  `update.downloadProgress`（`downloaded` / `total`，`total` 未知为 0）推送。
