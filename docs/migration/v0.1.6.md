# v0.1.6 迁移说明

> 状态：随 v0.1.6 分支开发维护。发布说明见 [v0.1.6 发布说明](../releases/v0.1.6.md)，总体架构见 [设计 018](../design/018-v0.1.6-version-design.md) 与 [设计 017](../design/017-ui-v2-workbench.md)，与 [SDK 兼容性盘点](../sdk-compatibility.md) 同口径。

## 1. 本地 Wire 保持协议版本 2（增量能力扩展与双序列兼容）

v0.1.6 继续保持整数 `PROTOCOL_VERSION = 2` 不变，无破坏性协议变更：

- `SERVER_CAPABILITIES` 新增四项能力标识：
  - `'references'`：启用 `reference/candidates`、`reference/search`、`reference/read` 与 `run/start` 的 `references` 参数；
  - `'retry'`：启用 `session/event` 流中的 `stream_reset` 与 `retry_scheduled` 事件；
  - `'checkpoint'`：启用 `checkpoint/list`、`checkpoint/diff`、`checkpoint/restore`；
  - `'worktree'`：启用 `worktree/list`、`worktree/create`、`worktree/status`、`worktree/diff`、`worktree/previewMerge`、`worktree/applyMerge`、`worktree/remove` 以及 `session/create` / `external/open` 的 `worktree` 选项。
- **旧客户端零缺口与字段门控兼容**：本地宿主对 `session/event` 采用按连接能力分流的双序列发生器（`SessionEventFeed`）。未声明 `'retry'` 的 v0.1.4 / v0.1.5 客户端不会收到 `stream_reset` 或 `retry_scheduled` 帧，其控制连接触发的模型运行自动关闭半截流式重试（`allowMidStreamRetry: false`）以杜绝无重置帧时的残文拼接，且事件 `seq` 保持严格单调连续；同时 `session/create`、`session/open` 与 `external/*` 的 `worktree` 字段按 `'worktree'` 能力门控，`external/*` 的 `diffSummary` 按 `'checkpoint'` 能力门控，`session/list` 的 `delegation` 与 `approval/request` 的 `subagentOrigin` 仅向声明任一 v0.1.6 新能力的连接下发。
- `ApprovalPrompt` 新增可选字段 `subagentOrigin?: WireSubagentOrigin`（包含子代理最内层身份与父子会话 ID）；当父会话轮次已结束而后台 `detached` 子代理触发人工审批时，服务端将 `runId` 回退为 `subagentOrigin.agentId ?? 'background'` 发起 `approval/request`。

## 2. Core 与 Host 公共面兼容性

- `@kiturone/kapibala`（Core）保持 **0 运行时依赖**与严格 **Headless**，相对 v0.1.5 **零移除符号**，全部新增参数与字段均为可选向后兼容：
  - **沙箱写禁区收紧（安全加固）**：`PathSandbox` 的 `isProtectedWorkspacePath` 现将工作区根及任意子目录下的 `.git` **精确路径本身**（无论目录还是链接工作树的 `.git` 文本指针文件）纳入写硬禁区，阻断通过改写 `<worktree>/.git` `gitdir:` 指向逃逸仓库边界。只读操作不受影响。
  - **模型自动重试与流空闲守卫**：`AgentLoop` 默认对瞬时可重试故障（`408` / `429`（非配额耗尽）/ `5xx` / 网络闪断 / SSE `90s` 分块超时与非正常 EOF）执行最多 **2 次**指数退避重试；若 SDK 调用方需关闭自动重试，可在 `SessionOptions` 或 `AgentLoopOptions` 中显式传入 `retry: { maxRetries: 0 }`。
  - **子代理规则继承修复**：`ManagedHostSession` 派生的子代理会话现完整继承父会话 `PermissionPolicy` 计算出的 `deny` / `ask` 规则列表，并在等待人工审批期间自动暂停子代理运行超时计时器。
- 自定义实现 `ManagedHostSession` 接口的宿主适配器需同步补齐新增只读/操作成员：`checkpoints()`、`checkpointDiff()`、`restoreCheckpoint()`、`worktree()` 与 `createBranchWithSummary()`（详见 [SDK 兼容性盘点](../sdk-compatibility.md)）。

## 3. 受管 Git Worktree 与 Shadow Git 检查点存储隔离

v0.1.6 新增两处全局受管本地目录（目录权限 `0700`，**零污染用户项目仓库 `.git` 与工作树**）：

1. **受管工作树目录 `~/.kapibala/worktrees/<4-hex>/<repoName>`**：
   - 采用 4 位十六进制短路径桶规避 Windows `MAX_PATH` 限制；会话历史与项目信任仍归属主仓库 `projectRoot`，通过 4 步 `.git` 双向 `fs.realpathSync.native` 回链验真继承信任；
   - 本地合并采用两阶段冲突隔离（先在工作树内 `git merge --no-edit` 目标分支，冲突仅留在工作树内供 Agent 修复；无冲突后再对主工作区执行 `git merge --ff-only`）；
   - Windows 下清理工作树前会先识别并递归剥离 NTFS Junction 目录联接（如 `pnpm` `node_modules`），防止误伤主仓共享依赖。
2. **侧挂检查点目录 `~/.kapibala/checkpoints/<projectKey>/<executionRootHash>/`**：
   - 宿主为 Git 仓库时通过 `objects/info/alternates` 共享对象库并预热索引，宿主为非 Git 普通文件夹（含默认空间）时自动初始化独立侧挂裸仓；
   - 回滚（`checkpoint.restore`、`regenerate({ restoreFiles: true })`、`/checkpoints restore`、`/branch --restore-files`）**仅按轮次归因路径集定向恢复或删除 Agent 触碰过的文件**，绝不执行全目录 `git reset --hard` 或 `git clean -fd`，用户预存未跟踪文件不受影响；检测到用户事后手动修改归因文件时默认返回 `conflict` 拦截，仅在显式 `force: true` 时覆盖并自动保留 `pre-restore` 备份引用。

## 4. 桌面端依赖与原生终端打包变更

- `packages/desktop` 已彻底移除 `@cloudflare/kumo` 依赖，全量切换至 `src/renderer/ui/` 原生语义原语与四域 Zustand Store；
- 桌面 `agent-host` 引入惰性按需加载的 `node-pty`（随 `electron-builder` `asarUnpack` 解包），缺省或平台预编译二进制不可用时仅将工作台「终端」标签降级为不可用提示，不影响对话、文件与 Diff 功能；
- 右侧工作台「预览」标签的本地服务预览仅允许本机回环地址（`http://localhost`、`http://127.0.0.1`、`http://[::1]`），拒绝私网 RFC1918、云元数据地址与公网内嵌。
