# v0.0.2 迁移说明

## SDK 工具授权

`AgentSession` 默认模式是 `Approval`。所有注册工具在执行前都经过 `ToolExecutor` 的权限与审计门；没有 `metadata.permissions` 声明的旧 SDK 工具会请求人工批准。宿主没有提供 `ApprovalChannel` 时，需要审批的调用会被拒绝，并以安全的 `tool_result` 闭合历史。SDK 宿主应为自定义工具声明实际能力，并在需要人工交互时注入 `approvalChannel`。`Plan` 会拒绝未声明能力及写入、执行、网络能力的工具；`FullAccess` 须由宿主为当前会话显式传入，仍受显式 `deny/ask` 和工具自身的限制。

```ts
const session = new AgentSession({
  defaultProfile,
  defaultProvider,
  rootDir: process.cwd(),
  mode: 'Approval',
  approvalChannel,
});
```

新增的工具错误含稳定 `errorCode` 和 `retryPolicy`。旧 JSONL 历史无需迁移；读取方应允许这些字段缺失。`after_user_action` 表示需要用户处理后再运行，结果未知时不要自动重试有副作用的调用。

## 日志与会话历史

普通模式默认写入脱敏运行日志和逐工具审批审计。CLI 文件分别位于 `~/.kapibala/logs/` 和 `~/.kapibala/audit/`；SDK 可注入 `eventLogger` 或用 `loggingDirectory` 指定本地目录。日志通过 `sessionId`、`runId`、`operationId` 和 `toolUseId` 关联。审计记录请求、决定、启动和结果，以及 `human`、规则、模式或缓存等来源。`--debug` 增加脱敏开发诊断并向 stderr 展示，不影响默认日志。日志不保存完整提示词、命令和输出；完整命令可能在已有会话历史中，本地日志不具备防篡改能力。

默认 `StructuredLogger` 的普通运行日志写入失败不会中断问答，但该事件未持久化。CLI 在 stderr 显示安全诊断，无需 `--debug`；SDK 可通过 `SessionConfig.onDiagnostic` 接收诊断，未提供时回退到 `logger`。自行构造 `StructuredLogger` 并注入 `eventLogger` 时，应在该 Logger 上配置 `onDiagnostic`；其它自定义 `EventLogger` 应自行实现相同失败策略。诊断不包含原始异常，诊断回调失败也不影响会话。审计写入失败仍阻止尚未执行的工具；执行后审计失败报告结果未知，不自动重试。

会话历史仍按消息写入工作区 `.kapibala/history.jsonl`。这不等于多会话检索、恢复和归档；后者列入 v0.0.7。

宿主在工具进度事件期间通过 `for await` 的 `break` 或迭代器 `return()` 提前结束 `session.run()` 时，Core 会取消在途工具并等待其清理，闭合全部工具结果并逐消息落盘后才释放会话锁；已完成的工具保留真实结果。自定义工具应响应 `AbortSignal` 并等待自身资源回收。直接持有迭代器的宿主必须等待 `return()` 完成；只丢弃迭代器引用不会触发清理。

## CLI 命令工具与配置

CLI 默认注册 `run_command`，无需启用 Bash 开关。`--disable-shell` 或用户级 `shell.enabled=false` 可关闭注册；切换权限模式不会重新启用已关闭的工具。解释器发现只依赖 `PATH` 与用户显式给出的路径，不写死安装目录；bash 家族经运行时探针分类，Windows `--shell auto` 按 native Bash → WSL → `pwsh` → Windows PowerShell 依次兜底。macOS/Linux 自动选择 Bash。`auto` 找不到任何环境时仅禁用 `run_command` 并诊断；显式 `--shell bash|wsl|pwsh|powershell` 或解释器全路径不可用时会报错。命令进程使用当前系统用户的权限，不受文件工具 PathSandbox 约束；命令执行仍逐次通过授权与审计。

Windows native Bash 的中止和超时同时处理 MSYS 进程组与 Windows launcher，并等待进程退出及 MSYS 组消失；无法确认时仍报告结果未知。解释器启动握手不进入模型输出或日志，不改变用户命令。

`--permission approval|plan|auto|full-access` 只覆盖本次会话。用户配置可默认选择前三种；配置中的 `FullAccess` 会诊断并回退 `Approval`。REPL 的 `/mode full-access` 需要明确确认。当前 CLI 拒绝项目配置中的权限和 Shell 执行字段，即使项目已被信任。可执行规则只从用户级配置加载，命令规则需指定完整命令、解释器和工作目录，不支持前缀或通配符。

Shell 会话审批缓存对无参数的 `pwd` / `Get-Location`，以及工作目录内无参数的直接 `.sh` / `.ps1` 调用开放。直接脚本的真实路径和自身内容进入执行指纹，审批后编辑会重新裁决。组合命令和无法绑定的外部调用只提供“仅本次允许”；脚本自身引用的间接依赖不在内容摘要内。

审批提示将命令、工作目录、解释器和工具参数中的终端控制字符与双向文本控制符显示为可见转义文本，避免终端重绘隐藏命令；执行仍使用原始参数。

命令模型内联输出最多 64 KiB；较大输出写入工作区 `.kapibala/tool-results/` 的受管文件，单文件最多 16 MiB，可用 `read_file` 按行读取。stdout/stderr 分别流式解码后统一为 UTF-8 文本，上限按归一后的 UTF-8 字节计算，并在完整字符边界截断。WSL launcher 固定设置 `WSL_UTF8=1`，该环境策略参与审批指纹；非法 UTF-8 输入使用替换字符，不承诺保留二进制输出。该目录随工作区访问权限可见。

从 v0.0.2 回退到 v0.0.1 时，旧版会忽略新增的可选历史字段和配置字段，但旧版没有 v0.0.2 的执行前授权门。发布前须通过 Windows 与 POSIX CI 的命令生命周期验收，记录见 [验收任务](../../openspec/changes/v0-0-2-trusted-execution/tasks.md)。
