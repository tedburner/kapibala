## 真实多层进程回收验证

针对子代理可能启动任意深度进程树的场景，`packages/core/tests/process-group-kill.test.ts` 派生真实的 Node.js 多层嵌套进程（Parent → Worker → Sub-worker，子进程均处于活跃监听状态）：

- **Windows 平台**（本机实测）：`taskkill /PID <pid> /T /F` 递归杀死整棵进程树，无论子进程是否捕获 `SIGINT` / `SIGTERM`；
- **POSIX 平台**：同一用例走 `process.kill(-pid, 'SIGKILL')` 进程组分支，由 CI 的 Linux runner 执行；
- **残留核验**：回收后核验系统进程状态，确认无孤儿进程遗留。

## 远端 CI 首轮红灯与路径身份整改

`main` 首次推送（run 38894245146）在 ubuntu 与 windows 两个 runner 同时失败，标签推送前置阻断。逐项定位后确认全部为**平台路径身份与时间预算**缺陷，本机（长路径临时目录 + 单盘）不可复现，因此在 CI 复现条件（以 junction 使 `os.tmpdir()` 的字面值与其 `fs.realpathSync.native` 结果不一致）下回归验证：

| 失败点 | 根因 | 整改 | 证据 |
| --- | --- | --- | --- |
| `tools-fs.test.ts` grep 输出 `../../../../../runneradmin/…` | `list_dir` / `grep` 以宿主原始 `ctx.rootDir` 做 `path.relative`，而命中路径来自沙箱的 native 长路径根；短名或软链接别名根下两者身份不一致，渲染出无法回读的逃逸串 | 两处相对化基准统一改为 `sandbox.workspaceRoot`（`capabilities/tools/builtin/fs.ts`） | `tools-fs.test.ts`（36 项，junction 沙箱下全绿） |
| `sandbox.test.ts` 3 项、`session-context.test.ts` 1 项、`shell.test.ts` 1 项 | 断言用未折叠的 `os.tmpdir()` 拼期望值；`PathSandbox`/会话执行目录按契约走 `fs.realpathSync.native`，短名 runner 上「同一目录两种写法」被判为不等，精确 cwd 匹配的 allow 规则也永不命中 | 测试根目录创建后立即折叠为 native 长路径（`canonicalTempDir`），期望值与生产契约同源 | 上述三文件在 junction 沙箱下全绿 |
| `session-search-archive.test.ts` `timeoutMs: 0` 期望 `isPartial` 为真 | deadline 判定用严格大于，预算为 0 时 `Date.now()` 可能与 deadline 同毫秒，导致「零文件也宣称完整」的部分结果不可复现 | `catalog.ts` 两处 deadline 判定改为 `>=`，耗尽预算必然标记 `search_timeout` | `session-search-archive.test.ts`（5 项全绿） |
| `agent-budget-approval.test.ts` 2 项 | 用例写死 `F:/Project` 盘符路径，POSIX runner 上不是绝对路径，先在 `toNativePhysicalPath` 抛 `CONFIG_INVALID`，容量与深度熔断本身从未被执行 | 工作区身份改为本平台 `fs.mkdtempSync` 真实绝对路径 | Linux runner 通过（run 待补记） |
| `session-manager.test.ts` 分页用例超时 | Windows runner 上顺序创建 25 个会话超出 Vitest 默认 5s，属用例预算过紧而非实现退化 | 该用例显式放宽至 30s | `session-manager.test.ts`（11 项全绿） |

整改后本地门禁复跑：typecheck → test（112 文件 / 1033 通过 / 3 跳过）→ lint（含架构与密钥扫描）全绿。
