# v0.1.0 D1 本机测试打包验收

日期：2026-10-25。版本仍为 0.0.10，源码基线 `9a8763e27d2d0f021d4303dfe614ef3029cbbbbc`，工作区包含未提交改动（dirty）。本文记录本机开发验证，不是最终候选或正式发布证据。设计与剩余门禁见 [004](../design/004-v0.1.0-desktop-harness.md)，执行入口见[开发指南](../desktop-development.md#11-本机测试打包d1)。

## 变更与边界

- 新增 `pack:desktop`：验证 → 独立生产部署 → 闭包检查 → 原生测试包 → 安装副本 smoke → 逐文件哈希、许可全文与构建清单。
- 产品名、文件名和 About 标注测试身份；打包应用仍显示测试构建，不因 `app.isPackaged` 变成正式版本。缺少严格构建元数据的包拒绝启动。
- `--candidate` 缺凭证先阻断，即使配置凭证也不跳过尚未完成的 D2/D3。测试命令不继承签名/发布凭证、不上传或创建标签。
- 项目入口改为“创建项目”表单与二次信任确认，设备仅此电脑；名称为显示别名，取消信任保留表单，原生选择目录不提交最近项目，不创建会话或调用模型。

## 安装副本证据

当前使用显式 `--native-dmg`：builder 先生成应用并作 ad hoc 签名，系统 `hdiutil` 生成测试 DMG。默认 builder DMG helper 下载曾因 GitHub 连接超时失败，不能记为默认后端通过；未使用未完成或未校验的下载文件，也未关闭下载校验。

本次 `pnpm pack:desktop --native-dmg` 完整通过（包含桌面验证），安装副本 E2E 1/1 通过。smoke 只读挂载 DMG，将应用复制到隔离安装目录，保留 framework 相对链接，校验副本不指向源应用；从副本二进制启动，确认 `isPackaged=true` 和资源路径属于副本。home/userData 为临时目录，GUI PATH 仅 `/usr/bin:/bin`（本机无 Node），本地确定性 Provider 返回真实 `write_file` 调用，经审批落盘。正常退出后 guard 消失，移除应用副本后配置、历史和工具文件仍在。

该路径验证安装副本依赖闭包，不证明 Developer ID、公证、Gatekeeper、系统安装器升级或系统卸载。

独立终审发现上游预打包来源许可遗漏，已通过先失败后通过的来源版本回归修复；重新完成全仓门禁与最终 DMG 打包。终审未发现 Critical，所列 Important 已修复，其余 Minor 如下保留。

## 决策与 pending

- legacy deploy 留下指向源桌面目录的辅助自链接、内部 workspace 协议：只清理确切自链接、同版本内部范围，其它外链仍失败；原子改写避免污染硬链接源。若 pnpm 部署结构变化，预期阻断并需要重新适配，而不是放宽闭包检查。
- 采用显式系统 DMG 后端继续本机测试，不自动替换默认 builder 后端；若两种容器行为不同，需在正式候选前分别验收。
- Renderer 依赖由构建内联，保留为 devDependencies；构建额外生成实际模块许可原文，避免仅扫描生产树而漏项。人工许可审核仍 pending。
- D1 未整体勾选：Windows x64 NSIS/ZIP、Linux x64 AppImage、macOS x64，实际升级/系统卸载和跨平台 GUI 均 pending。
- D2 签名/公证、D3 不可变候选与审核附件流程、D4 最终证据和发布均 pending。
- 本批终审 Minor（延后）：Main 的 Host 回复及别名恢复在 await 后未再次核验控制身份；断连后的迟到回复仍可能更新最近项目、guard 与旧 workspace 登记。未发现工具重放。后续需加入连接代次复核与迟到回复回归。
