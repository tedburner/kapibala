## P0 — 阻断合入

### P0-1 权限分类层：9 条可复现绕过（`packages/core/src/capabilities/shell/command-class.ts`、`script-trust.ts`）

以下均对 `a04ec1e` 实测（tsx 直跑 `classifyShellCommandClass` / `assessScriptTrust`），`read` 在 Approval 与 Auto 放行，`workspace-write` 在 Auto 放行：

1. **直引路径按 basename 判类**（`command-class.ts:872-877` `baseName` + `:590` 查表）：`./bin/rg pattern` → `read`；`./node_modules/.bin/tsc --noEmit` → `workspace-write`。两步攻击链（Auto 下免审写假可执行文件 → 直引执行）全在免审面内，且绕过 script-trust（无扩展名不提取目标）。修复：`words[0]` 含路径分隔符时不得按 basename 查表，归 `unknown` 或走 script-trust 门控。
2. **`cd` 后路径漂移**（`command-class.ts:342-381`、`:549-577`）：`cd .git/hooks && echo x > pre-commit` → `workspace-write` 且 protected=[]，硬禁区（git hook、`.kapibala/permissions.json`）被相对写法绕过。修复：分段追踪 `cd` 落点解析重定向候选，或 `cd` 目标命中硬禁区段即整条 deny。
3. **scriptTrust 对 gitignored 返回 clean**（`script-trust.ts:182-198`，`git status --porcelain` 不列 ignored）：模型写 `node_modules/evil.js` 后执行 → clean；改写 `.gitignore` 为 `*` 可使 script-trust 整体失效。修复：`git ls-files --error-unmatch` / `check-ignore`，tracked 且无改动才 clean。
4. **前导环境赋值不查值**（`command-class.ts:587` 纯跳过）：scriptTrust=clean 时 `NODE_OPTIONS=--require=./evil.js pnpm test`、`PATH=./bin pnpm test` 放行。修复：赋值值含路径/反引号（尤其 PATH/NODE_OPTIONS/LD_PRELOAD/BASH_ENV 类高危键）归 `unknown`。
5. **`pnpm/npm/yarn exec` 无条件 `workspace-write`**（`command-class.ts:736`）：`pnpm exec bash -c "curl …|sh"` 是免审任意命令执行器（`dlx` 归 `network`，`exec` 却不看）。修复：`exec` 与 `npx`/`dlx` 同判。
6. **解释器 `--flag=脚本` 形态不进信任校验**（`script-trust.ts:115` 只提取首个非 `-` 参数）：`node --require=./hook.mjs app.js` → clean（`node -r ./hook.mjs app.js` 反而正确）。修复：高危选项族取值纳入 targets，或含该形态归 `unknown`。
7. **WORKSPACE_PROGRAMS 不看 scriptTrust**（`command-class.ts:609`）：模型自写未跟踪 `Makefile` / `eslint.config.js` / `vitest.config.ts` 后 `make` / `eslint` / `vitest` → `workspace-write`。修复：`make` 与 JS 配置解释器把主配置纳入 `assessScriptTrust`。
8. **决议 3 escape 清单零实现**：`.github/workflows/**`、`.npmrc`、`.netrc`、`.git-credentials` 在 core src 零命中（grep 确认）；Auto 下可免审写 CI workflow（下次 push 以仓库密钥执行任意代码）与 registry 劫持。修复：共用候选判定加 escape 清单（工作区内、非硬拒、命中归 `escape`）。
9. **git 读子命令 `--output=`/`-o` 不查落点**（`command-class.ts:800-804`）：`git log --output=~/.ssh/authorized_keys --pretty=format:…` → `workspace-write`，Auto 免审向工作区外写模型可控内容。修复：与重定向目标同权检查 `isWithinRoot`。

P1 伴随项：Windows 尾随空格/点绕过 `.env` 硬禁区**新建**场景（`sandbox.ts:71-73` 未剥尾随空白）；FullAccess 下「硬禁区三档一致」宣称应收敛为「可解析写法三档一致」（§11.5 已声明，文档口径待收敛）。

### P0-2 监视：重启/会话重建后 armed 条目对未变化文件假触发

`packages/host/src/host/watch/service.ts:216-219`——`start()` 恢复 armed 条目只写 `{ state }`，不重建签名（对照 `register()` 的 `initialFileSignature` 路径，`service.ts:333-339`）；`inspectFile` 判定放行点因 `entry.signature`/`entry.hash` 为 undefined 恒不成立 → 文件零改动也 `fired`（评审时已用构建产物运行时复现，输出虚假「文件内容已变化」并触发续跑）。触发面：进程重启、CLI 分支切换重建会话、桌面接管写租约。修复：恢复路径按 `register()` 同法重建签名/哈希，并补「恢复后不触发」回归。

### P0-3 桌面：`app.downloadUpdate` 受统一 30s RPC 超时约束

`packages/desktop/src/shared/rpc.ts:77-80` 对所有方法统一 `LIMITS.requestTimeout`（30s），`app.downloadUpdate` 不在豁免名单（`contracts.ts:657`），主进程 handler await 整个下载才回包（`main/index.ts:256-275`）。下载超 30s（安装包百 MB 量级、带宽 < ~4MB/s 即触发）确定性出现：渲染层收 `REQUEST_TIMEOUT` 显示失败、取消按钮消失（只在 `downloading` 为 true 时渲染），后台下载继续并在完成时 `shell.openPath` 自动弹安装器——与「失败」直接矛盾，违背 011 U0.2「可取消/可重试」。修复：per-method 长超时或主进程立即回执「已开始」+ 终态走事件。
