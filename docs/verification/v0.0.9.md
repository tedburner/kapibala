## 尚不能替代的门禁

- Windows ACL、进程树取消/回收与 Linux 真实发行版环境验收尚未执行；CI 全量测试已覆盖 Windows named pipe 基本传输，但不能替代 ACL/进程树验收。
- Node 20 的运行与独立安装 smoke 尚未执行；当前证据为 Node v26.12.0。
- 真实终端键盘/审批交互、MCP 启动完整生命周期和长时间资源压测尚未做平台验收。
- 审批实现支持受控目标白名单；敏感命令或无法充分安全描述的工具拒绝，不承诺所有自定义工具均可人工放行。
- 快照与活动尾部存在明确内存预算，不承诺无限历史在单连接内整体重建。

## 实施裁决与进度

- 不新增 npm 包，模块边界用子路径构建与传递依赖门禁保持。
- 既有 node_modules 含 Windows 二进制且依赖不完整，使用 `pnpm install --frozen-lockfile --force` 重建；锁文件未改。
- 执行中将大快照细化为同修订字符串分块，单连接快照预算 8MiB；过大显式失败，避免静默丢历史。
- MCP 首次挂载延后到受控运行，使启动审批能关联已生效控制代际。
- Core 迭代结束后仍报告 busy 时发送失败诊断与 settled，设置 needsCleanup 围栏拒绝新运行，允许关闭重试；运行时与会话均清理成功后才释放存储锁。
- 无法确认旧 daemon 时保留陈旧元数据报错，未实现自动回收未知实例。
- 2026-10-20 代码审查 R01–R21 已逐项修复，证据与修复前问题见 [审查记录](v0.0.9-code-review-2026-10-20.md)：错误契约、控制面生命周期、资源回收、审批描述与能力协商、快照/重放语义、事件投影与 daemon 可观测性；复跑全部门禁与真实 daemon 平台检查通过。
- 提交内容经用户确认后，按仓库流程创建实现提交、合并与发布标签；推送仍手动执行。

实现任务和剩余验收以 [OpenSpec tasks](../../openspec/changes/v0-0-9-local-client-contract/tasks.md) 为准，文档与模拟测试不代替真实平台证据。
