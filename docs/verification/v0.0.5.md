## 远端发布验收（2026-10-11）

v0.0.5 已于 2026-10-11 发布到 npm 与 GitHub Release：`@kiturone/kapibala@0.0.5` 与 `@kiturone/kapibala-cli@0.0.5` 的 `latest` 均为 0.0.5，Release 附双包 tarball 与 `SHA256SUMS.txt`。发布源提交为标签 `v0.0.5`（3174cef），成功的 Actions 运行为 [Release #38144176061](https://github.com/tedburner/kapibala/actions/runs/38144176061)（publish 经一次失败后按预案重跑完成，prepare 与双平台 verify 复用首轮绿色结果）。

发布过程共三次失败，均如实记录：前两次为 main 的 Verify 失败，暴露并修复两个仓库问题——其一，本仓库第二次踩中 Windows 8.3 短名坑：信任写入走 `realpathSync.native` 长路径身份，而 `detectProjectRoot`/`resolveProjectTrust`/`getCliSkillOptions` 用 JS `realpathSync` 保留 CI 临时目录的 `RUNNER~1` 短名，已信任项目会在技能信任判定中失配；这不只是测试断言问题，长用户名（超 8 字符）的 Windows 真实用户同样受影响，修复统一四处为 native 规范化并同步测试夹具（`c6e4356`）。其二，shell 的 17 MB 级 PowerShell 管道多字节文件上限测试在 CI VM 上连续两轮越过 40 秒（本地约 2.7 秒，实时扫描拖累，且曾连带并行文件超时；重跑后其余消失，判定波动），断言与速度无关，超时放宽至 120 秒（`937ae12`）。本地标签 `v0.0.5` 因此在零产物状态下重打两次，属安全回收；推送顺序始终遵循「main 的 Verify 通过后再推标签」。

第三次失败发生在 publish 阶段的 registry 冒烟安装：两个包实际均已通过 Trusted Publisher 成功上传，但 npm CDN 传播延迟超出 10 次 × 30 秒重试窗（`ETARGET`）；按预案重跑 publish 任务，按 SHA512 与 `latest` 校验跳过两个已发布同版本包，冒烟安装、GitHub Release 创建与资产上传全部完成。本地不重复隔离安装冒烟，以 CI 的 registry 安装为准。真实 Anthropic/OpenAI 付费 API 冒烟的限制继续成立，[迁移说明](../migration/v0.0.5.md)、[发布说明](../releases/v0.0.5.md) 与 [OpenSpec 任务](../../openspec/changes/v0-0-5-skills-system/tasks.md) 已同步本次交付边界。
